# 项目初始目标与阶段路线

> 当前项目位置为 `D:\Games\worldtrace_workspace\worldtrace`。本文保存阶段目标，若目录描述与[目录与模块边界规则](目录与模块边界规则.md)冲突，以后者为准。

可以实现，但要从“可验证的最小闭环”开始，而不是直接实现通用3D自主游戏智能体。

## 项目名称

推荐名称：

> **界迹（WorldTrace）**

完整名称：

> **界迹：面向游戏的视觉关系网学习、规划与执行系统**

含义：

- “界”同时表示游戏世界、界面和窗口环境；
- “迹”表示用户键鼠轨迹、连续画面变化、路线和执行证据；
- 系统将这些轨迹收束成状态、能力和关系网。

建议代码仓库名：

```text
worldtrace
```

建议作为独立项目建立，例如：

```text
D:\Games\nikkigallery\WorldTrace
```

Whimbox作为游戏能力和调度参考，UIAgent作为视觉实验环境，ALAS作为确定性闭环参考，不把新系统继续堆进Whimbox核心。

## 可实现范围

目前可以较确定实现：

- 连续截图和键鼠同步记录；
- 输入前后帧对齐；
- 稳定UI状态发现；
- 基础步骤收束；
- 短距离移动和视角闭环；
- 单一目标发现、接近和互动；
- 场景关键节点记忆；
- 稀疏空间拓扑；
- 用户确认后的关系图计划执行；
- 故障证据和恢复记录。

需要实验验证：

- 通用地面、墙体和台阶识别；
- 场景指纹跨视角定位；
- 无小地图副本自主探索；
- 多楼层自动定位；
- 悬崖和危险边界识别。

后期再考虑：

- 任意游戏通用寻路；
- 飞行、水下和完整三维空间；
- 高速战斗控制；
- 未知复杂解密；
- 无用户确认的自动能力学习。

## 第一阶段：Trace Core

第一步不接OCR、YOLO、SAM和LLM，先建立系统事实主干：

```text
CaptureService
-> 连续FrameStream

InputRecorder
-> 用户键鼠事件流

WindowRegistry
-> 目标窗口身份和代次

Timeline
-> 帧、输入、焦点使用同一单调时钟

FrameRingBuffer
-> 保留最近数秒画面

EvidenceStore
-> 保存输入前后关键窗口

ReplayTool
-> 离线重放同一段记录
```

第一阶段完成标准：

- 每帧都有唯一`frame_id`；
- 每个输入都有唯一`action_id`；
- 能找到输入前帧和输入后帧；
- 能区分新鲜帧、旧帧和截图失败；
- 能记录用户输入作用于哪个窗口；
- 能保存最近数秒错误现场；
- 同一段记录可以重复离线回放。

## 第二阶段：基础控制闭环

只选择一个游戏、一个窗口模式、一个安全场景和第三人称普通状态。

实现两个能力：

```text
ViewDirectionController
-> 小角度转动镜头并验证实际变化

ShortMoveController
-> 短时间前进并验证角色或画面真实位移
```

同时加入：

- `desktop_physical_input`独占；
- `focus_epoch`；
- 停止和按键释放；
- 无推进检测；
- 左右振荡检测；
- `StepAttempt`与公共`ExecutionOutcome`。

这一阶段只需要证明：

```text
能够转向一个方向
能够前进一小段
能够确认是否真的移动
遇到UNKNOWN能够立即停止
停止后没有残留按键
```

## 第三阶段：单目标互动

实现一个固定、低风险目标：

```text
发现目标
-> 镜头对准
-> 短距离接近
-> 识别互动提示
-> 执行互动
-> 验证目标消失或结果出现
```

这会首次串联视觉、视角、移动、输入、后置验证和证据记录。

## 第四阶段：最小关系图

只建立：

```text
2至3个稳定状态
2个地点节点
1个目标
3至5个已验证能力
1条完整计划
```

例如：

```text
游戏主界面
-> 前往目标区域
-> 对准目标
-> 接近目标
-> 执行互动
-> 验证完成
```

这时再接入LLM进行命名、提问和抽象计划候选生成；候选经过程序校验与必要的用户确认后，才形成`AbstractPlan`。

最务实的开工顺序是：

```text
连续帧与输入时间线
-> 离线回放
-> 小角度视角控制
-> 短距离移动
-> 单目标互动
-> 最小关系图
```

这个顺序能够真正行动起来，而且每一步都可以独立测试，不需要等待完整理论系统完成。
