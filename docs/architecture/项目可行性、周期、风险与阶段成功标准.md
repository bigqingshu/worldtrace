## 1. 估算性质

本文中的成功率和周期是工程判断，不是统计测量结果。

当前项目已经形成较完整的构想、边界和实验方法，但正式代码、数据集和长期实验尚未开始，因此不确定性仍然很大。

估算主要用于：

- 防止把不同层级目标混成一个“成功”；
- 确定阶段预算和停止条件；
- 建立合理心理预期；
- 在真实实验后更新判断；
- 避免因为宏大终局尚未实现而否定中间成果。

## 2. 估算假设

以下判断基于：

```text
主要由一名开发者配合AI工作
Windows平台
先选择一个游戏和一个测试账号
先使用非侵入式截图和输入方法
允许人工标注、用户确认和游戏Profile
基础模块逐项验证
不要求第一版跨游戏零配置
```

如果要求从第一天开始兼容多个游戏、完全自动学习或直接进入复杂3D，成功率会明显降低，周期会显著增加。

## 3. 三种成功定义

### 3.1 有用的研究平台

```text
可以可靠记录和回放
可以人工检查原始与派生数据
可以验证状态、关系和运动假设
可以逐步加入新检测器和规则
```

这是当前最重要且最现实的成功定义。

### 3.2 单游戏综合原型

```text
在一个游戏的限定窗口、版本和场景中
发现并执行若干UI关系
记录部分图标、物品和数值
完成一个有限领域闭环
验证简单3D运动状态
```

### 3.3 跨游戏通用智能体

```text
多个游戏共享大部分识别和执行能力
极少人工配置
能够自主发现复杂关系
能够处理开放3D、异常、物品和规划
```

这是长期研究方向，不适合作为第一阶段成败标准。

## 4. 分项成功率估算

| 成功定义 | 当前工程估算 |
| --- | ---: |
| 流式截图、输入对齐、证据保存和回放 | 85%～95% |
| 单游戏中识别若干稳定菜单状态 | 75%～90% |
| 自动执行5～10条经过验证的UI关系 | 70%～85% |
| 从用户操作中发现简单关系候选 | 55%～75% |
| 图标、物品记录和简单材料规划 | 65%～85% |
| 安全场景中区分静止、走路、跑步和疾跑阶段 | 55%～75% |
| 单游戏中完成有限3D视觉移动 | 40%～65% |
| 多个游戏共享核心并使用各自适配器 | 30%～50% |
| 几乎无需配置地适配任意游戏 | 10%～25% |
| 完全自主学习、规划并操作任意3D游戏 | 5%～15% |

这些范围会在完成第一轮截图、输入、UI和3D实验后重新评估。

## 5. 当前总体判断

如果成功定义为：

> 建立一个能够持续实验、记录用户操作、发现简单关系，并在单个游戏中执行有限闭环的研究平台。

当前估算成功率为：

```text
70%～85%
```

如果成功定义为当前全部广泛构想在一个系统中成熟落地：

```text
20%～35%
```

如果成功定义为不需要游戏适配、几乎完全自主的通用游戏智能体：

```text
5%～15%
```

最终最可能形成的是：

```text
通用事实和规则核心
+ 通用实验与回放工具
+ 每个游戏的Profile与适配器
+ 用户确认和按需AI
```

而不是完全零配置的统一模型。

## 6. 什么会提高成功率

- 第一个版本只支持一个游戏；
- 固定一种窗口模式、分辨率和测试账号；
- 先做无资源消耗的UI闭环；
- 保存原始证据并支持离线回放；
- 被动记录和主动执行分开；
- 允许`UNKNOWN`和`UNOBSERVABLE`；
- 使用用户确认和少量人工标签；
- 每次只验证一个基础模块；
- 规则拥有范围、版本和反例；
- 3D先使用离散运动状态和相对风险；
- 高风险操作始终需要用户批准。

## 7. 什么会降低成功率

- 一开始同时支持多个游戏；
- 要求系统完全不使用人工标签；
- 过早接入全部OCR和视觉模型；
- 把LLM放进实时判断闭环；
- 没有回放就直接在线调试；
- 用单个置信度覆盖所有故障来源；
- 直接追求米制3D重建和通用悬崖判断；
- 在关系验证前开放主动输入；
- 没有账号和窗口归属检查；
- 每个想法都立即变成正式模块；
- 依赖过多不稳定开源项目；
- 不设阶段停止条件。

## 8. 时间估算口径

### 8.1 全职投入

按每周约35～45小时有效投入估算，其中包括开发、实验、记录、重现和文档。

### 8.2 业余投入

按每周约10～20小时且可能被现实事务打断估算。业余项目的日历周期通常不只是全职周期的简单倍数，因为重新进入上下文也会消耗时间。

### 8.3 AI带来的影响

AI可以加快：

- 项目骨架；
- 数据结构；
- 测试工具；
- 重复代码；
- 文档和代码检索；
- 多方案原型。

AI不能消除：

- 游戏实验等待；
- 数据质量问题；
- 真值标注；
- 偶发Bug复现；
- 账号和安全风险；
- 模型效果验证；
- 长时间稳定性测试。

## 9. 分阶段周期

| 阶段 | 全职投入 | 业余投入 |
| --- | ---: | ---: |
| 截图实验台与Trace Core v0 | 1～2个月 | 2～4个月 |
| 基础画面特征、输入对齐和离线回放 | 1～2个月 | 2～4个月 |
| 第一个UI识别与执行闭环 | 2～3个月 | 4～6个月 |
| 初步关系发现和规则引擎 | 3～6个月 | 6～12个月 |
| 图标、物品和简单材料规划演示 | 2～4个月 | 4～8个月 |
| 安全场景中的3D运动实验 | 4～9个月 | 8～18个月 |
| 一个游戏的综合研究原型 | 12～18个月 | 2～3年 |
| 多游戏可复用研究平台 | 2～4年 | 4年以上 |

阶段可以部分并行，表格不能直接逐项相加。

## 10. 累积里程碑预期

### 10.1 约3个月

```text
至少两种截图方法完成对比
连续帧、被动输入和窗口事件可以对齐
可以查看RGBA/BGRA、差异和时间线
可以保存并离线回放
```

### 10.2 约6个月

```text
可以稳定区分两个或更多UI状态
可以形成一条输入到变化的关系候选
可以安全执行一个按键或静态点击
可以完成一个基础菜单往返闭环
```

### 10.3 约12个月

```text
可以识别3～5个稳定UI状态
可以发现并验证5～10条简单转换关系
具备基础规则版本和运行证据
完成图标、OCR、物品或材料规划中的至少一个领域演示
可以在安全平地输出人物离散运动状态
```

### 10.4 约18个月

```text
一个游戏形成较完整实验Profile
UI关系、故障恢复和用户确认能够共同运行
至少一个领域能力达到可重复演示
有限3D移动或跳跃画像得到验证
```

## 11. 时间估算为什么容易失准

- 游戏更新改变实验条件；
- 截图后端在不同机器表现不同；
- 偶发窗口和输入问题难以复现；
- 一个“简单页面”可能包含大量动态效果；
- 真值和负样本需要人工准备；
- 模型依赖和GPU环境可能冲突；
- 文档构想在真实数据下需要重写；
- 项目同时承担研究工具和自动化产品两种需求；
- AI可能快速生成大批代码，随后需要时间验证和拆除。

因此应按阶段交付，而不是承诺一次性总工期。

## 12. 风险一：范围增长

每个新想法都会带来：

```text
新状态
新上下文
异常与恢复
版本和证据
用户确认
新的测试组合
```

范围增长可能比实现速度更快。

应对：

- 同一时间只有一个活动实验目标；
- 新想法先进入构想文档；
- 完成可观测性审计后再进入实验；
- 不改变数据契约和安全边界的想法只作为案例；
- 每个阶段设置明确预算和停止条件。

## 13. 风险二：画面有变化但不能区分答案

画面变化可能来自：

- 角色动画；
- 镜头运动；
- 粒子和光效；
- 服务器同步；
- UI动画；
- 动态分辨率；
- 真实状态变化。

可能得到大量像素数据，却不能判断目标事实。

应对：

- 明确直接和间接证据；
- 加入输入、窗口和时间上下文；
- 使用相似负样本；
- 允许`UNKNOWN`；
- 无法区分时标记`UNOBSERVABLE`并停止调参。

## 14. 风险三：输入和画面时间错位

旧帧、截图缓存、输入队列、窗口切换和动画延迟可能制造错误关系。

应对：

- 使用单调时间线；
- 为每帧和输入建立唯一ID；
- 记录截图健康和新鲜度；
- 保存输入前后时间窗；
- 实验测量响应延迟分布；
- 不使用统一固定等待代替观测。

## 15. 风险四：相关关系被误认为因果

按键后出现的图标、提示或剧情不一定由该按键造成。

应对：

- 被动观察只生成`OBSERVED_ASSOCIATION`；
- 保存同时发生的其他输入和上下文；
- 收集无效输入和相似状态；
- 使用低风险受控实验；
- 关系进入`SHADOW`后才允许主动执行。

## 16. 风险五：上下文爆炸

同一个按键可能随角色、能力、载具、地图、任务和活动改变作用。

应对：

- 规则先限定狭窄`scope`；
- 移动意图、实际响应和环境修正分开；
- 稳定身份和版本分开；
- 发现反例时拆分上下文，不平均成全局规则；
- 接受每个游戏需要Profile和适配器。

## 17. 风险六：游戏更新

更新可能修改：

- UI布局和图标；
- 文本和本地化；
- 物品和公式；
- 截图行为；
- 角色和技能；
- 输入控制；
- 反作弊策略。

应对：

- 所有检测器、规则、公式和素材版本化；
- 记录游戏版本和画质Profile；
- 活动规则不可原地覆盖；
- 更新后执行回归实验；
- 失效规则进入`DEGRADED`或`RETIRED`。

## 18. 风险七：3D视觉难度

3D阶段需要区分：

```text
人物运动
镜头旋转和平移
游戏速度效果
动态场景对象
相对深度变化
地面连续性
实际推进和碰撞
```

单目画面通常不能直接恢复可靠米制尺度。

应对：

- 先使用离散运动模式和相对推进等级；
- 镜头、人物和环境修正分开；
- 从平地和低风险场景开始；
- 深度只输出相对风险和趋势；
- 跳跃使用经验响应画像；
- 悬崖和移动平台最后验证。

## 19. 风险八：模型效果不稳定

OCR、YOLO、CLIP、SAM和深度模型可能受到：

- 游戏美术风格；
- 分辨率和UI缩放；
- 透明特效；
- 角色遮挡；
- 画质设置；
- 模型版本；
- GPU和推理后端。

应对：

- 先建立不依赖模型的事实层；
- 每种模型拥有清晰输入输出；
- 离线评估后再接实时流程；
- 模型失败返回`UNKNOWN`；
- 模型名称不等于已获得业务能力。

## 20. 风险九：AI产生错误架构和结论

AI可以快速生成大量看似完整的代码、关系和解释，但可能：

- 发明不存在的API；
- 混淆模块边界；
- 忽略真实游戏时序；
- 把候选当成事实；
- 使用过时网络资料；
- 产生无法复现的数值。

应对：

- AI只生成候选、解释和代码草案；
- 修改前说明归属、输入、输出和验收；
- 普通算术和规则求值保持确定性；
- 网络知识保留来源和版本；
- 运行规则必须通过Schema、回放和实验；
- 用户确认不覆盖原始证据。

## 21. 风险十：环境和依赖

Python 3.12、GPU驱动、PyTorch、OCR、截图后端和编译依赖可能冲突。

应对：

- 主项目只保存环境规格；
- 实际虚拟环境放在工作区`environments`；
- 不同高风险实验允许独立环境；
- 模型适配器与核心数据契约分开；
- 先验证Python 3.12支持和许可证；
- 避免主项目一次安装全部模型。

## 22. 风险十一：账号、安全与反作弊

主动输入、自动消费、窗口Hook和游戏注入可能带来账号与合规风险。

应对：

- 第一阶段使用非侵入式系统接口；
- 优先测试账号；
- 不做渲染注入和反作弊绕过；
- 正式账号和测试账号数据隔离；
- 高风险行为需要固定计划版本和用户批准；
- 付费、出售稀有物品和不可逆剧情默认禁止。

## 23. 风险十二：数据量和隐私

连续帧、输入和模型中间结果可能快速增长，也可能包含其他窗口和用户输入。

应对：

- 使用环形缓冲和事件触发保存；
- 实验时才允许完整录制；
- 输入记录限定目标窗口和时间；
- 不保存其他应用文本；
- 原始数据和派生数据设置不同保留策略；
- 证据包包含来源、用途和删除策略。

## 24. 风险十三：缺少真值和反例

用户操作记录不自动包含状态真值。只有正样本会使错误特征显得有效。

应对：

- 第一批状态由用户少量确认；
- 保存无效输入、遮挡、加载和相似页面；
- 分离机器命名和语义确认；
- 使用可重复安全场景；
- 建立小而可靠的回归集。

## 25. 风险十四：长期维护和动力

长期项目可能因为看不到最终效果而失去推进动力。

应对：

- 每个阶段都有可视化或可回放产物；
- 每月保留一个可演示结果；
- 不把“通用智能体”作为唯一成功；
- 失败实验也进入报告；
- 允许长期方向被`DEFERRED`；
- 定期冻结构想阶段，进入实现和测量。

## 26. 心理预期一：前期不像游戏AI

前几个月主要产物可能是：

```text
截图帧
通道图
差异热图
输入时间线
窗口元数据
回放工具
实验报告
```

这些看起来不像完整自动化，但它们决定后续所有判断是否可信。

## 27. 心理预期二：很多实验没有结论

预期会频繁得到：

```text
证据不足
方法对画质敏感
只能在一个界面工作
需要连续帧
需要用户标签
当前不可观测
```

这些结论能够关闭错误方向，属于有效进度。

## 28. 心理预期三：大量时间用于基础问题

可能有一半以上时间消耗在：

- 时间戳；
- 重复和旧帧；
- 窗口焦点；
- 多窗口；
- 坐标和DPI；
- 数据保存；
- 偶发失败；
- 反例和复现。

这些基础问题没有解决时，更强模型只会给出更复杂的错误结果。

## 29. 心理预期四：每个游戏仍需适配

通用核心可以共享：

- 帧和输入契约；
- 时间线；
- 证据和回放；
- 规则生命周期；
- 安全执行；
- 实验工具。

游戏特有内容通常仍需适配：

- 状态证据；
- 图标和布局；
- 按键和能力；
- 地图和物品；
- 运动和镜头模式；
- 故障恢复。

## 30. 心理预期五：架构会被修改

当前架构是实验前的最佳假设，不是最终真理。后续可能推翻：

- 是否需要某个字段；
- 某种图是否应该独立；
- 速度是否需要连续数值；
- 某类关系能否自动学习；
- 哪些模型值得实时运行。

应尽量保持Trace Core原始事实和证据契约稳定，让上层解释可以替换。

## 31. 心理预期六：受限成果也有价值

即使最终没有实现通用3D智能体，以下产物仍然独立有用：

- 游戏流式截图和回放工具；
- 输入与画面时间对齐；
- 可解释UI自动化；
- 游戏视觉实验平台；
- 规则归纳和证据系统；
- 物品和材料规划工具；
- 运动和深度分析工具。

## 32. 阶段门禁一：测量能力

进入状态识别前应满足：

- 至少两个截图后端经过可重复对比；
- 像素格式、时间戳和窗口归属明确；
- 被动输入可以与帧对齐；
- 旧帧、失败和重复帧可以区分；
- 同一段数据能够离线重放。

如果无法满足，应继续修正事实层，不进入模型堆叠。

## 33. 阶段门禁二：状态能力

进入关系发现前应满足：

- 至少两个UI状态可稳定区分；
- 相似负样本不会强制命中；
- 动画和遮挡返回`UNKNOWN`；
- 判断可以列出具体证据；
- 离线重复结果一致。

## 34. 阶段门禁三：关系能力

进入主动输入前应满足：

- 关系有多次支持样本；
- 输入未送达和相似状态作为反例；
- 被动相关和因果候选分开；
- 关系固定适用范围和版本；
- 影子运行能够解释预测结果。

## 35. 阶段门禁四：执行能力

进入多个UI能力组合前应满足：

- 输入只送到目标窗口；
- 焦点变化会阻止执行；
- 输入后使用新鲜帧验证；
- 失败、停止和超时释放全部按键；
- 一个简单往返闭环可以重复运行。

## 36. 阶段门禁五：3D能力

进入危险3D场景前应满足：

- 镜头和人物运动能够区分；
- 平地运动状态稳定；
- 撞墙和无推进可以识别；
- 相对深度失效时返回`UNKNOWN`；
- 停止延迟有实验记录；
- 所有试验在安全场景或测试账号进行。

## 37. 一年成功标准

第一年不以“能够自动玩游戏”作为验收，而是：

```text
稳定记录一个游戏窗口的连续画面和输入
能离线重放并检查全部证据
能识别3～5个稳定UI状态
能发现并验证5～10条简单转换关系
能安全执行一个菜单往返闭环
能记录一种物品及数量变化
能在安全平地识别人物运动阶段
```

这些目标可靠完成，项目核心方向即得到初步证明。

## 38. 最小可接受成果

如果一年后只完成：

```text
可靠流式截图
被动输入对齐
证据保存和回放
人工可用的Frame Inspector
一组可重复实验报告
```

项目仍然产生了有价值的游戏视觉研究工具，但说明自动关系和执行方向需要重新评估。

## 39. 理想成果

```text
Trace Core稳定
-> 状态和关系可以从示范中形成候选
-> UI闭环安全执行
-> 图标、物品或运动领域至少一个完成完整演示
-> 新游戏可以复用事实、规则和实验基础设施
```

## 40. 需要暂停或重新评估的信号

- 多种截图方式都无法得到稳定可用帧；
- 输入和帧长期无法可靠对齐；
- 状态只能靠大量人工硬编码且不能复现；
- 主动输入无法可靠限制目标窗口；
- 大量关键问题被证明不可观测；
- 每加入一个游戏都需要重写核心层；
- 维护成本持续高于得到的实验价值；
- 项目只产生文档，没有连续数月的实验产物；
- 安全或账号风险无法控制。

暂停并不等于永久失败，可以收缩为截图回放、UI自动化或单游戏工具。

## 41. 风险登记方式

```text
RiskRecord
├── risk_id
├── description
├── affected_milestones
├── likelihood
├── impact
├── detection_signals
├── mitigation
├── contingency
├── owner
├── review_date
└── status
```

风险不只写在文档里，应在每个阶段复查并更新。

## 42. 周期更新方式

每完成一个阶段，用真实数据更新：

```text
planned_duration
actual_duration
blocked_time
rework_time
experiment_count
invalid_run_count
new_risks
scope_changes
```

后续周期预测使用实际速度，而不是一直沿用本文初始估算。

## 43. 当前建议

未来约三个月只判断一件事：

> 能否建立可靠、可检查、可回放的游戏画面和输入事实层。

如果可以，再用接下来三个月证明一个简单UI状态和执行闭环。只有这两个门槛通过，才扩大到自动关系、物品规划和3D。

## 44. 当前结论

项目最现实的成功路径是：

```text
研究平台
-> 单游戏有限闭环
-> 一个领域完整演示
-> 多游戏适配器和通用核心
```

最大的风险不是某一个模型不够强，而是范围、数据质量、因果误判和上下文增长。最重要的心理预期是：前期大量成果属于测量、回放和失败分析；它们不是绕路，而是后续自动学习和安全执行能够成立的条件。
