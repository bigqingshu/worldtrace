# 大世界互动姿态与主动视角搜索方案

## 1. 文档目标

本文讨论大世界点位到达后，因为角色朝向、镜头角度、距离或遮挡不满足条件，导致互动图标不出现的问题。

核心目标是把现有的：

```text
到达地图点位
→ 检测互动图标
→ 按互动键
```

升级为：

```text
到达互动区域
→ 恢复或搜索可互动姿态
→ 确认目标对象和互动提示
→ 执行互动
→ 验证互动结果
```

## 2. 核心结论

大世界互动对象不能只记录为一个地图坐标点。应当增加“互动姿态”概念：

> 互动姿态 `InteractionPose` 是能够使指定对象出现正确互动提示的一组位置、身体朝向、镜头视角和视觉证据。

同一个对象可以存在多种可成功姿态：

```text
互动对象节点
├─ 姿态A：从南侧接近，平视
├─ 姿态B：从东侧接近，镜头向下
└─ 姿态C：备用位置，稍远距离
```

对象节点表达“这是什么”；互动姿态表达“站在哪里、怎么看它、如何确认能够互动”。

## 3. 为什么单一地图点位不够

同一个二维地图坐标附近，互动提示是否出现可能同时受到以下条件影响：

- 角色最终站立位置；
- 角色身体朝向；
- 镜头水平角度 `yaw`；
- 镜头垂直角度 `pitch`；
- 角色与对象之间的距离；
- 对象是否被墙、植被或其他物体遮挡；
- 对象是否进入游戏设定的屏幕交互区域；
- 附近是否存在另一个优先级更高的互动对象；
- 当前角色状态或能力；
- 对象是否已经被采集或进入冷却；
- 游戏版本是否改变了互动判定范围。

二维点位只能回答“角色大概到了哪里”，不能回答“角色是否正以正确方式面对指定对象”。

## 4. 对象节点与互动姿态分离

### 4.1 对象节点

对象节点保存相对稳定的语义信息：

```json
{
  "object_id": "world_object_000182",
  "type": "collectible",
  "name": "调查点",
  "map_space": "miraland_main",
  "position": [1250.3, 820.7],
  "state": "available",
  "version": 1
}
```

### 4.2 互动姿态

互动姿态保存一次可成功互动所需的控制条件：

```json
{
  "pose_id": "pose_000182_a",
  "object_id": "world_object_000182",
  "stand_position": [1250.3, 820.7],
  "approach_from": [1242.1, 835.4],
  "body_yaw": 42.5,
  "camera_yaw": 40.0,
  "camera_pitch_offset": -18,
  "control_context_requirement": {
    "character_id": "character_...",
    "form_id": "default",
    "ability_loadout_id": "loadout_..."
  },
  "validated_control_schema_revision": 7,
  "expected_prompt": "调查",
  "position_tolerance": 1.5,
  "yaw_search_range": 20,
  "transition_confidence": 0.96,
  "conditional_execution_reliability": 0.93,
  "transient_fault_rate": 0.02,
  "attempts": 28,
  "game_version": "",
  "version": 3
}
```

第一版无法稳定获得绝对 `pitch` 时，可以先保存鼠标纵向相对偏移 `camera_pitch_offset`，后续再替换为可观测的垂直视角状态。

### 4.3 为什么需要多个姿态

同一个对象可能存在：

- 正常推荐姿态；
- 主路径被遮挡时的侧面姿态；
- 不同角色体型或动作状态对应的姿态；
- 游戏更新后的新姿态；
- 更安全但距离稍远的备用姿态。

新演示不应覆盖旧姿态。系统应根据实际成功率、最近验证时间和当前环境选择候选。

姿态定义不应永久绑定某次运行时epoch。定义保存适用的`ControlContext`条件；执行时解析当前角色、武器、形态和能力绑定，生成新的`control_schema_epoch`。旧epoch的排队动作、检测结果和校准均不得继续使用。

## 5. 身体朝向与镜头朝向必须分开

第三人称游戏中，角色身体朝向和镜头朝向不一定相同：

```text
角色身体朝向：决定角色实际面对哪个方向
镜头yaw/pitch：决定玩家正在观察哪个方向
```

只旋转镜头不一定会改变角色身体朝向；只让角色朝向对象，也不保证对象进入正确的屏幕区域。

因此互动姿态至少应描述：

```text
站立位置
+
接近方向
+
身体朝向
+
镜头水平视角
+
镜头垂直视角
```

## 6. 使用互动前置点保证身体朝向

### 6.1 只记录最终点的问题

如果路线只记录最终站立点，角色可能从任意方向到达该点。最终位置相同，但身体朝向完全不同。

### 6.2 approach_from

建议每个互动姿态增加一个互动前置点：

```text
approach_from
→ stand_position
→ interaction
```

执行时：

1. 先到达 `approach_from`；
2. 根据 `stand_position` 计算目标方向；
3. 从前置点向最终点直线前进；
4. 到达后立即停止并释放移动键；
5. 此时角色通常自然面向互动对象。

必要时可以在最终点执行极短的向前轻触，让角色身体完成最后一次朝向刷新，但必须防止走过头。

## 7. 用户演示如何产生互动姿态

### 7.1 保留互动前滚动缓冲

系统应持续保留最近 1～3 秒的临时观测和输入缓冲：

- 角色位置；
- 小地图方向；
- 鼠标水平移动；
- 鼠标垂直移动；
- 键盘移动状态；
- 游戏截图；
- 目标检测框；
- 互动提示文字或图标。

当用户成功按下互动键并确认结果后，再回看这段缓冲。

### 7.2 提取内容

一次成功演示可以提取：

```text
最后从哪个方向接近
最终站在什么位置
角色身体大致朝向
镜头水平移动量
镜头垂直移动量
目标位于屏幕哪个区域
出现了什么互动提示
按键后发生了什么状态变化
```

### 7.3 演示不是直接保存原始鼠标轨迹

不建议把所有鼠标移动逐帧原样保存并机械回放。更合适的是收束为：

```text
接近方向
→ 目标视角
→ 允许搜索范围
→ 成功证据
```

这样分辨率、鼠标灵敏度或轻微位置误差变化时，系统仍可以通过视觉反馈修正。

## 8. 主动观测闭环

### 8.1 主流程

推荐的通用执行流程：

```text
到达互动前置点
→ 沿记录方向进入最终站立点
→ 停稳并释放所有移动键
→ 取得desktop_physical_input与有效focus_epoch
→ 确认control_schema_epoch仍匹配
→ 恢复历史成功yaw/pitch
→ 检测目标对象
→ 检测指定互动提示
→ 连续多帧确认
→ 按互动键
→ 验证互动结果
```

它不是“盲目恢复视角后立即按键”，而是“恢复姿态后等待视觉条件成立”。

### 8.2 推荐状态机

```text
APPROACHING
→ POSITION_SETTLED
→ ALIGNING_VIEW
→ SEARCHING_PROMPT
→ PROMPT_CONFIRMED
→ INTERACT_SENT
→ OUTCOME_CONFIRMED
```

失败状态可以包括：

```text
TARGET_NOT_FOUND
PROMPT_NOT_FOUND
WRONG_PROMPT
VIEW_SEARCH_EXHAUSTED
INTERACTION_TIMEOUT
OUTCOME_NOT_CONFIRMED
```

这些名称是控制器内部阶段和`reason_code`，不是另一套公共结果枚举。`CapabilityRun`最终仍使用`SUCCEEDED/FAILED/UNKNOWN/CANCELLED/BLOCKED`，并与截图、角度、位置、焦点epoch和候选姿态绑定。

## 9. 互动提示必须与目标身份绑定

### 9.1 只检测通用F图标不够

附近存在多个可互动对象时，通用互动图标只能说明“某个对象可互动”，不能说明“指定对象可互动”。

最终条件应当是：

```text
目标对象身份正确
+
期望互动提示正确
+
提示连续稳定出现
```

### 9.2 可用身份依据

可以组合：

- 目标对象检测框；
- OCR 识别的互动文字；
- 对象名称；
- 对象在屏幕中的相对位置；
- 当前地图节点；
- 对象周围的环境视觉特征；
- 互动后的结果。

### 9.3 连续帧确认

建议至少连续两帧检测到正确提示后再执行，避免动画、拖影或单帧误识别：

```text
frame N：正确提示
frame N+1：正确提示
→ PROMPT_CONFIRMED
```

### 9.4 提示缺失不等于姿态关系错误

到达历史成功姿态后没有出现图标或文字，至少需要区分：

```text
对象当前不可用或已采集
目标被遮挡或布局发生变化
角色/能力上下文不匹配
截图或检测器失效
输入送达错误窗口
游戏瞬态Bug导致提示缺失
互动姿态本身已经失效
```

系统先生成`ui_integrity`、可用性、感知健康和输入归属证据。只有环境健康、上下文匹配、对象可用且感知有效时，多次受控搜索仍失败，才降低姿态的条件执行可靠性。故障画面不能直接进入正常提示模板或新姿态聚类。

## 10. 视角搜索策略

### 10.1 不应盲扫360度

在已知对象附近直接旋转一整圈存在明显风险：

- 附近其他互动对象进入视野；
- 错误提示被触发；
- 角色失去原始朝向；
- 搜索耗时过长；
- 动态目标移动；
- 镜头进入墙体或遮挡区域。

搜索应围绕历史成功姿态，在有限锥形范围内进行。

### 10.2 水平交错扫描

推荐按从小到大的交错顺序搜索：

```text
0°
+5°
-5°
+10°
-10°
+20°
-20°
```

这种顺序优先尝试最接近记录姿态的视角，并避免向单一方向持续偏离。

每次调整后应：

1. 等待画面稳定；
2. 获取新截图；
3. 检测目标和互动提示；
4. 更新搜索证据；
5. 成功后立即停止扫描。

### 10.3 垂直视角扫描

Whimbox 当前没有可用的绝对 `pitch` 状态。第一版可以使用相对鼠标纵向偏移层：

```text
0px
-20px
+20px
-40px
+40px
```

实际像素值必须通过当前游戏灵敏度测试，不能直接跨游戏复用。

建议先在每个水平候选下只测试少量垂直偏移，避免组合数量爆炸。

### 10.4 分层搜索顺序

完整搜索建议按成本递增：

```text
1. 恢复最高成功率姿态
2. 小范围水平扫描
3. 少量垂直扫描
4. 前后微调距离
5. 左右微移解除遮挡
6. 换用下一组历史姿态
7. 请求用户重新演示
```

不要一开始同时组合大量位置和角度候选。

## 11. 位置微调策略

### 11.1 为什么需要移动

互动提示不出现不一定是镜头错误，也可能是：

- 距离太远；
- 距离太近；
- 对象被遮挡；
- 站在对象背面；
- 地形碰撞使角色没有真正到达记录位置；
- 动态对象发生少量移动。

### 11.2 推荐微调顺序

在视角扫描失败后再尝试：

```text
轻微后退
→ 恢复视角并检测

轻微前进
→ 恢复视角并检测

左侧微移
→ 恢复视角并检测

右侧微移
→ 恢复视角并检测
```

每次移动后必须重新定位，并在 `finally` 中释放所有按键。

### 11.3 受限搜索区域

互动节点应定义最大允许偏移范围。超过范围后停止自动搜索，避免角色离开安全区域、跌落或触发其他对象。

## 12. YOLO目标检测后的视觉伺服

### 12.1 对象框对齐

如果 YOLO 能够检测目标对象，可以通过目标框进行连续视角修正：

```text
检测目标对象框
→ 计算目标中心与期望交互区域的水平误差
→ 相对移动鼠标修正yaw
→ 计算垂直误差
→ 相对移动鼠标修正pitch
→ 重新检测
```

这是一种视觉伺服，不依赖一次鼠标移动绝对准确。

### 12.2 InteractionZone

对象不一定必须位于屏幕正中心。可以通过成功演示统计：

> 某类对象通常位于屏幕哪个区域时，游戏会显示互动提示。

将该区域定义为 `InteractionZone`：

```json
{
  "center": [0.52, 0.48],
  "width": 0.18,
  "height": 0.22
}
```

坐标使用归一化屏幕比例，减少分辨率变化影响。

### 12.3 目标检测不是最终成功条件

YOLO 检测到对象，只能说明对象可见。是否真正可互动仍应以游戏互动提示或后置状态为准。

## 13. OCR、YOLO、SAM、CLIP与模板匹配分工

| 模块 | 主要职责 | 不负责的内容 |
| --- | --- | --- |
| 模板匹配 | 快速检测通用互动图标 | 区分复杂目标身份 |
| OCR | 识别“调查”“拾取”“对话”等提示文字 | 精确控制镜头角度 |
| YOLO | 检测对象、NPC、动物、机关和对象框 | 最终确认互动成功 |
| SAM | 分割对象轮廓和遮挡区域 | 第一版固定对象流程 |
| CLIP | 对象语义候选、地点语义和相似内容搜索 | 像素级视角伺服 |

低层执行应由确定性视觉反馈控制。LLM 不参与每次鼠标微调，也不决定什么时候盲目按互动键。

## 14. 动态互动对象

动物、移动NPC等对象不能只依赖固定 `stand_position`。

建议：

```text
固定地图节点
→ 只表示对象通常出现的区域

实时YOLO跟踪
→ 输出当前对象框和运动方向

视觉伺服
→ 持续调整视角与距离

互动提示
→ 最终触发条件
```

动态对象的互动姿态应更多保存“距离范围、目标屏幕区域、接近策略”，而不是单一绝对位置。

## 15. 成功验证

### 15.1 按键不等于成功

互动键已经发送只能说明发生了输入事件，不能说明目标对象接受了互动。

至少应验证一种后置证据：

- 互动提示消失；
- 对象从场景消失；
- 出现获得物品文字；
- 进入对话页面；
- 进入新界面；
- 角色播放指定动作；
- 任务计数变化；
- 背包数量变化；
- 地图节点状态变化。

### 15.2 三阶段证据

```text
PROMPT_CONFIRMED
→ INTERACT_SENT
→ OUTCOME_CONFIRMED
```

只有到达 `OUTCOME_CONFIRMED`，本次关系边执行才记录为成功。

公共记录表示为：

```text
StepAttempt
├── ExecutionOutcome
├── reason_code
├── FailureAttribution
├── SampleDisposition
├── focus_epoch / control_schema_epoch
└── 前置、提示、输入和后置证据
```

主动搜索、输入发送和后置确认分别保留事实。输入已经发送但后置截图失效时结果为`UNKNOWN`，不能自动重复互动键。

### 15.3 幂等性与不可逆动作

对于对话、拾取等相对安全动作，可以有限重试。对于购买、分解、提交稀有物品等不可逆动作，未确认目标身份时不得自动重试。

## 16. 姿态版本与置信度管理

互动姿态是节点版本管理最有价值的应用位置之一。

每个姿态建议记录：

- 创建来源；
- 用户演示时间；
- 游戏版本；
- 角色或能力条件；
- 分辨率和视角设置；
- 尝试次数；
- 成功次数；
- 连续失败次数；
- 最近成功时间；
- 最近失败证据；
- 关系正确性；
- 当前可用性；
- 条件执行可靠性；
- 感知可靠性；
- 瞬态故障率；
- 恢复成功率；
- 是否已失效。

选择顺序可以是：

```text
当前游戏版本匹配
→ 前置条件满足
→ 最近验证时间较新
→ 成功率较高
→ 搜索成本较低
```

连续失败的姿态应先按`FailureAttribution`分类，而不是直接降权或删除。游戏Bug、截图失败、输入错投和角色绑定过期不进入姿态条件执行可靠性的失败分母；只有有效Attempt中的真实失败才影响选择权重。游戏更新后可以保留旧版本用于分析差异。

## 17. Whimbox现有实现与缺口

### 17.1 路线点没有互动姿态

Whimbox 的路线点模型主要保存：

```text
position
move_mode
point_type
action
action_params
```

见 [`scripts_manager.py`](../../../../reference_repos/whimbox/whimbox/common/scripts_manager.py#L25)。当前没有：

- `body_yaw`；
- `camera_yaw`；
- `camera_pitch`；
- `look_at`；
- `target_object_id`；
- `expected_prompt`。

### 17.2 录制路线不保存视角

路线录制主要记录角色地图位置和动作标记，没有把用户成功互动时的镜头角度保存下来，见 [`record_path_task.py`](../../../../reference_repos/whimbox/whimbox/task/navigation_task/record_path_task.py#L31)。

宏录制还明确提示不支持录制视角转动，见 [`record_macro_task.py`](../../../../reference_repos/whimbox/whimbox/task/macro_task/record_macro_task.py#L234)。

### 17.3 普通拾取只检测提示

[`PickupTask`](../../../../reference_repos/whimbox/whimbox/action/pickup.py#L9) 的行为是：

```text
检测IconPickupFeature
→ 出现则按互动键
→ OCR读取获得文字
→ 提示不出现则退出
```

它不会主动旋转镜头、调整距离或搜索备用站位。

后台自动拾取同样只检测提示并连续按互动键，见 [`background_task.py`](../../../../reference_repos/whimbox/whimbox/task/background_task/background_task.py#L386)。

### 17.4 材料追踪是有限参考

[`MaterialTrackBaseTask`](../../../../reference_repos/whimbox/whimbox/action/material_track_base.py#L45) 会：

```text
从小地图追踪标记计算目标方向
→ 转动水平镜头
→ 向前移动
→ 能力按钮亮起后停止
```

它已经具有“方向反馈 + 接近 + 可执行状态判断”的雏形，但依赖游戏自带材料追踪，只适用于特定材料能力，不是通用互动对象方案。

### 17.5 当前只具备水平镜头控制

[`direct_cview()`](../../../../reference_repos/whimbox/whimbox/view_and_move/view.py#L9) 只发送水平相对移动：

```python
itt.move_to([px, 0], relative=True)
```

没有通用的垂直视角状态、校准和反馈，因此特殊俯视或仰视互动需要新增模块。

## 18. 最小可行升级

第一阶段不需要立即接入完整目标检测和复杂姿态学习，可以先做确定性扩展。

### 18.1 路线点扩展

增加可选字段：

```json
{
  "approach_from": null,
  "facing_yaw": null,
  "prompt_text": null,
  "view_search": null,
  "control_context_requirement": null,
  "interaction_pose_revision": null
}
```

旧路线没有这些字段时继续使用原有行为，保持兼容。

### 18.2 到点后的水平校正

```text
到达互动点
→ 停止移动
→ 验证window_instance_id、focus_epoch和control_schema_epoch
→ change_view_to_angle(facing_yaw)
→ 检测指定互动提示
```

### 18.3 小角度扫描

提示未出现时执行：

```text
0°、+5°、-5°、+10°、-10°、+20°、-20°
```

每次等待稳定帧并检测提示，超过次数后结束。

### 18.4 结果验证

按键后检查：

- 提示消失；
- 奖励文字；
- 页面变化；
- 指定动作状态。

失败时保存完整截图、当前角度、位置和搜索历史。

该最小升级仍需让整段控制持有`game_control:<window_instance_id>`；真正发送鼠标和键盘时再独占`desktop_physical_input`。任一epoch变化都结束当前Attempt并重新观察，禁止从旧搜索索引继续输入。

## 19. 后续升级顺序

建议按以下顺序逐步实现和测试：

1. 互动提示检测与OCR身份确认；
2. 路线点保存最终水平朝向；
3. 到点后的水平小范围扫描；
4. 互动后置结果验证；
5. 记录互动前置点和接近方向；
6. 垂直鼠标相对偏移扫描；
7. 距离与左右位置微调；
8. 多互动姿态统计和降权；
9. 图标缺失、控件变灰和瞬态Bug故障注入；
10. 多窗口抢焦点和旧epoch拒绝测试；
11. YOLO对象检测；
12. 目标框视觉伺服；
13. 动态目标跟踪；
14. 绝对或可观测的镜头pitch状态。

每一步都应拥有离线截图测试和实机受限测试，不要等到完整关系网规划器完成后才统一验证。

## 20. LLM边界

LLM 不参与以下实时低层过程：

- 每帧是否向左转5°；
- 当前是否向上移动20像素；
- 是否按下互动键；
- 是否继续前进一步；
- 是否命中连续帧阈值。

这些应由确定性控制器处理。

当所有已知姿态和受限搜索都失败后，LLM 可以：

- 整理失败截图和证据；
- 对比旧版本成功记录；
- 判断可能缺少的前置条件；
- 向用户提出具体问题；
- 给新演示生成候选名称和说明；
- 在关系网允许范围内选择备用对象或备用计划。

## 21. 最终建议

建议把通用能力命名为：

```text
InteractionPoseController
互动姿态控制器
```

它接收：

```text
对象节点
+
互动姿态候选
+
当前位置和镜头状态
+
实时截图
```

输出：

```text
ExecutionOutcome
+ reason_code
+ FailureAttribution
+ SampleDisposition
+ 完整姿态搜索与后置验证证据
```

第一版只实现“接近方向 + 最终水平朝向 + 指定提示 + 小角度搜索 + 后置验证”。这已经能够解决大量“点位到了但没有正对对象”的问题。垂直视角、YOLO视觉伺服和动态目标跟踪应在基础闭环稳定后再增加。
