# 无小地图游戏副本的视觉探索与交互方案

## 1. 问题概述

部分游戏副本没有小地图，也不提供完整路线信息，常见特征包括：

- 地图基本只有一条主路线；
- 偶尔存在少量支路；
- 支路通常放置金币、宝箱或拾取物；
- 副本通过机关、门、战斗或场景交互推进；
- 存在轻量解密；
- 副本终点通常有宝箱、出口、传送点或结算界面。

这种副本不适合继续使用大世界中的“小地图导航”逻辑。

更合适的处理方式是：

> 视觉走廊导航 + 可交互目标搜索 + 场景状态变化判断 + 轻量拓扑记忆 + 简单解密状态机。

---

## 2. 无地图副本不需要完整地图

这类副本的重点不是精确坐标，而是：

```text
当前处于哪个场景
当前区域有哪些可交互目标
哪些目标已经处理
哪个操作能够推进副本
下一条可通行道路在哪里
```

因此不需要建立完整二维或三维地图，可以只建立一张进度拓扑图：

```text
入口
  ↓
走廊
  ↓
房间 A
  ├─ 左侧金币
  ├─ 右侧拾取物
  └─ 正前方机关
          ↓
      门开启
          ↓
      房间 B
          ↓
      战斗或解密
          ↓
      终点宝箱
```

这里更重要的是前后关系和事件进度，而不是精确距离。

---

## 3. 副本运行状态

建议至少划分以下状态：

```text
沿路移动
区域搜索
目标接近
执行交互
等待反馈
战斗状态
解密状态
场景切换
副本结束
异常恢复
```

不同状态使用不同的视觉分析和控制逻辑。

---

## 4. 沿路移动

适用于：

- 走廊；
- 山洞；
- 狭窄道路；
- 楼梯；
- 单一道路；
- 线性平台。

此时不需要寻找复杂路线，重点识别：

- 地面可通行区域；
- 道路中心；
- 左右墙体；
- 透视消失点；
- 前方门口；
- 路面断层；
- 明显的道路转弯。

基本流程：

```text
识别可通行区域
  ↓
计算道路中心
  ↓
角色或画面中心对准道路中心
  ↓
短距离前进
  ↓
重新观察
  ↓
修正方向
```

第三人称以角色脚底为起点。

第一人称以画面中心下方为起点。

---

## 5. 唯一道路方向判断

在走廊和单线路径中，可以通过以下信息判断前进方向：

- 地面区域向远处收窄；
- 左右墙体形成透视线；
- 深度图中间区域距离更远；
- 走廊尽头存在门、亮光或开口；
- 背景光流表明角色正在向前移动；
- 地面轮廓在某个方向上连续延伸。

可以从角色脚底或画面下方生成临时路线：

```text
角色脚底或画面下方
  ↓
近处地面中心
  ↓
中距离地面中心
  ↓
远处开口或走廊中心
```

输出只需要是：

```text
前方偏左可通行
正前方可通行
前方偏右可通行
当前道路终止
```

不需要恢复精确三维坐标。

---

## 6. 进入房间后执行区域扫描

走廊可以持续前进，但进入较大的房间后，应先停止移动并扫描。

建议扫描顺序：

```text
当前方向
→ 左侧
→ 正前方
→ 右侧
→ 必要时回看入口
```

扫描内容包括：

- 金币；
- 宝箱；
- 掉落物；
- 发光物体；
- 可交互轮廓；
- 按键提示；
- 机关；
- 门；
- NPC；
- 敌人；
- 可破坏物；
- 新道路开口。

扫描完成后建立当前房间的临时目标表：

```text
目标 1：左侧金币，未拾取
目标 2：前方机关，未交互
目标 3：右侧宝箱，未开启
出口 A：关闭
入口：已记录
```

---

## 7. 可交互目标识别

可交互目标通常具有较稳定的视觉特征：

- 发光；
- 描边；
- 高亮；
- 固定颜色；
- 粒子效果；
- 图标；
- 目标名称；
- 距离提示；
- 屏幕上的交互按键；
- 准星经过时颜色变化；
- 物体外形明显不同。

建议分两层检测。

### 7.1 远距离候选检测

负责发现：

- 发光点；
- 特殊颜色；
- 宝箱外形；
- 物品轮廓；
- 交互图标；
- 场景中明显独立的小目标。

输出：

```text
目标位于画面左侧
目标位于画面中心偏右
目标距离较远
目标类型疑似拾取物
```

### 7.2 近距离交互确认

接近目标后等待：

- 拾取提示；
- 调查提示；
- 开启提示；
- 互动提示；
- 按键图标；
- 目标轮廓高亮。

只有近距离交互条件成立，才真正执行交互。

---

## 8. 使用视觉闭环接近目标

不需要预先估算物品真实三维坐标。

只需要让目标逐步靠近画面指定区域：

```text
目标在左侧
→ 向左调整镜头或移动

目标进入画面中心附近
→ 向前移动

目标尺寸持续变大
→ 正在接近

出现交互提示
→ 停止并执行交互
```

完整闭环：

```text
观察目标偏移
→ 执行小幅动作
→ 再观察
→ 修正方向
→ 接近目标
→ 等待交互提示
```

这比固定鼠标量和固定移动时间更稳定。

---

## 9. 物品收集优先级

进入房间后，可以按以下优先级处理：

```text
即将消失的掉落物
任务物品
高价值宝箱
关键机关
普通拾取物
金币和散落物
主路线出口
```

每个候选目标建议记录：

```text
目标类型
画面位置
目标大小
是否可到达
尝试次数
是否出现交互提示
交互是否成功
是否已消失
是否会推进剧情
```

连续多次无法到达的目标可以标记为：

```text
暂时不可达
疑似装饰物
需要先完成其他机关
路径被阻挡
```

## 10. 交互成功判断

不能只确认是否按下交互键，还要观察交互后的变化。

拾取成功可能表现为：

- 物品消失；
- 数量增加；
- 获得物品提示出现；
- 发光轮廓消失；
- 交互提示消失；
- 音效或动画出现；
- 任务进度变化。

机关成功可能表现为：

- 门开启；
- 灯光变化；
- 新道路出现；
- 机关颜色变化；
- 动画播放；
- 任务文字更新；
- 场景结构发生变化。

建议流程：

```text
记录交互前状态
  ↓
执行交互
  ↓
等待动画或反馈
  ↓
记录交互后状态
  ↓
比较变化
```

输出：

```text
交互成功
交互无效
正在播放动画
需要继续操作
状态不确定
```

## 11. 轻量解密处理

轻量解密通常是有限状态问题，例如：

- 按顺序点亮机关；
- 激活多个开关；
- 推动物体；
- 旋转装置；
- 连接线路；
- 根据颜色或符号进行选择；
- 将物品放到指定位置；
- 观察环境提示后进行操作。

可以将其作为独立解密状态机：

```text
检测到解密区域
  ↓
识别可操作对象
  ↓
记录当前状态
  ↓
执行一个操作
  ↓
观察状态变化
  ↓
判断是否接近完成
  ↓
继续、回退或更换操作
```

---

## 12. 规则明确的解密

如果视觉规则明确，可以直接处理：

```text
未亮机关 → 激活
颜色不一致 → 旋转
线路未连通 → 调整
多个按钮中有一个未按 → 前往未按按钮
图案不一致 → 调整到目标图案
```

这类解密不需要大模型持续参与。

---

## 13. 未知规则解密

如果规则未知，可以采用低成本试探：

```text
记录初始状态
→ 操作对象 A
→ 观察变化
→ 操作对象 B
→ 观察变化
→ 判断每个操作的作用
```

保存：

```text
状态
→ 操作
→ 新状态
```

逐步建立小型状态图。

只要对象数量不多，就可以通过有限尝试找到可行路径。

---

## 14. 固定解密的示范学习

对于复杂但固定的解密，更现实的方法是：

- 用户示范一次；
- 记录操作顺序；
- 保存机关视觉特征；
- 保存每一步操作后的状态；
- 下次通过视觉重新定位；
- 根据当前状态复现操作。

重点不是固定坐标点击，而是：

```text
重新识别机关
确认当前状态
执行对应动作
验证状态变化
```

---

## 15. 使用事件进度代替地图坐标

无地图副本中，事件进度比精确坐标更重要。

可以维护：

```text
当前副本阶段
├─ 已进入副本
├─ 第一段走廊通过
├─ 房间 A 金币已收集
├─ 机关 A 已激活
├─ 门 A 已开启
├─ 房间 B 战斗完成
├─ 解密 B 已完成
└─ 终点宝箱未开启
```

这是一张事件地图。

即使不知道准确坐标，也可以知道：

```text
已经完成哪些条件
当前还缺少什么
下一步应该寻找什么
```

---

## 16. 场景指纹与面包屑

没有小地图时，场景指纹承担主要定位作用。

每经过一个关键位置保存：

```text
场景深度指纹
颜色特征
轮廓结构
入口方向
出口方向
当前副本阶段
已完成交互列表
```

典型节点：

- 副本入口；
- 走廊转弯；
- 房间入口；
- 机关位置；
- 楼梯入口；
- 战斗房；
- 解密区；
- 出口；
- 终点宝箱。

形成：

```text
入口节点
→ 走廊节点
→ 房间 A
→ 机关 A
→ 开门后走廊
→ 战斗房
→ 终点
```

---

## 17. 岔路和支路处理

主路线唯一时，也可能存在短支路。

路口节点：

```text
路口节点
├─ 主路：未探索
└─ 支路：未探索
```

处理方式：

```text
进入支路
→ 收集物品
→ 检测尽头
→ 旋转回头
→ 根据场景指纹返回路口
→ 继续主路
```

支路尽头通常表现为：

- 前方墙体；
- 地面终止；
- 可通行区域变窄；
- 没有新门口；
- 没有新的深度延伸。

此时应执行回头。

---

## 18. 主路线判断

可以综合以下证据：

- 道路更宽；
- 地面连续更远；
- 存在门、亮光或远景；
- 主任务标志位于该方向；
- 已完成机关后该方向发生变化；
- 支路尽头没有出口；
- 场景构图和灯光明显引导；
- 敌人或交互物集中在该方向。

游戏关卡经常通过以下方式引导玩家：

```text
灯光
道路宽度
门框
远景
颜色
动态目标
```

这些都可以成为主路线判断的视觉权重。

## 19. 卡住和漏项恢复

无地图副本常见问题：

- 漏掉机关；
- 没捡关键物品；
- 门没有打开；
- 卡在墙边；
- 目标不可达；
- 在同一区域重复扫描；
- 不知道下一步做什么。

异常判断：

```text
持续移动但场景深度基本不变
→ 可能撞墙或卡住

重复出现相同场景指纹
→ 可能绕圈

出口关闭且没有发现新道路
→ 可能漏掉机关

任务阶段长时间不变化
→ 检查遗漏的交互物或拾取物
```

恢复流程：

```text
停止移动
→ 回到房间中心或入口附近
→ 扩大镜头扫描范围
→ 查找未处理目标
→ 按低置信度候选逐个验证
```

---

## 20. 战斗与探索分离

战斗会干扰：

- 光流；
- 深度判断；
- 场景指纹；
- 角色位置；
- 可交互物识别；
- 道路判断。

因此应切换状态：

```text
探索状态
→ 战斗状态
→ 战斗结束确认
→ 掉落物收集
→ 场景重新扫描
→ 恢复探索
```

战斗结束后不要立即继续前进，应先：

- 搜索掉落物；
- 检查新门；
- 检查新机关；
- 重新识别出口；
- 更新副本阶段。

---

## 21. 副本场景切换

副本中常见：

- 门开启；
- 电梯；
- 传送；
- 黑屏；
- 加载动画；
- 镜头演出；
- 场景结构改变。

进入场景切换状态时：

```text
暂停移动
→ 等待画面稳定
→ 检测当前视角
→ 识别新场景
→ 重新建立可通行区域
→ 更新副本阶段
```

---

## 22. 副本结束判断

副本结束可能表现为：

- 终点宝箱开启；
- 结算界面；
- 副本完成文字；
- 奖励列表；
- 离开按钮；
- 传送出口；
- 倒计时停止；
- 任务状态完成。

应将其作为独立状态：

```text
副本结束
├─ 收取奖励
├─ 确认是否还有遗漏
├─ 执行离开
└─ 保存本次路线与结果
```

---

## 23. 统一运行流程

```text
进入副本
  ↓
判断当前是走廊还是房间
  ↓
走廊：沿可通行区域前进
  ↓
进入新房间
  ↓
停止并扫描场景
  ↓
建立可交互目标列表
  ↓
收集普通物品
  ↓
执行关键机关
  ↓
观察门和道路变化
  ↓
发现新出口
  ↓
记录场景节点
  ↓
继续下一段
```

遇到解密：

```text
识别解密对象
→ 建立当前状态
→ 执行一次操作
→ 观察反馈
→ 更新状态
→ 直到出口开放
```

遇到战斗：

```text
进入战斗状态
→ 完成战斗
→ 收集掉落
→ 重新扫描房间
→ 继续探索
```

## 24. 与大世界模式的区别

| 大世界导航 | 无地图副本 |
|---|---|
| 小地图提供全局方向 | 场景出口提供前进方向 |
| 地图坐标重要 | 副本阶段重要 |
| 需要远距离路线规划 | 主要处理局部道路 |
| 场景指纹辅助定位 | 场景指纹承担主要定位 |
| 路线选择较多 | 通常单线或少量支路 |
| 依赖目标点引导 | 依赖交互和场景变化 |
| 主要问题是寻路 | 主要问题是漏项和推进 |

因此无地图副本更适合建立：

> 场景节点图 + 交互任务图。

## 25. 副本探索模式输出

建议统一输出：

```text
场景类型：房间

可通行出口：1 个
已发现交互目标：3 个
已完成目标：2 个
关键机关：未完成

当前搜索状态：扫描右侧
最近节点：房间 A 入口
重复场景风险：低
```

## 27. 推荐实现顺序

### 第一阶段：沿路移动

实现：

- 地面分割；
- 走廊中心；
- 前方开口；
- 墙体和断层；
- 短距离闭环移动。

### 第二阶段：房间扫描

实现：

- 停止移动；
- 左、中、右扫描；
- 门口、物品和机关候选检测；
- 临时目标列表。

### 第三阶段：目标接近与交互

实现：

- 目标居中；
- 目标尺寸变化；
- 近距离交互提示；
- 交互结果确认。

### 第四阶段：副本事件状态

实现：

- 门开启；
- 机关完成；
- 场景变化；
- 副本阶段推进；
- 漏项检测。

### 第五阶段：场景节点记忆

实现：

- 入口、走廊、房间和机关节点；
- 场景指纹；
- 支路返回；
- 重复场景判断。

### 第六阶段：轻量解密

实现：

- 可操作对象识别；
- 状态变化记录；
- 简单规则；
- 有限试探；
- 用户示范复现。

## 28. 核心结论

无小地图副本不需要完整地图，也不需要复杂全局寻路。

它更适合采用：

```text
走廊：
沿可通行区域前进

房间：
停止并扫描

物品：
视觉闭环接近并确认拾取

机关：
交互后观察场景变化

解密：
使用有限状态机

定位：
依靠关键场景指纹

进度：
依靠副本事件状态

异常：
通过重新扫描和漏项检查恢复
```

可以将整体策略概括为：

> 有路就沿路走，进入房间先扫描，有物品就接近确认，有机关就交互并观察反馈，门不开就寻找遗漏条件，场景变化后继续推进，走过的位置只记录关键节点。

这种副本模式通常比大世界自主导航更容易实现，因为游戏关卡已经限制了路线，系统主要解决的是：

```text
看路
搜索
拾取
交互
轻量解密
确认进度
避免漏项
```
