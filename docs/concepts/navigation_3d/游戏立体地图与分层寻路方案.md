# 游戏立体地图与分层寻路方案

## 1. 问题概述

目前许多游戏，无论是大世界地图、地下城、建筑内部还是城市区域，都存在不同高度和不同层级的地图结构，例如：

- 地面道路；
- 地下通道；
- 建筑不同楼层；
- 高架桥；
- 山洞上下层；
- 空中平台；
- 多层城市；
- 水下区域；
- 飞行区域。

如果仍然把地图当作单一二维平面处理，就会出现明显问题：

```text
玩家与目标在小地图二维位置上接近
但实际上：
├─ 玩家在地面
├─ 目标在高架桥
└─ 或目标在地下通道
```

因此，立体地图不能只保存横向和纵向坐标，还需要加入地图层级、高度关系和层间连接。

本方案不追求一开始完整重建精确三维世界，而是采用：

> 分层 2.5D 地图 + 垂直连接节点 + 当前高度状态 + 局部视觉判断。

---

## 2. 核心思路

整体结构：

```text
全局地图
  ├─ 不同地图区域
  ├─ 不同地图层级
  ├─ 每层内部二维路线
  └─ 层间连接节点

局部视觉
  ├─ 楼梯
  ├─ 斜坡
  ├─ 平台
  ├─ 墙体
  ├─ 路面断层
  └─ 可通行区域

场景记忆
  ├─ 当前区域
  ├─ 当前层级
  ├─ 当前方向
  └─ 场景指纹
```

可以理解为：

- 每一层内部继续按照二维地图处理；
- 不同层之间通过楼梯、电梯、攀爬、跳落等特殊节点连接；
- 深度图和视觉判断负责眼前的立体关系；
- 小地图、地图楼层UI和历史路线负责全局层级定位。

---

## 3. 将地图拆成不同层级

立体地图不应保存成一张混合二维图：

```text
地图
└─ 所有道路混在一起
```

而应拆成：

```text
区域地图
├─ 地下二层
├─ 地下一层
├─ 地面层
├─ 二层平台
├─ 高架层
└─ 特殊立体区域
```

每个层级内部仍然按照二维方式处理：

```text
当前层内
├─ 前进
├─ 左转
├─ 右转
├─ 路口
├─ 障碍
├─ 门口
└─ 目标点
```

不同层级之间通过特殊连接建立关系：

```text
地面层节点 A
  ↓ 楼梯上行
二层节点 B
  ↓ 穿过走廊
二层节点 C
  ↓ 电梯下降
地下层节点 D
```

---

## 4. 地图位置的数据表示

普通二维地图可能只需要：

```text
横向位置 X
纵向位置 Y
```

立体地图至少需要：

```text
地图位置
├─ 横向位置 X
├─ 纵向位置 Y
├─ 地图层级
├─ 相对高度
└─ 当前区域
```

同一二维位置可以同时存在多个节点：

```text
X=120，Y=85，层级=0：地面道路
X=120，Y=85，层级=1：高架桥
X=120，Y=85，层级=-1：地下通道
```

不一定要计算真实海拔，可以使用离散层级：

```text
地下二层：-2
地下一层：-1
地面层：0
上层：1
高层：2
未知层：未知
```

这里的层级表示拓扑关系，不代表准确高度。

## 5. 地图类型分类

不同游戏区域的立体结构不完全相同，建议将地图类型分为：

### 5.1 单层地图

特点：

- 只有一层；
- 高度变化很小；
- 普通二维寻路即可。

### 5.2 多楼层地图

特点：

- 一层、二层、地下层划分明确；
- 地图UI通常支持楼层切换；
- 层间通过楼梯、电梯等连接。

例如：

- 建筑；
- 地下城；
- 商场；
- 地铁站；
- 室内副本。

### 5.3 连续高度地图

特点：

- 没有明确楼层；
- 道路持续上坡或下坡；
- 可能存在山路、盘旋道路和大型洞穴。

此时可以使用高度带：

```text
低高度带
中高度带
高高度带
```

只记录比之前高、低或基本不变，不追求真实米数。

### 5.4 完全三维区域

特点：

- 可以自由飞行；
- 可以自由上浮和下潜；
- 路径不再主要依附地面。

例如：

- 飞行地图；
- 水下区域；
- 太空区域。

这类地图需要单独的三维移动控制，不能完全套用地面寻路逻辑。

---

## 6. 层间连接节点

不同层级之间通过特殊路线边连接。

普通连接：

```text
节点 A → 节点 B
类型：平面移动
操作：向前
```

垂直连接：

```text
节点 A → 节点 B
类型：楼梯上行
操作：向前 + 方向修正
结果：层级 +1
```

建议支持以下连接类型：

```text
平面移动
楼梯上行
楼梯下行
斜坡上行
斜坡下行
电梯
攀爬
跳跃到高处
向下跳落
传送
滑索
飞行上升
飞行下降
游泳上浮
游泳下潜
```

---

## 7. 层间连接的属性

每条连接不能只记录起点和终点，还应记录：

```text
路线连接
├─ 起点
├─ 终点
├─ 连接类型
├─ 上升或下降
├─ 单向或双向
├─ 是否需要交互
├─ 是否需要跳跃
├─ 是否需要等待
├─ 操作方式
├─ 风险等级
├─ 历史成功率
└─ 失败修正
```

例如：

```text
高台 → 地面
类型：跳落
方向：下降
通行方式：单向
风险：中

地面 → 高台
不可直接通行
```

这可以避免系统把不可逆路线错误地当成双向道路。

---

## 8. 如何判断当前所在层级

应优先利用游戏自身提供的信息，其次才使用视觉推断。

### 8.1 地图楼层UI

很多游戏会提供：

- 一层、二层、地下层按钮；
- 当前楼层高亮；
- 上下楼层切换；
- 地下区域标识；
- 楼层名称；
- 地图自动切层。

这类信息可信度最高：

```text
地图UI显示：地下二层
→ 当前地图层 = 地下二层
```

### 8.2 目标上下提示

任务点经常提供：

- 向上箭头；
- 向下箭头；
- 高度差符号；
- 目标位于上层或下层的提示。

例如：

```text
二维距离已经很近
+ 目标显示向上箭头
→ 目标不在当前层
```

### 8.3 小地图局部图案变化

进入新楼层或新区域后，小地图可能明显变化：

```text
开放道路
→ 狭长走廊
→ 楼梯间
→ 室内房间
```

可以为不同层级保存小地图局部指纹。

### 8.4 视觉中的垂直运动

连续画面可以辅助判断：

- 角色持续上坡；
- 角色正在下坡；
- 角色爬楼梯；
- 玩家跳落；
- 电梯正在移动；
- 镜头高度持续变化；
- 地面结构发生稳定变化。

视觉通常只能判断正在上升或下降，不一定能准确知道具体楼层。

### 8.5 路线事件累计

最稳定的方法之一是记录层级转换事件：

```text
到达楼梯入口
→ 执行上楼
→ 到达楼梯出口
→ 当前层级 +1
```

如果路线过程没有被打断，可以通过事件累计维护当前层级。

## 9. 立体地图寻路

立体地图不能只比较二维直线距离。

例如：

```text
目标就在玩家头顶
二维距离：很近

实际路线：
向后走
→ 找到楼梯
→ 上楼
→ 绕回目标位置
```

因此路径必须按照拓扑连接计算：

```text
当前位置节点
  ↓
当前层内路线
  ↓
层间连接节点
  ↓
目标所在层
  ↓
目标节点
```

---

## 10. 不同连接的路径成本

不同连接方式应设置不同成本：

```text
普通道路：低成本
缓坡：低成本
楼梯：中等成本
电梯：等待成本
攀爬：较高成本
跳跃：存在失败风险
跳落：存在不可逆风险
传送：特殊成本
飞行：消耗能力或资源
```

路径计算不应只追求最短距离，还应考虑：

- 是否安全；
- 是否容易执行；
- 是否可逆；
- 是否需要特殊能力；
- 是否需要交互；
- 历史成功率；
- 当前角色状态。

---

## 11. 深度图在立体地图中的作用

深度图主要处理眼前的局部立体关系：

- 前方是平路还是上坡；
- 是否存在楼梯；
- 是否存在平台边缘；
- 地面是否突然下降；
- 前方是否有高墙；
- 高低层之间是否直接连通；
- 角色是否接近断层。

深度图不负责完整的全局楼层定位。

可以理解为：

```text
分层地图
→ 告诉系统应该去哪个楼梯、入口或电梯

视觉深度
→ 告诉系统眼前是否真的是楼梯、能不能走、会不会掉下去
```

---

## 12. 立体场景中的断层分类

检测到高度下降时，不能全部判定为危险。

需要进一步分类：

```text
悬崖：停止
楼梯下行：可以通行
缓坡下行：可以通行
平台边缘：谨慎
任务指定跳落点：允许跳落
普通高台边缘：高风险
水面落差：根据角色能力决定
```

可以结合以下信息：

- 地面区域是否继续；
- 是否存在规则台阶轮廓；
- 深度变化是否渐进；
- 小地图路线是否继续；
- 历史路线是否成功通过；
- 是否出现跳跃或攀爬提示；
- 是否存在交互按钮；
- 当前是否位于已知层间连接节点。

例如：

```text
深度明显下降
+ 地面轮廓呈连续阶梯
+ 小地图路线继续向前
→ 可能是下楼梯
```

```text
深度突然断开
+ 地面分割中止
+ 小地图没有道路
→ 疑似悬崖
```

## 13. 电梯处理

电梯应作为特殊状态流程，而不是普通移动。

```text
到达电梯入口
  ↓
识别电梯门或交互提示
  ↓
执行交互
  ↓
进入电梯
  ↓
识别楼层选择或自动运行
  ↓
等待移动结束
  ↓
检测开门
  ↓
更新当前层级
  ↓
重新进行场景定位
```

电梯过程可能出现：

- 画面基本不动；
- 小地图暂时隐藏；
- 场景加载；
- 楼层选择UI；
- 短暂黑屏；
- 传送式切换。

因此需要单独的电梯状态机。

---

## 14. 楼梯与斜坡处理

楼梯和斜坡可以通过以下信号识别：

- 规则重复边缘；
- 地面深度逐渐变化；
- 角色高度持续变化；
- 小地图路线连续；
- 角色脚底运动轨迹稳定；
- 历史节点标记为楼梯或斜坡。

楼梯节点可以记录：

```text
楼梯入口
楼梯方向
上行或下行
预计持续时间
出口场景指纹
出口层级
```

执行时不应只按固定时间，而应持续确认：

```text
正在上楼
→ 高度持续增加
→ 尚未到出口
→ 继续移动

检测到出口场景
→ 楼梯结束
→ 更新层级
```

---

## 15. 连续高度区域处理

山路、洞穴和盘旋道路不一定存在明确楼层。

此时不强行定义“一层、二层”，而使用高度趋势：

```text
当前高度状态
├─ 持续上升
├─ 持续下降
├─ 基本水平
└─ 高度未知
```

节点之间记录：

```text
节点 A
  ↓ 持续上坡
节点 B：高度带 +1
  ↓ 环形道路
节点 C：高度基本不变
```

系统只需要知道：

- 当前比之前高还是低；
- 是否能够直接到达目标；
- 是否需要寻找上升或下降连接；
- 是否已经到达目标高度带。

---

## 16. 完全三维区域处理

飞行、水下和太空区域需要增加垂直控制维度。

普通地面移动：

```text
前
后
左
右
```

完全三维移动：

```text
前
后
左
右
上
下
```

需要输出：

```text
目标水平偏移
目标垂直偏移
目标距离趋势
当前朝向
当前高度趋势
障碍方向
```

这类区域可以单独作为特殊地图模式，不与普通地面寻路混在一起。

---

## 17. 场景指纹与楼层绑定

原有场景指纹需要增加层级信息：

```text
场景指纹
├─ 当前区域
├─ 当前层级
├─ 高度等级
├─ 进入方向
├─ 小地图局部指纹
├─ 深度结构
├─ 颜色特征
├─ 轮廓结构
├─ 视角模式
└─ 垂直连接历史
```

例如：

```text
节点编号：B204
区域：中央车站
地图层：地下二层
节点类型：楼梯出口
进入方式：从地下一层向下
场景深度指纹：……
小地图局部指纹：……
离开方向：右前方
```

否则同一二维位置附近的地面广场、地下大厅和高架平台可能被错误识别成同一个位置。

---

## 18. 分层场景匹配

场景检索时先筛选：

```text
当前区域
→ 当前层级
→ 当前高度带
→ 最近节点
→ 当前方向
→ 候选场景指纹
```

而不是直接把当前画面与整个数据库比较。

例如：

```text
当前区域：中央车站
当前层级：地下二层
最近节点：楼梯出口
当前方向：向东

候选节点：
B204
B207
B212
```

然后再比较深度、颜色、轮廓和小地图指纹。

## 20. 地图区域结构

```text
地图区域
├─ 区域编号
├─ 区域名称
├─ 地图类型
│   ├─ 单层
│   ├─ 多楼层
│   ├─ 连续高度
│   └─ 完全三维
├─ 地图层列表
├─ 高度带列表
├─ 节点列表
└─ 区域连接
```

不同区域之间也可以通过入口节点连接：

```text
大世界地面
  ↓ 洞穴入口
地下洞穴
  ↓ 电梯
遗迹深层
```

## 21. 运行流程

```text
读取当前地图和小地图
  ↓
识别当前区域
  ↓
识别或推断当前层级
  ↓
读取目标层级
  ↓
判断是否位于同一层
  ├─ 是 → 当前层内寻路
  └─ 否 → 寻找层间连接节点
               ↓
        前往楼梯、电梯或入口
               ↓
        执行层级切换
               ↓
        确认新层级和出口场景
               ↓
        重新定位并继续寻路
```

同时运行局部视觉安全判断：

```text
检测前方地面
检测楼梯或斜坡
检测断层
检测墙体
检测交互提示
检测目标上下提示
```

---

## 22. 推荐实现顺序

### 第一阶段：地图层级识别

实现：

- 地图楼层UI识别；
- 当前楼层高亮识别；
- 目标上下箭头识别；
- 地图层级状态保存。

### 第二阶段：层间连接节点

实现：

- 楼梯入口和出口节点；
- 上行、下行状态；
- 电梯入口和出口；
- 当前层级更新。

### 第三阶段：分层拓扑寻路

实现：

- 每层内部路线；
- 层间连接；
- 单向和双向边；
- 路径成本和风险。

### 第四阶段：视觉辅助判断

实现：

- 楼梯、斜坡和平台识别；
- 路面断层分类；
- 高度趋势判断；
- 出口场景确认。

### 第五阶段：场景记忆绑定层级

实现：

- 场景指纹增加区域和层级；
- 分层候选筛选；
- 楼梯出口和电梯出口重定位；
- 历史路线成功率。

### 第六阶段：连续高度与完全三维

实现：

- 高度带；
- 山路和洞穴；
- 飞行或水下移动；
- 上下方向控制。

---

## 23. 核心结论

立体地图不需要一开始建立完整精确的三维模型。

更实用的处理方式是：

```text
全局：
分层拓扑地图

层内：
普通二维寻路

层间：
楼梯、电梯、攀爬、跳落、传送等连接节点

局部：
深度图、地面分割和断层判断

定位：
地图楼层UI + 小地图 + 场景指纹 + 路线历史

控制：
根据当前地图类型选择平面、分层或完全三维移动
```

最终系统需要解决的不是“完整恢复整个三维世界”，而是：

```text
知道自己在哪个区域
知道自己在哪一层
知道目标在哪一层
知道应该通过哪个入口上下移动
知道眼前是楼梯、斜坡还是悬崖
知道完成层级切换后如何重新定位
```

这套方案可以覆盖大多数具有多层地图的大世界游戏、地下城、建筑、城市、高架道路和洞穴区域。
