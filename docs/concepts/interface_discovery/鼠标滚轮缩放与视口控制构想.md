## 1. 核心想法

鼠标滚轮缩放也属于可校准连续交互，但它与普通滑动条不同：

- 输入通常是离散滚轮格数或原始滚轮增量；
- 实际结果可能是连续倍率、离散缩放等级或3D镜头变化；
- 同一个滚轮输入在不同页面、鼠标位置和控制模式下可能产生完全不同的效果；
- 缩放经常围绕鼠标所在位置发生，因此鼠标坐标本身也是动作参数；
- 放大和缩小不一定完全对称；
- 到达最大或最小级别后，继续滚动可能不再产生变化。

因此，不应把它简单记录成：

```text
滚轮向上3次
```

而应表达成：

```text
把地图缩放到目标倍率
```

或者：

```text
持续放大，直到目标图标达到可识别尺寸
```

系统负责根据当前视口、活动校准和实际反馈，计算需要发送多少次滚轮输入。

## 2. 同一个滚轮不是同一个能力

滚轮的语义高度依赖上下文：

```text
地图页面 + 光标位于地图视口
-> 放大或缩小地图

列表页面 + 光标位于列表区域
-> 上下滚动内容

设置页面 + 光标位于数值控件
-> 增加或减少当前数值

3D游戏状态 + 相机允许缩放
-> 改变镜头距离或视场角

3D游戏状态 + 武器切换规则
-> 切换武器或快捷栏
```

所以节点的前置条件至少需要包含：

```text
当前页面
当前控制模式
鼠标焦点区域
光标是否可见
目标视口身份
是否处于允许主动探测的安全状态
```

不能因为用户曾经在地图上使用滚轮放大，就把任意游戏状态下的滚轮向上都理解成缩放。

## 3. ContinuousController专业化

```text
ContinuousController: control.map_zoom
├── detect_viewport()
├── observe_zoom_state()
├── calibrate_wheel_response()
├── set_zoom(target)
└── verify_zoom(target)
```

节点定义可以包含：

```text
WheelZoomControllerSpec
├── controller_id + revision_id
├── control_id
├── viewport_detector
├── identity_region
├── focus_region
├── safe_input_region
├── forbidden_regions
├── zoom_observer
├── zoom_center_policy
├── wheel_actuator
├── response_model
├── boundary_policy
├── verification_policy
├── calibration_policy
├── calibration_profile_ref
└── safety_policy
```

`WheelZoomControllerSpec`是公共`ContinuousController`的专业配置，不是另一套顶层能力类型。它的算法定义与具体环境参数分开版本化，后者使用`CalibrationProfile<WheelZoomCalibrationPayload>`保存。

其中：

- `viewport_detector`确认当前缩放作用于哪一块画面；
- `identity_region`用于确认目标视口身份，不必等于输入落点；
- `focus_region`规定滚轮输入前鼠标必须位于哪里；
- `safe_input_region`是允许放置光标并发送滚轮的范围；
- `forbidden_regions`排除列表、按钮、危险控件和容易消费滚轮的覆盖层；
- `zoom_observer`负责估计当前倍率或缩放级别；
- `zoom_center_policy`描述以鼠标、屏幕中心还是目标对象为缩放中心；
- `wheel_actuator`描述滚轮方向、单次增量和输入节奏；
- `response_model`保存滚轮输入与画面结果之间的关系；
- `boundary_policy`处理最大、最小缩放和无响应；
- `verification_policy`规定目标误差和允许纠偏次数。

## 4. 先区分滚动、2D缩放和3D镜头变化

系统可以通过输入前后的运动场判断滚轮到底产生了什么效果。

| 画面变化 | 候选含义 |
| --- | --- |
| 大片内容沿同一轴平移，大小基本不变 | 列表或页面滚动 |
| 多数特征围绕一个中心向外扩张或向内收缩 | 2D视口缩放 |
| 远近区域变化幅度不同，透视、遮挡或视野范围改变 | 3D镜头缩放 |
| 只有局部数字、滑块或选项发生变化 | 滚轮调整数值控件 |
| 只有选中图标或物品发生变化 | 武器、快捷栏或选项切换 |
| 画面没有稳定变化 | 输入未生效、到达边界或焦点错误 |

### 4.1 页面滚动的变化签名

```text
特征点大小近似不变
-> 多数特征沿纵轴或横轴平移
-> 内容在裁剪区域边缘进入或离开
```

### 4.2 2D缩放的变化签名

```text
同一批特征仍然存在
-> 特征间距离整体按比例改变
-> 运动方向大致指向或远离某个缩放中心
-> 视口可见范围发生变化
```

### 4.3 3D镜头变化签名

```text
近处和远处对象缩放幅度不同
-> 可能出现新的遮挡或解除遮挡
-> 视场角、相机距离或透视关系改变
-> 很难用单一二维缩放矩阵完整解释
```

## 5. 微量自检流程

在低风险页面第一次使用滚轮缩放时，可以执行：

```text
取得游戏控制资源
-> 确认页面、视口和输入焦点
-> 把鼠标移动到安全缩放锚点
-> 采集缩放前新鲜画面
-> 记录当前缩放状态候选
-> 发送一个最小有效滚轮单位
-> 等待动画和画面稳定
-> 采集缩放后新鲜画面
-> 估计缩放、平移、透视或局部变化
-> 判断滚轮实际语义
-> 反向发送一个单位，尝试恢复原状态
-> 验证是否基本恢复
-> 保存校准记录和证据
```

自检需要回答：

- 滚轮向上是放大还是缩小；
- 一个滚轮单位实际对应多少原始输入量；
- 一个输入单位会改变多少倍率或等级；
- 缩放是线性、乘法还是离散等级；
- 缩放中心在哪里；
- 鼠标位置是否影响缩放中心；
- 连续快速输入是否触发加速或被合并；
- 正向和反向是否对称；
- 是否存在最大和最小边界；
- 反向输入能否恢复到原视口。

## 6. Windows滚轮增量与游戏响应不是同一个概念

底层可能使用类似固定原始增量的滚轮事件，但游戏或UI层可能：

- 把一个标准增量解释为一格；
- 累积多个高精度小增量后才触发一次；
- 忽略过快或过慢的输入；
- 根据连续滚动速度产生加速；
- 对不同输入设备使用不同阈值；
- 在动画尚未结束时吞掉后续输入。

因此校准记录不只保存“滚动几次”，还要保存：

```text
raw_delta_per_event
effective_notch_count
event_interval_ms
response_latency_ms
debounce_or_acceleration
input_backend
```

执行时应优先使用已经验证过的输入节奏，而不是一次性高速发送大量滚轮事件。

## 7. 2D缩放的倍率模型

假设从输入前后画面估计到：

```text
当前尺度：S0
一个滚轮单位后的尺度：S1
```

单步倍率为：

```text
r = S1 / S0
```

如果每个滚轮单位近似产生固定倍率，那么滚动`n`个单位后：

```text
Sn = S0 × r^n
```

给定目标尺度`Starget`，可以估计：

```text
n ≈ log(Starget / S0) / log(r)
```

再根据输入单位必须为整数进行取整，并在执行后视觉验证。

为了让乘法变化更容易建模，也可以使用对数尺度：

```text
z = log(S)
```

此时每个滚轮单位近似对应一个加法变化：

```text
z_next = z_current + k
```

但这个公式只能作为候选。系统必须通过多个位置和多个缩放等级验证`r`是否稳定。

## 8. 离散缩放等级

有些游戏地图并不是连续缩放，而是固定等级：

```text
level_0
level_1
level_2
...
level_n
```

其特征包括：

- 每次滚轮后画面跳到固定倍率；
- 相同方向输入产生重复的几组尺度；
- 接近边界时继续输入不再变化；
- 正反方向可以在相同尺度集合间切换。

这时不应拟合连续公式，而应建立响应表：

```text
zoom_level_0 -> wheel_up -> zoom_level_1
zoom_level_1 -> wheel_up -> zoom_level_2
zoom_level_2 -> wheel_down -> zoom_level_1
```

目标执行可以直接计算当前等级到目标等级之间的有界步数。

## 9. 缩放中心必须进入动作参数

许多2D地图、画布和查看器会围绕鼠标位置缩放。

理想的鼠标中心缩放可以近似表示为：

```text
x' = c + s × (x - c)
```

其中：

- `x`是缩放前的特征位置；
- `x'`是缩放后的特征位置；
- `c`是缩放中心；
- `s`是缩放倍率。

如果缩放围绕鼠标发生，则估计出的`c`应接近滚轮输入时的鼠标位置。

这意味着动作不能只记录：

```text
wheel_up × 3
```

还必须记录：

```text
cursor_anchor
viewport_id
wheel_direction
wheel_count
event_interval
```

### 9.1 缩放锚点策略

可以支持：

| 策略 | 用途 |
| --- | --- |
| `VIEWPORT_CENTER` | 保持整体操作稳定，不关注具体目标 |
| `CURSOR_POSITION` | 复现用户当前缩放中心 |
| `TARGET_OBJECT_CENTER` | 围绕目标图标或对象放大 |
| `SAFE_EMPTY_REGION` | 避免滚轮被局部控件或列表截获 |
| `FIXED_CALIBRATION_ANCHOR` | 自检时使用可重复的标准位置 |

如果鼠标位于重叠列表、浮层或控件上，滚轮可能被局部区域消费。因此每次执行前都要确认锚点仍属于目标视口。

## 10. 缩放经常伴随平移

围绕非中心位置缩放时，前后画面通常同时包含尺度变化和平移变化：

```text
x' = c + s × (x - c) + t
```

其中`t`表示额外平移或视口自动修正。

系统不能只比较某个对象变大了多少，还要区分：

- 纯缩放；
- 围绕鼠标的锚定缩放；
- 缩放后自动居中；
- 缩放与地图惯性平移叠加；
- 用户在滚轮期间同时移动了鼠标；
- 动画尚未稳定造成的临时位移。

自检时应尽量保持鼠标静止，并等待动画稳定后再估计最终变换。

## 11. 当前缩放状态怎样观察

优先级可以是：

### 11.1 直接数值

- 页面显示百分比；
- 地图显示比例尺；
- 设置项显示FOV或镜头距离；
- 存在明确缩放等级文字。

### 11.2 视口内稳定地标

选择两个或多个稳定特征，使用它们之间的像素距离估计尺度：

```text
scale_proxy = 当前地标距离 / 基准地标距离
```

### 11.3 可见区域范围

如果能够识别地图边界、网格或世界坐标，可以估计当前视口覆盖范围：

```text
world_units_per_screen_pixel
```

### 11.4 目标对象尺寸

对稳定目标，可以观察边界框尺寸：

```text
target_size_px
```

但在3D世界中，目标自身移动或相机位置变化也会改变尺寸，因此不能只靠单个对象判断镜头缩放。

### 11.5 无绝对尺度时的相对状态

如果只能判断前后画面相对放大或缩小，可以保存：

```text
UNKNOWN_ABSOLUTE_ZOOM
+ relative_scale_from_reference
+ zoom_direction
+ boundary_state
```

此时更适合执行“放大直到目标可见”一类语义目标，而不是设置精确倍率。

## 12. 3D镜头缩放需要单独建模

3D游戏中的滚轮变化可能来自：

- 改变视场角；
- 拉近或拉远第三人称相机；
- 让相机沿视线方向移动；
- 改变瞄准倍率；
- 切换几个固定镜头档位；
- 切换武器而不是缩放。

### 12.1 改变FOV

特征是：

- 视口中心方向大致不变；
- 整体透视范围改变；
- 屏幕边缘畸变和可见范围明显变化；
- 对象在画面中的尺寸变化，但相机世界位置可能没有移动。

### 12.2 拉近或拉远相机

特征是：

- 相机与角色或目标的距离改变；
- 前景、背景和遮挡关系可能发生变化；
- 可能受到墙壁碰撞限制；
- 相同滚轮输入在狭小环境中产生的结果可能不同。

### 12.3 瞄准倍率

它通常还依赖：

```text
当前武器
是否处于瞄准状态
瞄准镜类型
倍率档位
```

因此应建立类似：

```text
state.gameplay + focus_mode.aiming + weapon_scope_type
-> adjust_scope_zoom(target_level)
```

不能复用地图缩放节点。

## 13. 目标不一定是倍率数值

滚轮缩放可以接受几类目标。

### 13.1 精确倍率目标

```text
set_zoom(1.5x)
```

适合存在可靠数值或尺度观测的视口。

### 13.2 归一化目标

```text
set_zoom(0.7)
```

其中`0`表示最小缩放，`1`表示最大缩放。

### 13.3 离散等级目标

```text
set_zoom_level(level_3)
```

### 13.4 感知条件目标

```text
zoom_until(target_icon.size >= 40px)
zoom_until(region_of_interest fills 60% viewport)
zoom_until(all_required_markers_visible)
zoom_until(map_context_is_sufficient)
```

对自动识别系统而言，感知条件目标往往比固定倍率更实用，因为它直接表达后续OCR、YOLO、CLIP或模板匹配需要怎样的画面尺度。

## 14. 正式执行闭环

```text
确认目标页面、视口和控制模式
-> 确认鼠标锚点位于正确视口
-> 观察当前缩放状态
-> 检查活动校准是否仍然有效
-> 取得desktop_physical_input
-> 固定focus_epoch和适用的control_schema_epoch
-> 创建公共StepAttempt
-> 根据目标计算预计滚轮步数
-> 先发送有限批次输入
-> 等待画面稳定
-> 重新估计实际缩放状态
-> 根据残差继续少量输入
-> 接近目标时改为单步滚动
-> 达到容差或感知条件后停止
-> 保存前后画面、滚轮事件和结果证据
```

每个有限批次发送前都重新检查有效性令牌。任一epoch变化时停止未提交事件；已提交但无法确定效果的批次返回`UNKNOWN`，不能把旧批次继续发送到新页面或新控制Schema。

不建议一次性发送全部预计步数，因为：

- 游戏可能吞掉高速输入；
- 缩放响应可能非线性；
- 中途可能达到边界；
- 焦点可能被浮层改变；
- 目标可能提前满足；
- 动画延迟会让后续输入基于过期状态。

## 15. 边界检测

如果连续向同一方向滚动，但多次观察都没有有效尺度变化，可以形成边界候选：

```text
ZOOM_MIN_REACHED
ZOOM_MAX_REACHED
```

但“没有变化”也可能表示：

- 鼠标焦点错误；
- 当前页面不接收滚轮；
- 输入被局部列表消费；
- 画面仍在动画中；
- 截图返回旧帧；
- 滚轮输入单位低于游戏阈值；
- 当前控制模式禁止缩放。

所以至少需要：

```text
输入已确认发送
+ 新鲜后置画面
+ 视口身份未变化
+ 反方向输入仍有响应或历史上有响应
```

才能较有把握地确认到达边界。

## 16. 校准失效条件

以下情况应使滚轮缩放校准失效或降级：

- 页面或视口身份变化；
- 分辨率、窗口尺寸或UI缩放改变；
- 滚轮输入后变成内容平移而不是尺度变化；
- 滚轮方向与校准方向相反；
- 单步倍率明显变化；
- 出现新的缩放动画、加速或输入吞并；
- 缩放中心不再接近预期锚点；
- 目标尺度公式连续产生较大残差；
- 当前游戏版本、地图模式或相机模式改变；
- 3D场景碰撞导致相机距离模型失效。

系统可以保留旧校准记录用于追溯，但不能继续把它作为活动公式。

## 17. 安全边界

低风险主动探测可以优先用于：

- 已确认的地图页面；
- 图片或物品预览界面；
- 不会触发购买、删除或角色动作的独立视口；
- 能够通过反向滚轮恢复的离散缩放页面。

不应自动探测或需要用户批准的场景包括：

- 战斗中滚轮可能切换武器；
- 滚轮可能改变选中物品或快捷栏；
- 3D镜头变化可能影响角色行动；
- 当前视口与危险按钮、购买列表或设置控件重叠；
- 无法判断滚轮由哪个控件消费；
- 输入后无法可靠恢复原状态。

系统可以优先从用户自然滚轮操作中学习。在积累足够前后画面和输入证据后，再决定是否需要主动自检。

## 18. 校准记录建议

```text
CalibrationProfile
├── calibration_id + revision_id
├── controller_id + controller_revision
├── environment_fingerprint
├── validation_status
└── professional_payload: WheelZoomCalibrationPayload
    ├── control_id
    ├── page_state_id
    ├── viewport_id
    ├── focus_region
    ├── cursor_anchor_policy
    ├── wheel_up_effect
    ├── wheel_down_effect
    ├── raw_delta_per_event
    ├── event_interval_ms
    ├── response_latency_ms
    ├── model_type
    ├── model_parameters
    ├── zoom_levels
    ├── min_boundary_evidence
    ├── max_boundary_evidence
    ├── resolution
    ├── window_size
    ├── ui_scale
    ├── input_backend
    ├── visual_fingerprint
    ├── sample_ids

```

缩进中的滚轮字段属于`WheelZoomCalibrationPayload`。公共`CalibrationProfile`负责修订、环境指纹、验证状态和失效管理，避免其他连续控制器再定义一套校准生命周期。

每次执行另存运行事实：

```text
StepAttempt
└── professional_payload: WheelZoomAttemptPayload
    ├── before_frame_id
    ├── before_zoom_state
    ├── cursor_position
    ├── requested_target
    ├── predicted_wheel_events
    ├── actual_wheel_events
    ├── event_timestamps
    ├── after_frame_id
    ├── observed_transform
    ├── after_zoom_state
    ├── residual
    ├── boundary_result
    └── residual_reason
```

`StepAttempt`公共部分另行保存`focus_epoch`、`control_schema_epoch`、动作送达、顶层`ExecutionOutcome`、证据包和故障处置。专业payload只描述缩放观测与模型残差。

控制器发布状态、校准验证成熟度和当前有效性分轴保存：

```text
controller_release_status:
  DRAFT / CANDIDATE / SHADOW / ACTIVE / DEGRADED / RETIRED

calibration_validation_status:
  UNVALIDATED / OFFLINE_VALIDATED / SHADOW_VALIDATED / LIVE_VALIDATED

calibration_runtime_status:
  ACTIVE / SUSPECT / INVALID / EXPIRED
```

## 19. 建议的执行结果

公共`ExecutionOutcome`只使用：

```text
SUCCEEDED
UNKNOWN
FAILED
CANCELLED
BLOCKED
```

滚轮模块提供以下`reason_code`：

```text
CALIBRATION_REQUIRED
CALIBRATION_INVALID
WRONG_FOCUS_REGION
WRONG_CONTROL_EFFECT
NO_RESPONSE
ZOOM_MIN_REACHED
ZOOM_MAX_REACHED
TARGET_NOT_REACHED
UNSAFE_TO_PROBE
```

其中：

- `WRONG_CONTROL_EFFECT`表示本应缩放，但实际发生了滚动、切换选项或其他变化；
- `WRONG_FOCUS_REGION`表示鼠标所在区域没有把滚轮交给目标视口；
- `NO_RESPONSE`表示输入已发出但没有足够后置变化；
- `TARGET_NOT_REACHED`表示有限纠偏后仍无法达到目标；
- `outcome=UNKNOWN`表示输入可能生效，但画面证据不足以确定实际倍率；直接原因仍由`reason_code`说明。

## 20. 与关系网的结合

关系图不需要为每一个缩放等级建立独立页面节点。可以采用：

```text
离散页面状态
+ 连续视口变量
+ 参数化缩放Step
```

例如：

```text
state.world_map
  zoom_state: level_2
  viewport_center: region_017

step.map_zoom
  target: level_4
  anchor: target_marker_008
```

执行完成后仍停留在`state.world_map`，但连续状态发生变化：

```text
zoom_state: level_2 -> level_4
```

如果后续节点要求OCR识别某个小标签，可以声明前置条件：

```text
target_marker_size_px >= 36
```

规划器就可以自动插入：

```text
map_zoom_until_marker_readable
```

而不是依赖固定的“滚轮向上三次”。

## 21. 最小验证计划

| 实验 | 场景 | 验收重点 |
| --- | --- | --- |
| 语义分类 | 相同滚轮分别作用于列表、2D地图和3D镜头 | 滚动、2D缩放和3D变化不会共用校准 |
| 响应模型 | 线性倍率、乘法倍率和离散等级页面 | 自动选择或拒绝不匹配模型，残差可回放 |
| 缩放中心 | 改变鼠标锚点后执行同一输入 | 正确估计缩放中心和平移耦合 |
| 边界判读 | 到达最大缩放、错误焦点和旧帧三种无变化 | 只有前者形成边界证据 |
| epoch失效 | 批次中途切换窗口或控制模式 | 停止后续滚轮事件，旧StepAttempt不续跑 |
| 校准失效 | 改变分辨率、UI缩放或输入节奏 | 原CalibrationProfile进入INVALID并重新自检 |

记录分类混淆率、目标残差、纠偏次数、边界误报率、校准复用成功率和取消响应时间。主动实验只在可逆低风险视口进行。

## 22. 总结

鼠标滚轮缩放可以被理解为一种带焦点、缩放中心和反馈公式的连续交互：

```text
确认上下文和滚轮实际语义
-> 识别目标视口与鼠标锚点
-> 微量滚动并观察尺度变化
-> 区分滚动、2D缩放、3D镜头和局部控件变化
-> 建立滚轮输入到倍率或等级的响应模型
-> 下次按目标值计算输入
-> 分批执行并持续视觉验证
-> 结果不符时使校准失效并重新自检
```

它的执行目标不是“滚动多少次”，而是“让视口达到后续任务真正需要的观察尺度”。
