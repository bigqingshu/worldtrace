## 1. 核心结论

3D场景不能依靠“记录鼠标移动了多少”保证视角方向，只能依靠：

> 视角状态观测、有限输入、新画面验证和异常恢复组成的反馈闭环。

完整过程应为：

```text
观察当前视角状态
-> 计算目标误差
-> 发送小幅受控输入
-> 等待新鲜稳定画面
-> 测量真实变化
-> 继续修正或结束
```

如果当前画面、UI和历史上下文不足以判断方向，系统必须返回`UNKNOWN`，不能根据鼠标输入量假设已经到达目标角度。

## 2. “保证方向”需要区分两个层次

### 2.1 绝对世界方向

绝对方向回答：

```text
镜头当前朝向世界坐标中的哪个方向？
角色身体当前朝向世界坐标中的哪个方向？
```

它通常需要以下基准之一：

- 小地图北向；
- 罗盘刻度；
- 角色方向箭头；
- 镜头视野扇形；
- 已知方向的稳定地标；
- 游戏提供的角度或调试信息。

绝对方向适合：

- 路线导航；
- 地图定位；
- 按指定方位移动；
- 恢复历史互动姿态；
- 跨帧维护世界空间朝向。

### 2.2 任务相对方向

任务相对方向回答：

```text
指定对象是否已经进入正确屏幕区域？
是否出现了正确互动提示？
瞄准框是否已经对准目标？
```

它不一定需要知道精确世界角度。例如系统只要把目标对象移动到画面中心，并确认正确提示出现，就可以完成互动。

任务相对方向适合：

- 拾取和调查；
- 对话；
- 锁定或瞄准目标；
- 目标框视觉伺服；
- 让某对象进入安全可点击区域。

大多数具体互动优先使用任务相对方向。只有导航、建图和方向复现真正需要绝对世界方向。

## 3. 视角状态必须因子化

建议使用独立的`ViewStateSnapshot`，至少包含：

```text
ViewStateSnapshot
├── body_yaw
├── camera_world_yaw
├── camera_relative_yaw
├── camera_pitch
├── camera_fov_or_zoom
├── camera_mode
├── target_screen_relation
├── control_context
├── frame_id
├── focus_epoch
├── control_schema_epoch
└── evidence_confidence
```

各字段含义如下：

| 字段 | 含义 |
| --- | --- |
| `body_yaw` | 角色身体在世界中的水平朝向 |
| `camera_world_yaw` | 镜头在世界中的水平朝向 |
| `camera_relative_yaw` | 镜头相对角色身体的水平偏角 |
| `camera_pitch` | 镜头俯视或仰视状态 |
| `camera_fov_or_zoom` | 视野范围、镜头距离或瞄准倍率 |
| `camera_mode` | 自由视角、锁定、瞄准、载具、菜单光标等模式 |
| `target_screen_relation` | 目标框相对屏幕中心或目标区域的位置 |
| `control_context` | 当前角色、武器、形态、能力和输入配置 |

不能用一个`rotation`同时表达所有信息。

## 4. 身体朝向和镜头朝向必须分开

第三人称游戏中经常出现：

```text
角色身体朝北
镜头看向东边
```

只旋转镜头不一定改变身体朝向；角色移动和攻击又可能自动修正身体方向。因此至少需要分别观测：

```text
body_yaw
camera_world_yaw
camera_relative_yaw
```

在能够可靠取得身体方向和镜头相对方向时，可以使用：

```text
camera_world_yaw
= normalize(body_yaw + camera_relative_yaw)
```

但这个公式只有在游戏当前控制模式确实采用相对镜头关系时才有效。进入锁定、瞄准、载具或特殊技能模式后，关系可能变化，必须由`camera_mode`和`control_schema_epoch`使旧模型失效。

## 5. 方向观测的证据来源

### 5.1 小地图和罗盘

如果小地图同时存在角色箭头、镜头视野扇形和北向基准，可以分别估计：

```text
角色世界yaw
镜头世界yaw
镜头相对角色yaw
```

这是Whimbox水平视角控制最接近的现有参考。其优势是具有世界方向基准；不足是通常只能取得水平角，难以直接判断镜头俯仰。

### 5.2 目标检测框

当任务目标是指定对象时，可以通过YOLO、模板或跟踪器获得目标框：

```text
target_center = (target_x, target_y)
desired_center = (desired_x, desired_y)

screen_error = desired_center - target_center
```

系统只需要把`screen_error`逐渐缩小，不必先求出绝对`yaw/pitch`。

### 5.3 OCR和互动提示

互动文字、目标名称和提示图标能够证明视角已经满足某项业务条件。例如：

```text
目标对象身份正确
+ 互动提示文字正确
+ 提示连续稳定出现
= 当前视角满足互动条件
```

提示只能证明任务条件满足，不一定能反推出绝对角度。

### 5.4 稳定地标

已知建筑、道路、山体轮廓或场景标志可以作为局部方向锚点。地标记录需要绑定：

- `MapSpace`；
- 大致位置；
- 可见距离和角度范围；
- 昼夜、天气和游戏版本；
- 遮挡条件；
- 检测器和模板版本。

地标适合固定地点的重定位，不适合作为所有区域的通用方向传感器。

### 5.5 光流和局部视觉变化

系统可以发送一个很小的鼠标探测量，再测量画面真实运动：

```text
鼠标向右移动少量
-> 场景整体向左产生光流
-> 确认镜头正在向右旋转
-> 估算当前输入响应
```

光流适合判断相对变化方向和幅度，但没有北向或地标时，不能单独提供世界绝对方向。

### 5.6 画面几何

地平线、消失点、建筑垂直线和目标尺寸可以为`camera_pitch`、倾斜和距离提供弱证据。但复杂地形、镜头畸变、动态对象和不规则建筑会降低可靠性，因此它们更适合作为辅助证据，而不是唯一成功判定。

## 6. 单帧无法保证完整3D方向

以下画面可能缺少足够方向信息：

- 天空、海面、草地等低纹理区域；
- 大量重复墙面或走廊；
- 目标完全被遮挡；
- 镜头贴近角色或墙体；
- 过暗、过曝、粒子特效或运动模糊；
- 没有小地图、罗盘和稳定地标；
- 画面静止但截图实际是缓存旧帧。

这时系统不能声称方向已经确定。可选处理为：

```text
重新观察
-> 执行低风险微量探测
-> 调整站位取得更多纹理
-> 寻找地标或目标
-> 仍不可观测则返回UNKNOWN
```

## 7. 建立视角连续控制器

建议将视角调整实现为一种`ContinuousController`：

```text
ViewDirectionController
├── target_condition
├── view_observer
├── error_estimator
├── control_policy
├── calibration_profile_ref
├── action_chunk_limit
├── confidence_gate
├── stability_gate
├── timeout
├── no_progress_watchdog
├── oscillation_watchdog
├── recovery_policy
└── cleanup_actions
```

控制流程为：

```text
观察当前ViewStateSnapshot
-> 计算方向或屏幕误差
-> 选择匹配环境的CalibrationProfile
-> 生成有限鼠标位移
-> 提交输入
-> 等待新鲜稳定帧
-> 测量实际响应
-> 更新误差和校准残差
-> 继续、重校准、恢复或结束
```

控制器是`CapabilitySpec`的一种执行类型，不是另一套关系图节点。

## 8. 控制量不能一次发送完

建议根据误差动态限制单次动作：

```text
误差较大
-> 使用较大但有上限的鼠标位移

接近目标
-> 自动减小动作量

进入容差
-> 停止输入并连续验证
```

这样可以降低过冲、目标丢失和视角来回振荡。

一个简单控制形式可以表示为：

```text
mouse_dx = clamp(kx * yaw_or_screen_error_x, -max_dx, max_dx)
mouse_dy = clamp(ky * pitch_or_screen_error_y, -max_dy, max_dy)
```

其中`kx`和`ky`不能永久写死，需要由当前环境的校准和执行反馈修正。

## 9. 水平和垂直控制分别建模

水平镜头通常具有环形角度：

```text
0° == 360°
```

误差需要使用最短角距离：

```text
yaw_error = shortest_angle(target_yaw - current_yaw)
```

垂直镜头通常具有上下边界，并可能存在非线性响应：

```text
pitch_min <= camera_pitch <= pitch_max
```

因此水平和垂直控制不能简单共用一个比例。垂直方向没有绝对角度传感器时，可以先使用：

- 目标框垂直误差；
- 地平线位置；
- 离散俯视、平视、仰视等级；
- 相对鼠标偏移和历史成功姿态。

## 10. 建立环境化校准

可以在低风险场景执行小幅探测：

```text
发送dx=20
-> 实际yaw变化3.2°

发送dy=20
-> 目标垂直位置变化45px
```

据此建立`CalibrationProfile`：

```text
CalibrationProfile
├── game_version
├── window_size
├── dpi_scale
├── mouse_sensitivity
├── camera_mode
├── fov_or_zoom
├── character_or_vehicle_context
├── input_backend
├── observer_revision
├── horizontal_response_model
├── vertical_response_model
├── sample_count
├── residual_statistics
└── valid_environment_fingerprint
```

校准结果属于环境运行资产，不直接写入`ViewDirectionController`定义。

## 11. 校准失效条件

以下变化应使旧校准降级或失效：

- 用户修改鼠标灵敏度；
- 分辨率、DPI或窗口尺寸变化；
- FOV、缩放或瞄准倍率变化；
- 角色、载具、武器或能力模式切换；
- 游戏补丁修改镜头响应；
- 输入后端变化；
- 鼠标加速或原始输入模式变化；
- 实际响应持续偏离预测；
- 镜头进入边界或吸附状态；
- `control_schema_epoch`变化。

校准失效只表示当前控制参数不可继续使用，不代表“旋转镜头”这个能力关系本身错误。

## 12. 视角完成条件

视角完成不能以“鼠标已经移动”为依据。至少需要：

```text
方向误差或目标屏幕误差小于容差
+ 连续2至3帧结果稳定
+ 目标身份仍然正确
+ camera_mode没有变化
+ frame_id为输入后的新鲜帧
+ focus_epoch仍然有效
+ control_schema_epoch仍然匹配
```

绝对方向任务可以使用角度容差：

```text
abs(yaw_error) <= yaw_tolerance
```

目标对准任务可以使用屏幕区域容差：

```text
target_center inside desired_screen_region
```

互动任务还需要业务后置条件，不能只确认目标已经居中。

## 13. 输入所有权是闭环的一部分

视角控制使用系统级鼠标时，必须经过：

```text
取得game_control:<window_instance_id>
-> 取得desktop_physical_input
-> WindowRegistry确认窗口实例和代次
-> FocusBroker生成FocusLease和focus_epoch
-> 输入前检查目标窗口
-> 提交有限鼠标输入
-> InputOwnershipVerifier检查视觉响应归属
-> 后置验证完成
-> 释放资源和残留输入
```

目标窗口成为前台只是必要条件，不能证明鼠标输入一定被目标游戏消费。如果其他窗口产生符合输入的视觉响应，应立即使旧`focus_epoch`失效。

## 14. 无推进和振荡检测

视角控制需要同时检查：

- 鼠标有输入但画面没有响应；
- 画面向相反方向变化；
- 误差长期不下降；
- 左右动作反复交替；
- 目标在屏幕两侧来回越过；
- 目标持续丢失和重新出现；
- 角度估计发生不可能跳变；
- 控制动作达到总次数或总耗时预算。

例如：

```text
右转 -> 目标越过中心
左转 -> 目标再次越过中心
右转 -> 重复发生
```

这说明控制增益、延迟或观测存在问题。系统应停止、冻结证据并重校准，而不是无限继续左右旋转。

## 15. 目标丢失后的受限搜索

目标暂时离开视野时，可以在历史方向附近执行有限搜索：

```text
0°
-> +5°
-> -5°
-> +10°
-> -10°
```

搜索范围、动作次数和总耗时必须有上限。每次动作后重新检测目标身份，不能只寻找任意相似物体或通用互动图标。

以下情况应直接停止自动搜索：

- 目标身份存在多个高相似候选；
- 附近有高风险可互动对象；
- 镜头已经进入不明控制模式；
- 角色或能力上下文变化；
- 物理输入焦点不可靠；
- 搜索可能触发攻击、购买或其他不可逆动作。

## 16. 视角异常与恢复

以下异常需要与普通方向误差分开：

- 游戏失去鼠标锁定；
- 其他窗口抢走鼠标；
- 视角输入完全无效；
- 鼠标进入菜单光标模式；
- 游戏内镜头Bug导致自由移动异常；
- 角色进入特殊动作、过场或载具；
- 小地图方向识别失效；
- 截图链路返回黑帧或旧帧。

恢复顺序可以是：

```text
停止当前输入并释放鼠标
-> 重新观察窗口、画面和camera_mode
-> 重新取得FocusLease
-> 尝试切换或重置游戏内部视角模式
-> 回到已知菜单再返回游戏
-> 使用传送或场景重载
-> 重新进入游戏
-> 仍失败则请求用户
```

每个恢复动作必须创建独立`RecoveryRun`。恢复成功只表示系统重新获得可控状态，不能覆盖原`StepAttempt`的`FAILED`、`UNKNOWN`或`BLOCKED`。

## 17. 公共执行结果

视角控制最终使用公共结果：

```text
ExecutionOutcome = SUCCEEDED / FAILED / UNKNOWN / CANCELLED / BLOCKED
```

视角模块内部的`TARGET_LOST`、`NO_RESPONSE`、`OSCILLATION_DETECTED`和`CALIBRATION_INVALID`只作为`reason_code`。

完整结果为：

```text
ExecutionOutcome
+ reason_code
+ FailureAttribution
+ SampleDisposition
+ professional_payload: ViewDirectionAttemptPayload
```

其中：

- 输入前确定当前模式不可控制且没有发送业务输入，可返回`BLOCKED`；
- 输入已经发出但后置方向无法确认，应返回`UNKNOWN`；
- 有新鲜可靠证据证明有限控制后仍未达到目标，才返回`FAILED`；
- 达到方向容差后仍需通过任务后置验证，才能返回`SUCCEEDED`。

## 18. 执行证据

一次视角Attempt至少保存：

```text
ViewDirectionAttemptPayload
├── target_type
├── target_direction_or_screen_region
├── initial_view_state
├── final_view_state
├── observation_sequence
├── requested_mouse_deltas
├── measured_visual_responses
├── calibration_profile_revision
├── calibration_residuals
├── target_identity_evidence
├── camera_mode_sequence
├── window_instance_id
├── focus_epoch
├── control_schema_epoch
├── no_progress_and_oscillation_events
└── cleanup_result
```

这些字段作为公共`StepAttempt.professional_payload`保存。`ExecutionOutcome`、故障归因、样本处置和证据包引用仍由公共运行协议管理。

## 19. 与关系网的结合

关系网不保存“向右移动鼠标300像素”作为稳定状态边，而应引用能力：

```text
TransitionDefinition
-> capability_ref: ViewDirectionController
-> target_condition: 世界yaw或目标屏幕区域
-> postcondition: 方向稳定且业务条件成立
```

互动姿态、路线和战斗能力可以复用同一个控制器，但传入不同目标条件和风险策略。

`ViewStateSnapshot`属于因子化运行状态，不需要把每个角度都建立成离散`StateDefinition`节点。关系图只保存有业务意义的状态和转换，连续角度由控制器内部处理。

## 20. 第一阶段验证计划

建议按以下顺序测试：

1. 固定截图验证小地图身体方向识别；
2. 固定截图验证镜头视野扇形方向；
3. 原地执行单次小幅水平探测；
4. 建立水平`CalibrationProfile`；
5. 验证转向指定绝对yaw；
6. 使用目标框验证水平居中；
7. 使用目标框验证垂直居中；
8. 注入灵敏度、DPI、FOV变化，验证校准失效；
9. 注入低纹理、遮挡和目标丢失，验证`UNKNOWN`；
10. 注入左右振荡，验证看门狗停止；
11. 双窗口抢焦点，验证输入归属和旧epoch失效；
12. 手动停止，验证鼠标和按键全部释放；
13. 最后接入互动提示和业务后置验证。

每项实验至少统计：

- 初始角度误差；
- 最终角度或屏幕误差；
- 达到目标需要的控制周期；
- 过冲次数；
- 目标丢失率；
- `UNKNOWN`比例；
- 错误窗口响应次数；
- P50/P95控制耗时；
- 校准残差；
- 停止和清理完整性。

## 21. 第一阶段边界

第一阶段可以只支持：

- 单个游戏；
- 单个角色和普通自由视角；
- 水平世界yaw；
- 指定目标框水平居中；
- 小范围垂直目标调整；
- 有限次数受控搜索；
- 手动停止和输入清理。

暂不处理：

- 通用6DoF相机姿态恢复；
- 没有任何视觉基准时的绝对方向；
- 高速战斗跟踪；
- 复杂锁定目标切换；
- 载具和飞行的完整镜头模型；
- 仅凭单帧推断任意场景的绝对`yaw/pitch`；
- 无限360°盲目搜索。

## 22. 总结

3D场景中的视角方向保证应理解为：

```text
身体方向、镜头yaw、pitch、FOV和控制模式分开建模
-> 使用小地图、罗盘、目标框、互动提示、地标和光流提供证据
-> ContinuousController根据误差发送有限输入
-> CalibrationProfile描述当前环境的输入响应
-> 每次输入后用新鲜稳定画面验证真实变化
-> 通过双epoch和输入归属确认控制目标
-> 无推进、振荡或不可观测时停止
-> 异常恢复使用独立RecoveryRun
```

最终原则是：

> 鼠标移动只表示一次控制尝试；只有方向或任务后置条件被新鲜视觉证据确认，系统才能宣布视角控制成功。绝对方向无法观测时，应退化为任务相对方向或明确返回`UNKNOWN`。
