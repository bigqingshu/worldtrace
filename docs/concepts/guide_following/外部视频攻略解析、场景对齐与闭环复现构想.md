## 1. 核心目标

当系统已经熟悉一个游戏的场景、界面、移动方式和交互能力后，可以读取用户提供或合法访问的视频攻略，提取：

- 攻略目标；
- 起点和终点；
- 路线和关键地标；
- 需要执行的操作；
- 角色、能力和任务前置条件；
- 作者提示的危险、分支和恢复方式；
- 每一步在视频中的来源证据。

再将攻略候选映射到系统已经验证的状态、地点和`CapabilitySpec`，生成供用户审核的计划。

## 2. 视频不是可直接执行的宏

不能把视频中的鼠标移动、按键持续时间和人物屏幕位置直接重放到当前游戏。

视频可能存在：

- 剪辑和跳切；
- 加速、减速和停顿删除；
- 隐藏HUD或裁剪画面；
- 第一人称和第三人称差异；
- 不同角色、装备和移动能力；
- 不同游戏版本、地图和任务阶段；
- 作者使用系统尚未学习的技巧；
- 随机敌人、天气和事件；
- 不同分辨率、FOV、画质和镜头设置；
- 作者在录制前已经完成部分前置步骤。

核心原则是：

> 视频提供路线、意图、地标和操作候选，不提供可信的实时控制量。

## 3. 总体流程

```text
外部视频或攻略来源
-> 来源登记和版本判断
-> 字幕、语音、OCR和关键帧提取
-> 剪辑、场景和步骤切分
-> 地点、路线和操作候选
-> 与程序地点及能力库对齐
-> GuidePlanCandidate
-> 用户审核
-> 确定性编译
-> 当前游戏状态下闭环执行
-> 逐步验证、恢复和重新定位
```

## 4. 来源和合法访问边界

系统只处理：

- 用户主动提供的本地视频；
- 用户明确授权访问的公开链接；
- 平台允许下载、缓存或分析的内容；
- 用户已经合法获得的字幕、截图和攻略文本。

系统不应绕过登录、付费、访问限制、数字版权保护或平台技术措施。

长期保存时优先保存来源URL、时间戳、结构化步骤和必要证据引用，不默认永久复制整段外部视频。

```text
VideoGuideArtifact
├── guide_artifact_id
├── source_type
├── source_url_or_local_ref
├── title
├── publisher_or_author
├── published_at
├── accessed_at
├── expected_game_profile_id
├── expected_game_version
├── language
├── duration
├── transcript_ref
├── subtitle_track_refs
├── keyframe_refs
├── scene_segment_refs
├── edit_cut_refs

```

`expected_game_version`允许为`UNKNOWN`，但未知版本的攻略不能直接视为适用于当前游戏。

## 6. 原始和派生攻略数据

```text
GuideRawArtifact
-> 用户提供的视频、字幕、音轨和来源元数据

GuideDerivedArtifact
-> ASR文本、OCR、关键帧、场景描述器、步骤和路线候选
```

派生数据必须记录所使用的模型、参数和输入版本，以便以后重新解析。

## 7. 多模态信息来源

### 7.1 字幕和语音

用于提取：

- 地点名称；
- 操作指令；
- 前置条件；
- 危险提醒；
- 物品和奖励；
- 作者解释的路线原因。

### 7.2 游戏画面OCR

用于提取：

- 地图和区域名；
- 任务目标；
- 交互提示；
- 角色和队伍；
- 物品和数量；
- 页面或活动名称。

### 7.3 关键帧和场景描述器

用于记录：

- 地标和建筑；
- 小地图形状；
- 入口、出口和岔路；
- 镜头朝向；
- 特殊机关；
- 战斗或加载前后场景。

### 7.4 时间和剪辑结构

用于识别：

- 连续真实移动；
- 跳切；
- 加速片段；
- 重复演示；
- 回放或插入讲解；
- 路线以外的编辑内容。

## 8. 剪辑和时间失真

```text
GuideEditEvent

├── source_timestamp
├── before_segment_ref
├── after_segment_ref
```

`event_type`可以是：


出现剪辑时，视频时间不能用于推断真实移动时长和按键持续量。

## 11. 操作意图与控制量分离

视频可以支持：

```text
朝门口移动
向左侧岔路转向
跳到下一平台
打开地图并传送
与机关交互
```

视频不能直接提供当前运行所需的：

```text
鼠标移动17像素
按住W 2.3秒
点击桌面坐标(1321, 742)
```

控制量必须由当前游戏Profile、窗口、视角、人物运动状态和已验证控制器实时计算。

## 12. 地点和路线候选

```text
GuideRouteCandidate
├── route_candidate_id
├── ordered_place_candidates
├── traversal_candidate_refs
├── branch_candidates
├── landmark_sequence
├── irreversible_edges
├── expected_duration_range
├── required_capabilities
└── source_evidence_refs
```

攻略路线进入的是候选空间拓扑，不能因为视频看似连续就直接建立永久地图边。

## 13. 当前场景与攻略对齐

执行前需要回答：

```text
当前游戏位于攻略的哪个片段
当前面向哪个方向
已经完成哪些前置步骤
当前角色是否具备相同能力
当前版本和攻略是否兼容
```

```text
GuideAlignment
├── guide_artifact_id
├── current_state_snapshot_ref
├── candidate_segment_ids
├── place_alignment_candidates
├── orientation_alignment
├── progress_alignment
├── context_differences
├── ambiguity
├── confidence_components
└── evidence_refs
```

对齐不充分时不能从视频开头盲目重放。

## 14. 场景对齐证据

可以组合：

- 地图或区域名称；
- 小地图局部形状；
- 地标和建筑序列；
- 前一个和后一个地点；
- 入口和出口方向；
- 任务或机关进度；
- 多视角场景描述器；
- 用户指定“从视频这里开始”。

场景外观相似但路线历史不一致时，应保留多个位置假设。

## 15. 能力绑定

```text
GuideCapabilityBinding
├── guide_step_id
├── capability_spec_candidates
├── required_context
├── parameter_mapping
├── validation_status
├── missing_capabilities
└── evidence_refs
```

只能将攻略步骤绑定到：

- 已存在并经过验证的`CapabilitySpec`；
- 已知输入和结果契约；
- 当前游戏、角色和场景允许的版本。

攻略出现系统未知操作时，结果应为：

```text
UNRESOLVED_CAPABILITY
-> 请求用户解释或示范
-> 单独进入能力学习流程
```

不能让AI临时生成未经验证的键鼠脚本补齐。

## 16. `GuidePlanCandidate`

```text
GuidePlanCandidate
├── guide_plan_id
├── guide_artifact_ref
├── selected_goal
├── start_alignment_ref
├── ordered_guide_steps
├── capability_bindings
├── unresolved_steps
├── prerequisites
├── expected_route
├── risks
├── assumptions
├── source_refs
└── review_status
```

攻略计划不是活动执行计划，必须先完成用户和确定性审核。

## 17. 用户审核

用户需要看到：

- 攻略来源和游戏版本；
- 系统认为的起点；
- 每一步映射到什么能力；
- 哪些步骤仍然不确定；
- 哪些步骤可能消耗资源；
- 是否包含战斗、不可逆路线或高风险跳跃；
- 与当前角色和任务状态的差异；
- 计划使用的规则、地图和控制器版本。

用户修改后产生新的计划版本，旧审核和批准失效。

## 18. 编译执行

```text
GuidePlanCandidate
-> 确定性前置检查
-> 用户批准
-> AbstractPlan
-> RuleCompiler
-> ExecutablePlan
```

编译结果固定：

```text
state_rule_versions
place_and_route_versions
capability_versions
detector_versions
calibration_versions
recovery_policy_versions
guide_source_revision
```

## 19. 闭环执行而不是视频同步

执行循环：

```text
定位当前状态和地点
-> 选择下一攻略步骤
-> 执行已验证能力
-> 观察当前游戏实际结果
-> 验证后置条件
-> 更新攻略进度
-> 必要时重新对齐
```

视频不会在后台作为严格时间轴驱动输入。当前游戏事实始终优先于攻略时间戳。

## 20. 攻略进度

```text
GuideExecutionProgress
├── guide_plan_id与version
├── current_step_id
├── completed_step_ids
├── skipped_step_ids
├── unresolved_step_ids
├── current_alignment_ref
├── current_place_candidates
├── deviation_events
└── evidence_refs
```

攻略进度和游戏任务事实分开保存，不能因为视频走到某处就假设当前游戏也完成了对应任务。

## 21. 偏离攻略

```text
GuideDeviation

├── expected_state_or_place
├── observed_state_or_place
├── affected_step_id
├── possible_causes
├── recovery_candidates
├── severity
└── evidence_refs
```

可能的偏离：

```text
WRONG_PLACE

MISSING_PREREQUISITE
GAME_VERSION_MISMATCH
UNEXPECTED_ENEMY_OR_EVENT
CAPABILITY_UNAVAILABLE
ROUTE_BLOCKED
GUIDE_EDIT_GAP
LOCALIZATION_AMBIGUOUS
UNKNOWN
```

## 22. 恢复策略

恢复优先级：

```text
停止当前输入
-> 重新观察和定位
-> 回到最近已确认地标
-> 在攻略相邻片段中重新对齐
-> 使用已知替代路线
-> 请求用户确认或接管
```

不能为了重新追上攻略而无界搜索或连续盲走。

## 23. 战斗、随机事件和动态世界

视频中的敌人、天气和事件可能与当前运行不同。

攻略步骤应表达目标：

```text
清除阻挡敌人
等待机关可用
到达出口
获得任务物品
```

具体执行由当前状态和能力库决定。没有已验证战斗能力时，攻略运行应暂停并请求用户接管。

## 24. 角色和能力差异

```text
GuideCharacterContext
├── character_candidates
├── movement_capabilities
├── jump_or_flight_capabilities
├── required_equipment
├── stamina_or_resource_assumptions
└── special_shortcuts
```

作者使用高跳、飞行、钩索或角色专属能力时，系统必须检查当前角色能否满足。不能把视频中的路径自动视为通用可通行边。

## 25. 游戏版本和攻略失效

攻略可能因更新失效：

- 地图或入口改变；
- 任务条件改变；
- 角色能力调整；
- UI和按钮改变；
- 物品刷新和奖励改变；
- Bug或捷径被修复。

```text
GuideCompatibilityStatus
-> UNKNOWN / COMPATIBLE / PARTIALLY_COMPATIBLE / STALE / INCOMPATIBLE
```

发现多个结构性偏差时，应停止并将攻略标记为待重新审核。

## 26. AI的职责

AI可以：

- 处理字幕、语音和画面摘要；
- 提取地点和操作候选；
- 解释作者意图；
- 建议步骤切分；
- 比较攻略与当前程序知识；
- 提出缺失能力和用户问题；
- 解释偏离原因。

AI不能：

- 直接修改地图、规则或能力库；
- 把视频鼠标轨迹变成活动输入；
- 跳过场景对齐；
- 自动批准资源消耗和高风险步骤；
- 在未知能力处生成任意脚本；
- 把视频内容写入AI聊天记忆充当程序事实。

## 27. 攻略数据和AI记忆分离

攻略来源、关键帧、步骤、对齐和执行记录属于程序管理的数据：

```text
GuideArtifactStore
GuidePlanStore
GuideExecutionStore
```

AI通过只读查询获得所需片段。更换模型、清空聊天或重建Agent记忆后，攻略数据仍然存在。

`GuideExecutionStore`只保存攻略领域索引和投影视图，并引用通用`RunStore`中的`PlanRun`、`StepAttempt`和恢复记录，不能另建一份互相冲突的执行结果。

AI分析结果保存为带来源的`AnalysisArtifact`或候选，不覆盖攻略原始证据。

## 28. 与关系网的边界

攻略可以产生：

```text
PlaceCandidate
TraversalHypothesis
CapabilityBindingCandidate
GuidePlanCandidate
```

但不能直接产生：

```text
ACTIVE StateDefinition
ACTIVE TransitionDefinition
已验证空间边
已验证CapabilitySpec
```

候选仍需要通过正常实验和规则生命周期。

## 29. 与Trace Core的关系

Trace Core提供：

- 当前游戏连续帧；
- 用户和系统输入；
- 窗口和时间线；
- 执行前后证据；
- 攻略复现过程的离线回放。

它不负责下载视频、理解攻略或决定路线。

## 30. 实现前置条件

进入视频攻略实现前，至少需要：

- 一个游戏Profile稳定；
- 具备地点或场景候选定位；
- 具备视角和人物运动观测；
- 至少一个可靠UI执行闭环；
- 一组经过验证的移动与交互能力；
- 计划编译和用户批准机制；
- 程序事实与AI记忆完成隔离；
- 可以保存和回放完整运行证据。

## 31. 分阶段验证

### 阶段一：纯文本攻略

从带明确步骤的文本攻略中提取`GuideStepCandidate`，不处理视频。

### 阶段二：有字幕的短视频

选择一个无剪辑或少剪辑、只有一个安全UI操作的短片，提取字幕、关键帧和步骤。

### 阶段三：地点对齐

选择两个已知地点，验证当前游戏画面能否对齐到攻略片段，不执行移动。

### 阶段四：单个已知能力

将攻略中的一个步骤绑定到已验证UI能力，用户审核后执行并验证。

### 阶段五：短路线

选择一个安全、无战斗、无随机分支的短路线，逐地标闭环复现。

### 阶段六：剪辑和偏离

加入一次跳切、一次路线偏离和一次重新定位。

### 阶段七：复杂攻略

最后考虑3D移动、战斗、角色差异和随机事件。

## 32. 第一版验收标准

- 视频控制量不会被直接重放；
- 每个步骤保留来源时间戳和证据；
- 剪辑、加速和不连续片段能够标记；
- 当前游戏与攻略片段可以保留多个对齐候选；
- 只有已验证能力才能编译执行；
- 未知步骤会请求用户解释或示范；
- 用户可以审核和修改攻略计划；
- 执行依据当前游戏事实而不是视频时钟；
- 偏离攻略时停止、重新定位或请求接管；
- 游戏版本和角色差异会影响兼容状态；
- 攻略数据保存在程序存储，不依赖AI聊天记忆；
- 清空AI记忆后仍能复现既有攻略计划和运行记录。

## 33. 当前结论

视频网站攻略可以成为界迹后期的重要外部知识源，但它的正确作用是：

```text
视频攻略
-> 路线、地标、意图和步骤候选
-> 与程序已有地点和能力对齐
-> 用户审核的计划
-> 当前游戏中的闭环执行
```

它不是录制宏，也不是让AI看着视频实时按键。只有当系统已经拥有可靠场景定位、能力库、规则编译、用户批准和证据回放后，视频攻略复现才具有可控的实现路径。
