## 1. 核心结论

人物移动时出现的FOV变化、画面拉伸、径向模糊、速度线、镜头拉远、背景光流和动画频率，都可以作为速度与移动模式的视觉线索。

但这些表现主要服务于游戏观感，可能与真实人物平移速度解耦。因此它们应被记录为`VisualMotionCue`（视觉运动线索），与静态场景运动、相对深度、人物脚点和输入时序共同判断，不能单独作为速度真值。

跳跃能力也不应只保存一个“最大跳跃距离”。更合适的是建立条件化`JumpResponseProfile`（跳跃响应画像）：

```text
人物移动状态
+ 移动方位
+ 起跳前速度阶段
+ 空格按下和释放时序
+ 裂隙与落脚平台几何
+ 相机和角色上下文
-> 预测腾空时间、落地区间和成功概率
```

每次实际跳跃再通过起跳、最高点、落地、滑落和失败原因更新画像，形成闭环。

第一版分析窗口的目标不是自动控制全部跳跃，而是让开发者能够在实时画面或离线回放中看见：

```text
系统认为人物往哪里移动
系统认为速度处于什么阶段
人物是否接地或腾空
空格实际按住了多久
什么时候发生视觉起跳和落地
当前预测落点在哪里
判断使用了哪些证据以及是否稳定
```

## 2. 画面变形可以作为速度线索

### 2.1 候选视觉表现

游戏可能使用以下效果表达速度感：

- FOV随奔跑或冲刺增大；
- 画面边缘向外拉伸；
- 径向模糊或运动模糊增强；
- 屏幕出现速度线；
- 第三人称摄像机向后拉远；
- 摄像机跟随人物时产生滞后；
- 第一人称走路晃动频率提高；
- 人物跑步动画播放更快；
- 衣物、拖尾和粒子效果发生变化；
- 近处地面特征向后或向画面外侧移动更快；
- 远处背景变化相对较慢。

这些线索可以帮助区分：

```text
静止
缓慢移动
加速
普通巡航
冲刺
减速
特殊高速状态
UNKNOWN
```

### 2.2 画面效果不等于人物实际速度

以下情况会破坏直接关系：

- 人物撞墙后仍短暂保留冲刺FOV；
- 镜头快速旋转产生运动模糊；
- 剧情或技能主动改变FOV；
- 摄像机碰撞墙体后突然拉近；
- 画质设置关闭或降低运动模糊；
- 角色站在移动平台上；
- 网络延迟使动画与位置更新不同步；
- 特殊区域永久使用速度线或镜头畸变；
- 人物输入向前但被地形或状态阻止。

因此应区分：

```text
movement_intent
-> 系统请求的人物移动方向

visual_motion_effect
-> 游戏表现出来的速度效果

observed_character_motion
-> 由人物脚点和静态场景验证的实际运动

camera_motion
-> 摄像机自身的平移、旋转和缩放
```

这些来源可以互相支持，但不能互相覆盖。

### 2.3 视觉运动线索的候选内容

`VisualMotionCue`可以暂时记录：

```text
frame_id
timestamp
cue_type
screen_region
direction
magnitude
camera_mode
graphics_profile
source_revision
stability
reliability
```

这些字段只是实验候选。特别需要记录画质、FOV和相机模式，因为视觉速度效果可能随设置改变。

## 3. 从连续画面估计人物方向与速度阶段

### 3.1 场景参考物向后变化的含义

人物向前移动时，静态场景参考点通常相对相机向后移动。近处物体视差较大，远处物体视差较小，这是判断自运动的重要线索。

但画面运动应先分解：

```text
连续帧
+ 相对或度量深度
+ 人物、武器、HUD和动态对象遮罩
+ 输入上下文
-> 跟踪静态场景参考点
-> 估计镜头yaw、pitch、roll和FOV变化
-> 扣除旋转与缩放产生的运动
-> 分析剩余平移光流和深度关系
-> 输出人物运动方向与速度阶段候选
```

输入方向只提供先验。例如按住向右键不能证明人物已经向右移动，视觉响应才负责确认实际运动。

### 3.2 方向必须说明坐标系

分析窗口不能只显示一个含义不明的“向左”或“向右”。至少区分：

| 方向 | 含义 |
| --- | --- |
| 请求输入方向 | 键鼠希望人物如何移动 |
| 屏幕观察方向 | 人物或脚点在屏幕上的变化方向 |
| 相对镜头方向 | 人物相对当前镜头向左、右、前或后移动 |
| 摄像机运动方向 | 镜头自身平移或旋转方向 |
| 世界方向 | 具有地图、罗盘或地标基准时的可选方向 |

第三人称人物保持在画面中心时，屏幕观察方向可能接近零，但人物相对世界仍在高速移动。因此方向必须结合背景和地面参考点。

### 3.3 速度先输出阶段和等级

早期不要求立即恢复米制速度。候选`MotionState`（人物运动状态）可以输出：

```text
motion_direction
speed_phase = STOPPED / ACCELERATING / CRUISING / DECELERATING / UNKNOWN
speed_band = SLOW / MEDIUM / FAST / SPECIAL / UNKNOWN
ground_contact_state
camera_motion_state
visual_effect_state
time_to_edge
evidence_stability
```

分析窗口可以同时展示：

```text
像素光流速度
相对速度指数
速度阶段
速度等级
可选标定速度
```

没有可靠标定时，不能把相对速度指数显示为米每秒。

### 3.4 第一人称速度

普通第一人称相机通常随人物平移，因此静态背景光流较接近人物运动。仍需过滤：

- 鼠标转向；
- 走路、呼吸和受击晃动；
- 武器动画和后坐力；
- 瞄准缩放；
- 脚本镜头；
- 移动平台和载具。

第一人称使用相机作为运动跟踪锚点，但人物落脚点仍位于相机下方。起跳、下蹲和相机高度动画不能直接解释为地形变化。

### 3.5 第三人称速度

第三人称需要组合：

```text
人物脚点相对附近地面参考点的变化
+ 静态背景光流
+ 摄像机跟随滞后
+ 人物动画频率
+ 相对深度变化
+ 输入持续时间
```

摄像机速度不能直接等同于人物速度。冲刺拉远、镜头回弹、锁定目标和镜头碰撞都可能使二者不同。

## 4. 跳跃输入时序必须单独记录

### 4.1 空格按住时长可能改变跳跃

不同游戏可能采用：

- 按下时触发固定跳跃；
- 按住越久，上升阶段越长；
- 松开后提前增加下落速度，形成短跳；
- 按住进行蓄力，释放后起跳；
- 奔跑速度只影响水平距离；
- 空中继续接受方向输入；
- 特殊能力提供二段跳、冲刺跳或抓边；
- 特殊地面、增益或场景改变重力和跳跃高度。

系统不能预先假设某一种机制。应通过受控实验判断当前游戏和当前`MovementContext`（移动上下文）采用什么响应。

### 4.2 输入时间与视觉事件不是同一时刻

至少记录：

```text
space_down_time
space_up_time
takeoff_time
apex_time
landing_contact_time
stable_landing_time
```

可计算：

```text
input_hold_duration
= space_up_time - space_down_time

takeoff_latency
= takeoff_time - space_down_time

air_time
= landing_contact_time - takeoff_time

stable_landing_delay
= stable_landing_time - landing_contact_time

ascent_time
= apex_time - takeoff_time
```

空格按下不等于立即起跳。动画前摇、输入缓冲、土狼时间、蓄力和网络延迟都可能产生偏移。

按键持续时间也不等于有效上升控制时间。例如角色在起跳前已经按住空格一段时间，真正影响空中阶段的可能只是起跳后仍保持按下的部分。因此必须保留原始按下、释放和视觉事件时间，不要只保存一个派生时长。

## 5. 跳跃阶段与事件识别

### 5.1 候选跳跃状态

可以使用`JumpPhase`（跳跃阶段）描述：

```text
GROUNDED
APPROACHING_EDGE
JUMP_REQUESTED
TAKEOFF
ASCENDING
APEX
DESCENDING
LANDING_CONTACT
STABLE_LANDING
SLIPPING_OR_FALLING
FAILED_OR_INTERRUPTED
UNKNOWN
```

状态不能只由键盘事件切换。例如收到空格按下后，若人物仍在地面且没有上升证据，应保持`JUMP_REQUESTED`或进入失败状态，而不是直接宣布`TAKEOFF`。

### 5.2 第三人称阶段证据

第三人称可以组合：

- 脚部离开当前承载表面；
- 人物脚点相对静态背景向上变化；
- 人物动画从跑步切换为起跳；
- 人物与地面深度关系改变；
- 上升速度减小并改变符号；
- 脚部与远侧平台重新接触；
- 落地动画和地面运动恢复。

摄像机跟随可能使人物继续保持在相似屏幕高度，因此需要相对背景和落脚平台跟踪。

### 5.3 第一人称阶段证据

第一人称可以组合：

- 推断相机高度相对地面变化；
- 地平线和静态背景的垂直运动；
- 地面光流暂时减弱或改变；
- 跳跃、落地声音的可选证据；
- 输入响应和历史跳跃时序；
- 落地后相机振动和地面运动恢复。

第一人称镜头动画可能主动模拟跳跃感，因此仍需与静态场景和多帧轨迹共同判断。

## 6. 建立经验化跳跃响应画像

### 6.1 不先假设完整物理公式

理想抛体运动可以提供解释：

```text
水平距离约等于腾空期间水平速度的积分
```

但游戏可能使用：

- 分段或非真实重力；
- 松键后增加重力；
- 动画根运动；
- 空中加速和转向；
- 自动吸附落脚点；
- 抓边和翻越；
- 服务器位置修正；
- 特殊表面弹跳。

因此物理公式只作为候选解释和异常检查，主模型优先使用实际游戏响应。

### 6.2 JumpResponseProfile候选输入

```text
game_version
character_or_form
movement_context
camera_mode
control_schema_revision
visual_model_revision
takeoff_speed_phase
takeoff_speed_band
takeoff_direction
approach_angle
input_hold_duration
effective_hold_after_takeoff
air_control_sequence
relative_gap_span
relative_landing_height
landing_region_size
takeoff_surface_slope
landing_surface_slope
```

### 6.3 JumpResponseProfile候选输出

```text
takeoff_probability
expected_takeoff_latency
expected_air_time_range
expected_ascent_time_range
expected_horizontal_displacement_range
expected_landing_region
success_probability
failure_mode_distribution
uncertainty
supporting_sample_count
valid_environment_fingerprint
```

输出应以范围和概率为主，而不是过早给出单个精确落点。

### 6.4 腾空时间不能单独决定水平距离

相同腾空时间可能对应：

- 原地高跳；
- 高速向前跳；
- 低速向前跳；
- 空中被墙面阻挡；
- 从高处跳向低处；
- 从低处跳向高处；
- 特殊模式下的低重力运动。

因此至少需要联合：

```text
起跳前水平速度
+ 空中方向输入
+ 相对落脚高度
+ 腾空时间
+ 场景参考物相对运动
```

第三人称可以跟踪人物脚点相对起跳边缘和落脚平台的变化；第一人称可以跟踪场景参考点和推断相机轨迹。屏幕像素位移不能直接当作世界水平距离。

## 7. 日常跳跃实验与特殊模式隔离

### 7.1 普通跳跃基线

建议在安全、平坦、可重复的位置按以下顺序测试：

1. 原地轻点空格；
2. 原地短按、中按和长按；
3. 以缓慢、加速中、稳定奔跑和冲刺状态起跳；
4. 在同高度落脚面上比较水平位移；
5. 在较低和较高落脚面上重复；
6. 加入不同起跳方向和空中方向输入；
7. 重复多次测量随机性和输入延迟。

每组实验需要保留成功与失败样本，不能只保存平均值。

### 7.2 按键时长分桶

第一轮可以使用简单分桶：

```text
TAP
SHORT_HOLD
MEDIUM_HOLD
LONG_HOLD
```

分桶边界由游戏实验确定，不预先固定毫秒值。如果各分桶的腾空时间和高度没有显著差异，说明当前模式可能是固定跳跃；如果存在连续或分段差异，再建立更细响应曲线。

### 7.3 特殊跳跃不能污染普通画像

以下样本应进入不同`MovementContext`或暂时标记为异常：

- 跳板和弹射装置；
- 低重力、水下或飞行区域；
- 角色增益、技能或装备强化；
- 二段跳、冲刺跳和墙跳；
- 移动平台；
- 斜坡边缘提供额外速度；
- 被攻击、爆炸或环境机关击飞；
- 过场或脚本移动。

如果腾空时间、最高点或水平位移明显超出普通分布，不应直接扩大普通跳跃能力边界。系统应先判断是否出现新模式、旧画像失效或观测错误。

## 8. 跳跃预测与学习闭环

### 8.1 预测前

```text
确认窗口、帧和相机模式
-> 确认人物落脚锚点
-> 观察移动方向与速度阶段
-> 识别近侧边缘和远侧落脚区域
-> 估计TimeToContact
-> 选择匹配的JumpResponseProfile
-> 生成落地区间与成功概率
```

### 8.2 执行中

```text
维持或调整接近速度
-> 根据TimeToContact选择起跳时机
-> 记录空格按下和释放
-> 观察视觉起跳是否发生
-> 连续更新跳跃阶段
-> 跟踪人物、相机、边缘和落脚区域
-> 必要时执行允许的空中方向控制
```

### 8.3 执行后

```text
检测第一次落地接触
-> 等待稳定落地
-> 判断是否滑落、卡住或继续坠落
-> 比较预测落地区间和实际结果
-> 计算时间与位置残差
-> 完成FailureAttribution
-> 决定样本能否更新画像
```

### 8.4 更新规则

可以用于更新的样本至少应满足：

- 输入时序完整；
- 起跳和落地事件可观测；
- 相机模式没有未知切换；
- 目标窗口和帧时间线可靠；
- 人物没有被外部攻击或脚本打断；
- 起跳与落脚表面候选稳定；
- 失败原因能够归因；
- 视觉模型和特征版本已记录。

`ExecutionOutcome`（执行结果）为成功不代表所有预测字段都正确。系统仍应保存预测与实际的残差。失败也不是天然训练样本，只有失败原因明确时才能更新相应边界。

## 9. 失败归因需要细分

跳跃失败至少可能分为：

```text
NO_TAKEOFF
TAKEOFF_TOO_EARLY
TAKEOFF_TOO_LATE
INSUFFICIENT_SPEED
INSUFFICIENT_VERTICAL_RESPONSE
DIRECTION_MISALIGNED
COLLIDED_WITH_OBSTACLE
LANDING_REGION_TOO_SMALL
LANDING_SURFACE_TOO_HIGH
OVERSHOT_LANDING
LANDED_THEN_SLIPPED
CAMERA_MODE_CHANGED
SPECIAL_MODE_UNDETECTED
OBSERVATION_UNRELIABLE
INTERRUPTED
UNKNOWN
```

这些只是专业原因候选，最终仍映射到公共`ExecutionOutcome`、`FailureAttribution`和`SampleDisposition`。

不同失败原因修正不同内容：

- 起跳过早或过晚主要修正起跳时机和`TimeToContact`；
- 速度不足修正接近阶段和速度画像；
- 垂直响应不足修正空格时长与跳跃响应；
- 方位偏差修正运动方向和视角控制；
- 落地后滑落修正稳定落地条件；
- 特殊模式未识别修正`MovementContext`门控；
- 观测不可靠不应更新跳跃能力画像。

## 10. 分析窗口构想

### 10.1 定位

候选`MotionAnalysisView`（运动分析视图）首先是实验调试工具，不是面向最终用户的生产界面。它应支持离线回放优先，随后再考虑实时模式。

主要用途为：

- 检查人物运动方向是否判断正确；
- 检查镜头运动是否被错误计入人物速度；
- 比较视觉速度线索与静态背景光流；
- 检查脚点、起跳、最高点和落地事件；
- 对齐键盘时间线与视觉时间线；
- 查看预测落点、实际落点和误差；
- 手工修正标签并保留修正依据；
- 对不同模型和参数运行同一段回放。

### 10.2 画面叠加层

主画面可以叠加：

- 人物遮罩和人物框；
- 人物脚点或第一人称推断落脚点；
- 静态场景特征轨迹；
- 背景光流箭头；
- 被排除的动态区域；
- 地面走廊；
- 近侧边缘和远侧平台；
- 预测移动方向向量；
- 预测落地区间；
- 实际落地点；
- 当前证据不可靠区域。

不同叠加层应可独立开关，避免所有信息同时显示造成遮挡。

### 10.3 运动状态区域

建议显示：

```text
requested_direction
observed_character_direction
camera_motion_direction
optional_world_direction
speed_phase
speed_band
relative_speed_index
optional_calibrated_speed
acceleration_trend
ground_contact_state
evidence_stability
```

每个值应同时显示来源和可信度。没有标定时不显示伪精确的米制速度。

### 10.4 跳跃状态区域

建议显示：

```text
jump_phase
space_key_state
input_hold_duration
takeoff_latency
air_time
ascent_time
time_to_edge
relative_gap_span
relative_landing_height
predicted_landing_region
success_probability
movement_context
profile_revision
```

### 10.5 时间线区域

时间线应将以下事件放在同一单调时钟上：

```text
帧到达
方向键按下和释放
空格按下和释放
预测起跳时刻
视觉起跳时刻
最高点
第一次落地接触
稳定落地
失败或恢复事件
```

时间线需要支持逐帧前进、后退、区间循环和跳转到事件。

### 10.6 对比和标注

实验视图应能够：

- 同时显示预测值和人工标签；
- 比较两个模型或两组参数；
- 标记方向判断错误；
- 修正起跳、最高点和落地帧；
- 标记特殊移动模式；
- 标记失败归因；
- 将修正写为独立标注，不覆盖原始模型输出。

原始推理、人工修正和最终采用结果必须分开保存。

## 11. 与Trace Core和离线回放的关系

这项实验依赖Trace Core未来提供：

- 带`frame_id`和单调时间戳的连续帧；
- 键盘按下和释放事件；
- 窗口实例和焦点代次；
- 输入前后帧关系；
- 可重复读取的离线回放；
- 失败现场和证据引用。

合理关系为：

```text
Trace Core
-> 保存帧、输入、窗口和时间线事实

运动与跳跃实验
-> 从回放生成视觉运动和跳跃阶段候选

MotionAnalysisView
-> 展示原始事实、候选结果和人工标注

JumpResponseProfile分析
-> 判断样本是否足以形成经验边界
```

实验工具不能自行临时截图或使用与Trace Core不同的时间源。正式Trace Core完成前，可以使用离线视频和独立键盘日志进行原型验证，但必须明确同步误差。

## 12. 最小实验顺序

### 12.1 阶段A：静止与镜头运动

- 人物静止，分别测试水平和垂直转动镜头；
- 测试FOV缩放和第三人称镜头拉近拉远；
- 验证系统不会把纯镜头运动判断成人物移动；
- 记录各种画面变形线索的基线。

### 12.2 阶段B：平地速度阶段

- 固定相机模式；
- 从静止开始行走、奔跑和冲刺；
- 记录加速、巡航、减速和停止；
- 比较背景光流、人物动画和视觉速度效果；
- 验证不同画质设置下的变化。

### 12.3 阶段C：原地可变跳跃

- 测试轻点、短按、中按和长按；
- 记录输入、起跳、最高点、落地接触和稳定落地；
- 判断按键时长是否真正改变腾空时间或高度；
- 重复测量随机性和动画延迟。

### 12.4 阶段D：同高度水平跳跃

- 使用不同起跳速度阶段；
- 使用不同空格时长；
- 改变接近方向；
- 测量预测落地区间和实际落地结果；
- 学习普通跳跃能力边界。

### 12.5 阶段E：不同落脚高度

- 远侧平台较低、同高和较高；
- 比较腾空时间和水平距离变化；
- 测试落地后滑落；
- 验证高度证据是否改善预测。

### 12.6 阶段F：特殊模式

- 跳板、二段跳、冲刺跳或低重力；
- 验证异常样本不会污染普通画像；
- 建立或拒绝建立新的`MovementContext`。

### 12.7 阶段G：分析窗口与离线复现

- 用同一回放重复运行模型；
- 验证方向、速度、跳跃阶段和落点结果可复现；
- 逐帧修正事件标签；
- 比较两组模型或参数；
- 导出实验摘要和失败样本索引。

## 13. 评估指标

至少记录：

- 人物移动方向分类准确率；
- 摄像机运动被误判为人物运动的比例；
- 静止、加速、巡航、减速和冲刺状态混淆情况；
- 速度等级连续帧跳变次数；
- 起跳、最高点、落地接触和稳定落地的帧误差；
- 空格时长分桶之间的腾空时间差异；
- `TimeToContact`与实际到达边缘时间的误差；
- 预测落地区间覆盖实际落点的比例；
- 可跳与不可跳判断的Precision、Recall和校准误差；
- 各类失败归因混淆情况；
- 特殊模式被错误写入普通画像的比例；
- 同一回放重复推理的确定性；
- 实时和离线模式的P50/P95延迟；
- 人工修正前后的结果差异。

指标应按第一人称、第三人称、相机模式、画质配置、角色状态和游戏版本分组统计，不能只报告混合平均值。

## 14. 候选输入、输出与边界

以下仅用于描述实验，不代表公共契约。

### 14.1 候选输入

- 连续RGB帧与单调时间戳；
- 键盘按下、释放和输入归属；
- 人物、HUD、武器和动态区域遮罩；
- 相对或度量深度；
- 人物落脚锚点；
- 地面走廊、裂隙边缘和落脚区域候选；
- 相机模式、FOV和画质配置；
- 可选人工事件标签。

### 14.2 候选输出

- 视觉运动线索序列；
- 请求方向、观察方向和摄像机方向；
- 人物速度阶段和速度等级；
- 跳跃阶段与关键事件时间；
- 空格按键响应统计；
- `TimeToContact`；
- 预测落地区间与成功概率；
- 跳跃响应画像候选；
- 失败原因和样本处置建议；
- 分析窗口可视化数据。

### 14.3 不负责范围

- 不把FOV、模糊或速度线单独解释为真实速度；
- 不根据输入时长直接宣布已经起跳；
- 不用腾空时间单独推导水平距离；
- 不把摄像机运动等同于人物运动；
- 不将特殊跳跃写入普通跳跃画像；
- 不在落地接触后立即宣布稳定成功；
- 不覆盖原始帧、输入、模型输出或人工标注；
- 不在缺少可靠窗口和时间线时生成正式训练样本；
- 不直接执行高风险跳跃。

## 16. 总结

这一构想的核心不是建立一套看似精确的通用跳跃物理，而是让系统像玩家一样使用多种线索：

```text
画面速度感和静态背景运动
-> 判断是否已经加速到合适阶段

人物落脚点、边缘接近速度和TimeToContact
-> 判断何时起跳

空格按住时间、人物状态和落脚面高度
-> 选择跳跃响应画像

起跳、最高点、落地与实际落点
-> 验证预测并更新经验
```

第一版最重要的产物是可检查的分析窗口和可重复离线回放。只有当系统能够稳定显示人物方向、速度阶段、输入时序、跳跃阶段和预测残差后，才适合把这些结果用于自动跳跃。
