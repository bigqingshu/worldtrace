## 1. 核心结论

人物移动的第一版观测不一定需要实时计算真实长度、宽度和米制速度。人类玩家通常也不会持续计算这些数值，而是依靠：

- 当前按下了什么键；
- 人物正在播放什么动作；
- 背景和近处地面如何变化；
- 镜头是否拉远、扩张或产生速度效果；
- 人物是否真的向目标方向推进；
- 过去在类似状态下产生了什么结果。

因此可以先将人物速度替换为离散、可验证的运动状态：

```text
静止
走路或低速
跑步或中速
疾跑、冲刺或高速
超慢、超快或异常推进
UNKNOWN
```

但不能把所有信息压缩为一个速度枚举。更合理的候选抽象是将`MotionState`（人物运动状态）拆成三条独立轴：

```text
LocomotionMode
-> 人物正在执行什么移动方式

ProgressRate
-> 人物实际上产生了多强的推进

MotionCause
-> 当前运动或画面变化由什么造成
```

这种抽象不追求伪精确数值，而是服务于：

```text
当前状态能否稳定识别？
该状态在当前地形和角色条件下通常产生什么结果？
系统是否有足够证据据此执行下一步？
```

## 2. 为什么离散状态适合作为第一版

### 2.1 避免不必要的物理标定

若直接计算真实速度，通常需要：

- 稳定的度量深度；
- 相机内参和FOV；
- 人物与摄像机真实空间关系；
- 可靠的世界尺度；
- 摄像机运动与人物运动分离；
- 时间同步和多帧位姿；
- 游戏单位与现实单位的对应关系。

这些条件并非永远不值得实现，但不应成为验证“人物是否已进入疾跑状态”的前置要求。

### 2.2 离散结果更接近动作需求

跳跃、翻越和接近目标时，系统通常更关心：

```text
人物是否已经开始推进？
是否仍在加速？
是否进入稳定奔跑或冲刺？
是否因为障碍而没有推进？
当前是否处于特殊场景效果？
```

这些问题可以由离散状态回答，不要求先输出米每秒。

### 2.3 离散输出不等于完全不保存数值

光流幅度、画面扩张率、输入持续时间、深度剖面和人物动画频率仍可以保存为原始或中间证据。离散状态只是当前决策层使用的派生结果。

```text
原始帧与输入
-> 可重算的视觉和时间特征
-> 版本化离散状态
-> 条件化动作结果
```

未来如果推翻“低、中、高”划分，可以重新处理原始证据，而不必重新游玩采集。

## 3. 三条独立运动状态轴

### 3.1 LocomotionMode：人物正在做什么

候选`LocomotionMode`（移动方式状态）描述人物当前采用的动作或能力模式：

```text
STOPPED
WALKING
RUNNING
SPRINTING
DASHING
AIRBORNE
CLIMBING
SWIMMING
VEHICLE
SCRIPTED
UNKNOWN
```

它可以来自：

- 按键组合；
- 奔跑或冲刺切换键；
- 人物动画；
- 角色姿态；
- 技能或载具状态；
- 画面速度效果；
- 历史状态转换。

`LocomotionMode`描述“人物看起来正在做什么”，不保证人物真的产生对应位移。

### 3.2 ProgressRate：人物实际上推进多少

候选`ProgressRate`（实际推进强度）描述由静态场景、地面参考物和人物落脚点确认的推进程度：

```text
NONE
VERY_LOW
LOW
MEDIUM
HIGH
VERY_HIGH
ABNORMAL
UNKNOWN
```

例如：

```text
LocomotionMode = SPRINTING
ProgressRate = NONE
```

表示人物呈现冲刺输入或动画，但实际没有推进，可能撞墙、被卡住或处于无效动画。

又例如：

```text
LocomotionMode = STOPPED
ProgressRate = HIGH
```

表示人物没有主动移动动作，但正在被移动平台、击飞、滑坡或脚本运动带动。

### 3.3 MotionCause：运动由什么造成

候选`MotionCause`（运动来源）描述推进或画面变化的主要原因：

```text
SELF_PROPELLED
EXTERNAL_SURFACE
EXTERNAL_FORCE
CAMERA_ONLY
VEHICLE_OR_PLATFORM
SCRIPTED
MIXED
UNKNOWN
```

它用于区分：

- 人物主动走、跑或冲刺；
- 冰面、泥地、传送带和斜坡；
- 击飞、拉扯和爆炸；
- 纯镜头旋转、缩放或跟随；
- 载具和移动平台；
- 过场或脚本强制移动。

`MotionCause`不一定在单帧内可确定，可以先返回`UNKNOWN`，再由连续帧和动作结果收束。

### 3.4 三轴组合示例

| 移动方式 | 推进强度 | 运动来源 | 解释 |
| --- | --- | --- | --- |
| `WALKING` | `LOW` | `SELF_PROPELLED` | 普通低速行走 |
| `RUNNING` | `MEDIUM` | `SELF_PROPELLED` | 普通奔跑 |
| `SPRINTING` | `HIGH` | `SELF_PROPELLED` | 疾跑或冲刺 |
| `SPRINTING` | `NONE` | `UNKNOWN` | 有冲刺表现但没有推进，需检查障碍 |
| `STOPPED` | `HIGH` | `EXTERNAL_SURFACE` | 人物站立但被平台或传送带带动 |
| `AIRBORNE` | `VERY_HIGH` | `EXTERNAL_FORCE` | 被击飞或弹射 |
| `UNKNOWN` | `ABNORMAL` | `CAMERA_ONLY` | 画面剧烈变化但人物运动不可确认 |

三条轴分开后，超高速和超慢速不必强行解释为普通走跑速度。

## 4. 特殊场景效果应作为上下文记录

### 4.1 超高速和超慢速不一定是人物能力

可能导致异常推进的场景包括：

- 冰面持续滑动；
- 泥地、沼泽或减速区域；
- 传送带、移动平台和水流；
- 顺风、逆风或重力变化；
- 弹射器和跳板；
- 载具、飞行或滑翔；
- 被敌人击飞；
- 技能、增益或装备；
- 剧情和脚本移动。

这些结果可以记录，但不能直接扩大普通走路、跑步或冲刺画像。

### 4.2 MovementContext负责隔离经验

`MovementContext`（移动上下文）至少可以候选绑定：

```text
game_version
character_or_form
movement_ability
terrain_effect
buff_or_debuff
camera_mode
fov_or_zoom
graphics_profile
control_schema_revision
visual_model_revision
```

环境指纹变化后，旧经验可以作为先验，但其可信度需要下降。

## 5. 运动状态的证据来源

### 5.1 输入提供意图

键盘和鼠标可以说明：

- 用户或系统请求哪个方向；
- 走、跑、冲刺键是否按下；
- 输入持续多久；
- 是否发生冲突输入；
- 输入是否作用于正确窗口。

输入不能证明人物已经运动。

### 5.2 人物动作提供模式证据

人物姿态和动画可以帮助识别：

- 走路、跑步和冲刺；
- 起步、急停和转身；
- 跳跃、空中和落地；
- 攀爬、游泳和载具；
- 被击飞、僵直和受控状态。

动画可能继续播放但人物被墙挡住，因此还需实际推进证据。

### 5.3 画面效果提供速度模式证据

可使用：

- FOV变化；
- 边缘拉伸；
- 运动模糊和速度线；
- 第三人称镜头拉远；
- 第一人称晃动频率；
- 人物动画频率；
- 拖尾和粒子效果。

这些线索通常适合判断“进入了哪种移动表现”，不适合单独测量实际位移。

### 5.4 静态场景变化提供推进证据

可使用：

- 近处地面和背景光流；
- 静态参考点相对移动；
- 深度随时间变化；
- 人物脚点相对地面参考点变化；
- 接近目标或边缘的时间趋势；
- 小地图位置变化；
- 已知地标或场景指纹变化。

需要先排除镜头旋转、FOV缩放、动态物体和人物遮挡。

### 5.5 动作结果提供最终验证

系统还可以观察：

- 是否实际接近目标；
- 是否越过裂隙；
- 是否登上平台；
- 是否撞墙或原地跑动；
- 是否因特殊场地加速或减速；
- 是否稳定停下。

这些结果反向修正状态分类与动作能力边界。

## 6. 分层调用比每帧完整计算更务实

### 6.1 低成本高频层

可以高频使用：

- 输入状态；
- 简单帧差；
- 局部光流；
- 人物或相机历史状态；
- 已知动画或固定视觉标记；
- 当前状态机预测。

这一层主要回答：

```text
状态是否发生变化？
人物是否真的推进？
当前判断是否与输入明显冲突？
```

### 6.2 中成本确认层

按需使用：

- 更稳定的特征跟踪；
- 人物遮罩或姿态；
- 稠密光流；
- 相对深度图；
- 地面走廊和局部深度剖面。

适合在起步、进入冲刺、接近边缘和状态冲突时调用。

### 6.3 高成本消歧层

仅在高风险或持续不确定时使用：

- 更复杂深度模型；
- 多视角几何；
- 高质量分割或姿态模型；
- 长时间窗口重分析；
- 离线多模型对比。

### 6.4 离散输出不会自动降低模型推理成本

如果仍然每帧运行同一个完整深度模型，最终只输出低、中、高，并不会显著降低模型本身的计算量。

真正的效率来自：

```text
优先使用低成本线索
-> 只有状态变化或风险升高时升级观测
-> 稳定状态下降低昂贵模型频率
-> 失败现场再进行离线重分析
```

## 7. 状态机、迟滞与时间稳定性

### 7.1 不能逐帧独立分类

如果每帧直接选择最大概率类别，人物状态可能在走路、跑步和冲刺之间频繁闪烁。

建议候选状态切换条件为：

```text
连续多帧支持新状态
+ 新状态证据超过进入阈值
+ 当前状态证据低于保持阈值
+ 最短保持时间满足
+ 相机和上下文没有未知切换
-> 执行状态转换
```

进入阈值和退出阈值应不同，形成迟滞。

### 7.2 速度阶段可以先于速度等级

人物从静止进入奔跑时，可以先输出：

```text
ACCELERATING
```

等视觉推进稳定后再收束为：

```text
RUNNING + MEDIUM
```

同理，释放按键后可以进入`DECELERATING`，而不是立即切换为`STOPPED`。

### 7.3 冲突证据需要显式表示

例如：

```text
冲刺键按下
+ 冲刺FOV出现
+ 人物动画为疾跑
+ 背景几乎不动
```

这不是高置信度冲刺，而是：

```text
LocomotionMode = SPRINTING
ProgressRate = NONE
MotionCause = UNKNOWN
```

并触发撞墙、输入失效或场景异常检查。

## 8. 条件化置信度不能只用一个全局数字

### 8.1 建议分开记录的置信信息

至少区分：

```text
state_confidence
context_familiarity
temporal_stability
evidence_agreement
sample_support
observation_freshness
```

含义如下：

| 字段 | 回答的问题 |
| --- | --- |
| `state_confidence` | 当前证据有多支持这个状态 |
| `context_familiarity` | 当前环境与历史样本是否相似 |
| `temporal_stability` | 连续帧判断是否稳定 |
| `evidence_agreement` | 输入、动画、光流和深度是否一致 |
| `sample_support` | 类似条件下有多少有效样本 |
| `observation_freshness` | 使用的帧和输入是否仍然新鲜 |

### 8.2 高状态置信度不等于高可迁移性

例如：

```text
state_confidence = HIGH
context_familiarity = LOW
```

可以表示系统很确定当前看起来像冲刺，但当前位于从未见过的冰面或低重力区域，不能直接套用普通冲刺跳跃经验。

### 8.3 大多数场景可用的前提

离散状态有机会覆盖同一游戏中的大多数普通场景，但需要：

- 保留`UNKNOWN`；
- 对新地形和特殊模式降级；
- 不将摄像机效果当成人物推进；
- 统计不同上下文下的实际结果；
- 对置信输出做经验校准；
- 版本变化后重新验证。

置信度应表达“在相似条件下，这种判断过去有多可靠”，而不是模型主观感觉有多确定。

## 9. 用游戏实验学习状态与结果关系

### 9.1 记录条件化结果

一次有效记录可以表达：

```text
LocomotionMode = RUNNING
ProgressRate = MEDIUM
MotionCause = SELF_PROPELLED
裂隙等级 = NARROW
远侧高度 = SAME_LEVEL
空格时长 = SHORT_HOLD
结果 = STABLE_LANDING
```

又例如：

```text
LocomotionMode = SPRINTING
ProgressRate = NONE
MotionCause = UNKNOWN
结果 = NO_TAKEOFF_PROGRESS
```

第二个样本不能用于扩大疾跑跳跃距离，只能帮助识别冲刺无推进状态。

### 9.2 经验可以形成离散能力表

经过实验后，可能得到：

```text
WALKING + NARROW + SAME_LEVEL
-> 偶尔成功

RUNNING + NARROW + SAME_LEVEL
-> 高概率成功

SPRINTING + MEDIUM + LOWER
-> 高概率成功

RUNNING + MEDIUM + HIGHER
-> 大多失败
```

这已经可以辅助动作选择，不必先知道裂隙米数和人物米制速度。

### 9.3 结果仍需失败归因

失败可能来自：

- 状态分类错误；
- 人物没有实际推进；
- 起跳时机错误；
- 空格时长不合适；
- 方位偏差；
- 落脚平台过高或过小；
- 特殊场景效果；
- 摄像机或观测异常。

只有能够归因的结果才能更新对应状态、能力或场景规则。

## 10. 原始证据与派生状态必须分开保存

### 10.1 原始事实

尽量保留：

- 原始帧和`frame_id`；
- 单调时间戳；
- 输入按下与释放；
- 窗口实例和焦点代次；
- 相机模式和FOV；
- 人物、HUD和动态对象遮罩；
- 深度模型原始输出；
- 光流或特征轨迹；
- 人物动作和脚点候选；
- 动作结果与恢复事件。

### 10.2 派生结果

版本化保存：

```text
LocomotionMode
ProgressRate
MotionCause
MotionState
confidence_components
feature_revision
classifier_revision
environment_fingerprint
supporting_evidence_refs
```

### 10.3 推翻观点时重新计算

如果后续发现：

- 走路和跑步不应分开；
- 冲刺需要拆成多个模式；
- 视觉速度效果没有价值；
- 某种深度特征更可靠；
- 状态应使用连续隐藏变量；

可以从原始证据重新生成新版本派生状态。旧结果保留用于比较，不能覆盖历史。

## 11. 上下文变化与经验失效

以下变化应降低旧状态模型或结果经验的可信度：

- 游戏补丁；
- 角色、形态、装备或属性变化；
- 移动、冲刺和跳跃能力变化；
- 进入载具、游泳、飞行或攀爬；
- 冰面、泥地、低重力和移动平台；
- FOV、相机模式和镜头灵敏度变化；
- 画质、帧率和运动模糊设置变化；
- 输入后端和控制配置变化；
- 视觉模型和特征版本变化；
- 预测结果持续偏离实际结果。

失效不代表历史样本没有价值，而是不能继续把它们当作当前环境的直接可靠证据。

## 12. 与跳跃响应画像的关系

离散移动状态可以成为`JumpResponseProfile`（跳跃响应画像）的输入：

```text
LocomotionMode
+ ProgressRate
+ MotionCause
+ JumpPhase
+ TimeToContact
+ 空格按键时序
+ 裂隙和落脚平台类别
+ MovementContext
-> 落地区间与成功概率
```

跳跃响应画像不需要知道人物真实速度，但需要知道状态分类是否稳定、是否由人物主动推进，以及当前上下文是否与历史实验匹配。

## 13. 分析窗口应如何显示离散状态

`MotionAnalysisView`（运动分析视图）可以显示：

```text
Requested Direction
Observed Direction
Camera Motion
LocomotionMode
ProgressRate
MotionCause
Speed Phase
Context Familiarity
Temporal Stability
Evidence Agreement
UNKNOWN Reason
```

同时叠加：

- 静态特征轨迹；
- 人物脚点；
- 摄像机运动向量；
- 地面走廊；
- 深度层级；
- 当前状态转换；
- 触发状态判断的主要证据。

窗口不应只显示“速度：高速，置信度：90%”。这会隐藏高速来自人物推进还是镜头效果，也会隐藏当前上下文是否陌生。

## 14. 最小实验顺序

### 14.1 阶段A：输入和动画状态

- 固定游戏、角色和相机模式；
- 人工标注静止、走路、跑步和冲刺；
- 记录键盘、人物动画和画面效果；
- 验证`LocomotionMode`是否可分。

### 14.2 阶段B：实际推进状态

- 在安全平地重复各种移动；
- 记录背景光流、脚点和深度变化；
- 验证`ProgressRate`低、中、高是否稳定；
- 人为撞墙，验证冲刺动画不会被解释为高推进。

### 14.3 阶段C：镜头反事实

- 人物静止时旋转镜头；
- 改变FOV和镜头距离；
- 触发运动模糊或速度线；
- 验证`MotionCause = CAMERA_ONLY`或`UNKNOWN`。

### 14.4 阶段D：特殊场地

- 冰面、泥地、移动平台或其他可重复区域；
- 比较人物模式和实际推进；
- 验证特殊经验不会污染普通平地画像。

### 14.5 阶段E：跳跃结果

- 使用离散速度状态代替米制速度；
- 记录不同裂隙和落脚高度类别；
- 比较预测成功率和实际结果；
- 检查置信度是否随样本增加得到校准。

### 14.6 阶段F：跨场景验证

- 在未参与阈值选择的普通场景测试；
- 分别统计熟悉和陌生上下文；
- 验证`UNKNOWN`是否阻止错误泛化；
- 分析哪些视觉线索具有跨场景价值。

## 15. 评估指标

至少记录：

- `LocomotionMode`混淆矩阵；
- `ProgressRate`混淆矩阵和连续帧跳变次数；
- `MotionCause`分类准确率；
- 纯镜头运动误判为人物推进的比例；
- 人物撞墙时误判为高速推进的比例；
- 状态转换检测延迟；
- 状态最短稳定保持时间；
- 输入、动画、光流和深度证据冲突比例；
- 各置信度分桶的实际正确率；
- 熟悉与陌生上下文的结果差异；
- `UNKNOWN`比例和高风险误放行率；
- 相同回放在不同分类版本下的差异；
- 低、中、高成本观测层的延迟和调用频率；
- 离散状态对跳跃结果预测的实际增益。

## 16. 候选输入、输出与边界

以下只描述实验方向，不代表正式公共契约。

### 16.1 候选输入

- 连续帧与单调时间戳；
- 键鼠输入和窗口归属；
- 人物动作、脚点和遮罩候选；
- 光流、特征轨迹和画面效果；
- 相对深度和地面剖面；
- 相机模式、FOV和画质配置；
- 游戏、角色、地形和能力上下文；
- 实际动作结果与失败归因。

### 16.2 候选输出

- `LocomotionMode`；
- `ProgressRate`；
- `MotionCause`；
- 速度阶段和`MotionState`；
- 分项置信信息；
- 主要支持与冲突证据；
- 当前上下文熟悉度；
- 状态转换事件；
- 样本是否适合更新经验的建议。

### 16.3 不负责范围

- 不强制输出米制速度；
- 不把按键输入当作实际推进；
- 不把动画、FOV或速度线当作单独真值；
- 不把摄像机运动当作人物运动；
- 不将特殊场景状态写入普通移动画像；
- 不用一个总置信度覆盖上下文和时序差异；
- 不丢弃原始证据，只保存最终离散标签；
- 不在陌生环境中强制给出已知状态；
- 不因一次成功或失败立即重写能力边界。

## 18. 总结

这一构想的当前假设是：

> 对大多数普通游戏移动任务，稳定区分走路、跑步、冲刺、无推进和异常推进，可能比实时恢复精确米制速度更便宜、更稳健，也更接近人类玩家的判断方式。

完整路线为：

```text
输入、人物动作和低成本视觉变化
-> 候选LocomotionMode

静态场景、脚点和深度变化
-> 候选ProgressRate

相机、地形和特殊事件上下文
-> 候选MotionCause

时间稳定性、证据一致性和历史样本
-> 条件化置信信息

实际移动和跳跃结果
-> 修正状态与能力经验
```

这份文档本身也允许被后续实验推翻。最需要坚持的不是当前状态名称，而是：原始证据可追溯、派生结果可重算、上下文变化会降低可信度、`UNKNOWN`始终存在。
