## 2. 核心结论

1. 键位不是常量：`KeybindRef` 允许 UI 页面图在配置修改后继续解析最新键值。
2. Windows 通知采用可选依赖、懒初始化和 daemon thread，不阻塞任务主流程。
3. 计时器体系广泛用于 UI 稳定、超时和状态连续确认，但各类的启动/计数语义不同。
4. 通用 utils 混合了 I/O、权限、格式化和随机采样，存在较多宽泛异常和历史兼容行为。
5. 多数 `__init__.py` 是空包标记；少数文件承担稳定公共导出和导入副作用。

## 3. Keybind 模型

### 3.1 全局对象

模块末尾创建：

```python
keybind = Keybind()
```

[`Keybind.__init__()`](../../../../../reference_repos/whimbox/whimbox/common/keybind.py#L15) 先为所有字段设置硬编码默认值，再立即调用 `update_keybind()` 从 `global_config` 覆盖。

键位字段包括：

| 类别 | 字段 |
| --- | --- |
| 页面 | MAP、DAILY_TASK、DRESS、TAKE_PHOTO、MONTHLY_PASS、ITEM、EVENT |
| 交互 | INTERACTION、BELL、CHAT、BACK、TAB |
| 移动 | FORWARD、JUMP、FALLING、SPRINT |
| 钓鱼 | FISHING_REEL_IN |
| 能力 | ABILITY_DERIVATION、ABILITY_1 到 ABILITY_8 |

### 3.2 配置刷新

[`update_keybind()`](../../../../../reference_repos/whimbox/whimbox/common/keybind.py#L45) 从 `Keybinds` section 逐项读取当前值。

[`GlobalConfig.set()`](../../../../../reference_repos/whimbox/whimbox/config/config.py#L190) 修改 `Keybinds` 时会动态导入全局 `keybind` 并调用 `update_keybind()`。修改先作用于内存，是否写入磁盘仍取决于调用方是否执行 `global_config.save()`。

### 3.3 KeybindRef

[`KeybindRef`](../../../../../reference_repos/whimbox/whimbox/common/keybind.py#L3) 不保存具体键值，只保存：

- `keybind_obj`；
- 属性名 `attr_name`。

`resolve()` 调用时再执行：

```python
getattr(keybind_obj, attr_name)
```

UI 页面图使用：

```python
page_main.link(keybind.ref("KEYBIND_MAP"), page_bigmap)
```

页面图在模块导入时只保存引用；[`UI.goto_page()`](../../../../../reference_repos/whimbox/whimbox/ui/ui.py#L61) 真正执行边时再解析。因此运行中更新键位后不需要重建整个页面图。

### 3.4 使用边界

- `KeybindRef.__str__()` 直接返回 `resolve()`，隐含配置值应为字符串；
- 属性名写错直到运行 resolve 才抛 `AttributeError`；
- `update_keybind()` 逐项更新，没有锁；任务运行中修改配置可能看到部分新旧值；
- 硬编码默认值通常会立刻被 `global_config` 默认配置覆盖，主要承担构造期兜底。

## 4. Windows 通知

[`common/notification.py`](../../../../../reference_repos/whimbox/whimbox/common/notification.py#L1) 尝试导入 `win10toast.ToastNotifier`：

- 成功：`TOAST_AVAILABLE = True`；
- ImportError：功能禁用并记录 warning；
- 非 Windows 环境可以通过依赖缺失路径安全退化。

### 4.1 WindowsNotifier

[`WindowsNotifier`](../../../../../reference_repos/whimbox/whimbox/common/notification.py#L19) 构造时尝试创建 `ToastNotifier`。初始化异常会记录 error，并保持 `toaster=None`。

[`is_enabled()`](../../../../../reference_repos/whimbox/whimbox/common/notification.py#L31) 同时要求：

```text
Whimbox.enable_windows_notification == true
AND toaster 初始化成功
```

任何配置读取异常都返回 false。

### 4.2 发送流程

[`send_notification()`](../../../../../reference_repos/whimbox/whimbox/common/notification.py#L39) 检查：

1. 通知功能启用；
2. message 非空；
3. 构造内部 `_send()`；
4. 默认创建 daemon thread；
5. 子线程同步调用 `show_toast(duration=5, threaded=False)`。

外层已使用独立线程，因此显式把 win10toast 自身的 `threaded` 设为 false。

### 4.3 懒单例

模块级 `_notifier` 初始为 `None`。[`get_notifier()`](../../../../../reference_repos/whimbox/whimbox/common/notification.py#L84) 第一次发送时才创建实例。

这个懒初始化没有锁。多个线程首次同时发送可能创建多个临时实例，最后一个写入全局变量。

### 4.4 `status` 参数

公共 API 接受 `status`，注释说明可用于选择图标，但当前 `_send()` 没有读取它。它目前只是保留参数，不影响通知展示。

## 5. Timer 基类

[`Timer`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L6) 使用 `time.time()`：

- 构造时设置 `start_time` 和 `end_time`；
- `diff_start_time` 可把起点向前偏移；
- `reset()` 重置起点；
- `stop()` 更新终点；
- `get_diff_time(r=2)` 返回四舍五入后的秒数；
- `reset_and_get()` 获取耗时后重置。

使用 wall clock 而不是 `time.monotonic()`，系统时间调整会影响计时结果。

## 6. AdvanceTimer

[`AdvanceTimer`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L32) 用于“时间达到且连续确认若干次”的场景。

状态：

- `limit`：时间阈值；
- `count`：额外确认次数；
- `_current`：启动时间，0 表示未启动；
- `_reach_count`：当前检查次数。

### 6.1 启动和重置

| 方法 | 行为 |
| --- | --- |
| `start()` | 未启动时记录当前时间并把计数置 0 |
| `reset()` | 无论是否启动都把起点设为当前时间，计数置 0 |
| `clear()` | 起点清 0，计数设为 `count` |
| `started()` | `_current` 是否非零 |

### 6.2 reached 语义

每次调用 `reached()` 都先递增 `_reach_count`，然后判断：

```python
time.time() - _current > limit
and _reach_count > count
```

`count=0` 时，超过时间阈值后的第一次检查即可成功。`count=3` 时，需要 `_reach_count > 3`，即第四次检查才成功。

调用方通常应先 `start()` 或 `reset()`。未启动时 `_current=0`，`time.time()-0` 极大，时间条件会立即成立。

### 6.3 wait

`wait(additional_time)` 计算剩余时间，只有大于 0.05 秒才 sleep。它不循环确认，也不检查停止事件。

## 7. 其他 Timer 类型

### 7.1 CyclicVelocityDetector

[`get_cyclic_velocity()`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L127) 返回：

```python
int(1 / dt)
```

`dt` 来自保留两位小数的 `get_diff_time()`。极短间隔可能被舍入为 0，存在除零风险；频率精度也受两位小数限制。

### 7.2 CyclicCounter

在每个 AdvanceTimer 周期中累计调用次数。周期达到时：

- 返回旧次数；
- 把 `times` 重置为 1；
- 未达到时递增并返回 false。

返回类型是 `int | bool`，调用方不应只依赖 truthiness 区分“次数为 0”和未达到。

### 7.3 TimeoutTimer

[`TimeoutTimer`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L150) 使用 `get_diff_time()` 判断超时，因此默认按两位小数舍入。`timeout_limit < 0` 表示永不超时。

### 7.4 FileTimer

[`FileTimer`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L177) 保存到：

```text
configs/timer/<timer_name>.txt
```

文件不存在时写入 `0`，随后读取为浮点起点；`reset()` 写当前时间。

代码没有显式创建 `configs/timer/` 父目录。首次使用前若该目录不存在，`open(..., "w")` 会失败。

文件读写未指定 encoding、无锁、非原子，多个实例同名时会竞争。

### 7.5 Performance

[`Performance.output_log()`](../../../../../reference_repos/whimbox/whimbox/common/timer_module.py#L208) 希望每 `output_cycle` 次输出一次。但 `_output_num` 只在实际输出分支递增：

```text
初始 0 → 输出并变为 1 → 后续一直 1，else 分支不递增
```

当 `output_cycle > 1` 时，当前实现通常只输出第一次，之后不再达到整除条件。这是源码可确认的计数缺陷。

### 7.6 `@timer`

装饰器使用 `time.time()` 计算函数耗时并直接 `print()`，不写 Loguru，也不保留异常处理或异步函数语义。

## 8. JSON 工具

### 8.1 load_json

[`load_json()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L13) 组合：

```python
os.path.join(ROOT_PATH, folder_path, json_name)
```

使用 `object_pairs_hook=OrderedDict` 保留键顺序。任何异常都被宽泛捕获，记录 critical 后统一抛 `FileNotFoundError`。

这会把权限错误、JSON 语法错误、编码错误等不同原因都伪装成“文件不存在”。

文件通过 `json.load(open(...))` 打开，没有 context manager。

### 8.2 save_json

[`save_json()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L33) 直接覆盖目标 JSON：

- 默认排序键；
- 缩进 2；
- 保留中文；
- 不创建父目录；
- 非原子写入；
- 所有异常统一转为 `FileNotFoundError`。

## 9. 权限和路径工具

### 9.1 is_admin

[`is_admin()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L53) 延迟导入平台工厂，调用 `PathManager.is_admin()`。任何异常记录 error 并返回 false。

正常入口据此决定是否继续启动。

### 9.2 verify_path

[`verify_path()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L74) 递归检查父目录并调用 `os.mkdir()`。

它属于历史实现：

- 不使用 `os.makedirs(exist_ok=True)`；
- 通过 `root/../` 构造父路径；
- 没有处理盘符根目录、权限、并发创建和空路径；
- 失败时直接传播异常。

新增代码应优先使用 `Path.mkdir(parents=True, exist_ok=True)`。

## 10. 列表和 JSON 文本转换

| 函数 | 行为 |
| --- | --- |
| [`list_text2list`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L82) | JSON 字符串转 list；失败返回空 list；非 list 通过 `list(value)` 转换 |
| [`list2list_text`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L106) | list 转紧凑 JSON；失败回退 `str()` |
| [`list2format_list_text`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L127) | 缩进 JSON；`inline=true` 时把换行改空格 |
| [`is_json_equal`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L142) | 解析后按排序键重新编码比较 |

`list_text2list()` 对 JSON 字典执行 `list(dict)`，得到键列表；对数字等不可迭代非 list 值，`list(rt_list)` 会抛 TypeError，外层没有再次捕获。

## 11. 数值、文本和随机工具

### 11.1 类型判断

- [`is_int()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L158) 只捕获 `ValueError`，传入 `None` 等可能抛 `TypeError`；
- [`is_number()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L175) 先 float，再尝试 Unicode numeric；
- [`is_chinese()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L195) 只要包含一个 CJK 基本区字符即 true。

### 11.2 格式化

- `float2str()` 使用 `ljust` 补零，不保证科学计数法或负数格式；
- `float2str()` 在同一文件中定义了两次，后一个定义覆盖前一个；
- `round_list()` 原地修改输入 list 后返回浅复制；
- `replace_text_format()` 把常见中文标点转换为 ASCII；
- `point2str()` 把坐标截断为 int 后右对齐。

### 11.3 边界约束

[`maxmin(x, nmax, nmin)`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L210) 先取 `min(x,nmax)` 再取 `max(...,nmin)`。参数顺序是 max 在前、min 在后，和常见 clamp API 相反。

### 11.4 随机时间

[`random_normal_distribution_int()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L253) 通过多个均匀随机整数的平均值近似钟形分布；当 `a >= b` 时直接返回 `b`。

[`ensure_time()`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L272) 支持：

- 数字：原样返回；
- tuple：按指定精度随机采样；
- `"lower,upper"`；
- `"lower-upper"`；
- 单个数字字符串：转 int。

字符串区间只用 `int()` 解析，不支持小数和负数区间的无歧义表达。

### 11.5 ensure_int

[`ensure_int(*args)`](../../../../../reference_repos/whimbox/whimbox/common/utils/utils.py#L302) 递归转换：

- `int(item)` 成功：返回 int；
- TypeError：把 item 当可迭代对象继续递归；
- 单元素结果会降维为标量。

它不捕获 `ValueError`，例如 `"abc"` 会直接抛错。返回结构还会因单元素容器自动降维，调用方需要了解这一历史语义。

## 12. 自定义异常

[`common/errors.py`](../../../../../reference_repos/whimbox/whimbox/common/errors.py#L1) 定义：

| 异常 | 用途 |
| --- | --- |
| `FunctionModeError` | 函数模式参数错误 |
| `IMG_NOT_FOUND` | 资产图片无法找到 |
| `NAME_NOT_FOUND` | 无法推导资产名称 |
| `ThreadTerminated` | BaseThreading 内部正常终止信号 |
| `BigMapTPError` | 大地图传送失败或传送点未解锁 |

这些异常都没有额外字段，语义完全依赖 message 和捕获位置。

`ThreadTerminated` 的文案说明它常用于线程正常结束，不应一律作为 fatal error 上报。

- JSON 错误与权限错误的异常分类；
- ensure_time 的 tuple、逗号和横线输入；
- ensure_int 的标量、单元素、多元素和非法字符串；
- 包 `__all__` 导出稳定性。

## 15. 风险与改进方向

### 15.1 计时应使用 monotonic clock

任务超时和 UI 稳定检测不应受系统时间调整影响。可统一迁移到 `time.monotonic()`，文件持久化时间仍保留 wall clock。

### 15.2 Timer API 语义不统一

`Timer` 构造即启动，`AdvanceTimer` 构造未启动；`count` 使用严格大于；`TimeoutTimer` 继承两位小数舍入。建议明确接口契约并补边界测试。

### 15.3 Performance 计数缺陷

`_output_num` 应在每次调用递增，而不是只在输出分支递增。

### 15.4 FileTimer 目录和并发

应创建父目录，使用 encoding、锁和原子替换，并处理损坏内容。

### 15.5 宽泛异常丢失根因

JSON 工具将解析、权限、编码等错误统一转为 FileNotFoundError，降低诊断质量。应保留原异常链或定义更准确的领域异常。

### 15.6 通用 utils 职责过多

I/O、文本、随机、权限和数值函数混在一个模块，并通过 wildcard import 广泛传播。拆分后可以减少导入副作用和名称冲突。

### 15.7 全局 Keybind 更新无锁

逐字段原地更新可能让并发任务看到半更新状态。可构造新不可变映射后一次替换，或在任务开始时获取配置快照。

### 15.8 通知线程不可观察

daemon 通知线程不保存引用、不等待结束，进程退出时通知可能丢失。status 参数也尚未实现。

### 15.9 包初始化副作用不一致

有的 `__init__` 为空，有的导出类型，有的还创建全局 manager。调用方只看 package import 很难判断副作用，建议保持导出层轻量并显式初始化服务对象。
