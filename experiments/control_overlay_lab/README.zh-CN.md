# Control Overlay Lab（控制态叠加层实验）

## 当前状态

第一版独立实验，归属 `experiments`。它用于确认能否在 Windows 本机显示器上
复现类似 Codex Computer Use 的控制态视觉反馈：目标窗口高亮、双层鼠标、点击
定位环和组合键退出，同时尝试让这些视觉元素不进入兼容的截图或远控画面。

本实验不复制或声称使用 Codex 的内部实现。当前公开依据只是 Windows 的透明
置顶窗口、全局热键和窗口显示亲和性接口。

启动命令：

```powershell
cd D:\Games\worldtrace_workspace\worldtrace
..\.venv\Scripts\python.exe -m experiments.control_overlay_lab
```

离屏生命周期检查：

```powershell
..\.venv\Scripts\python.exe -m experiments.control_overlay_lab --smoke-test
```

## 第一版目标

- 选择一个当前可用的窗口作为显示目标；
- 沿目标客户区绘制蓝色脉冲高亮边框；
- 显示“系统鼠标 + 智能体指针”或“智能体内点 + 外环”；
- 通过测试按钮在目标中心显示左键或右键扩散环；
- 使用独立 Win32 全局 `Ctrl+Alt+Shift+F10` 热键结束本轮预览；
- 运行中持续检查热键线程存活、注册状态、回调错误和异常退出，失效即失败关闭；
- 尝试设置并回读 `WDA_EXCLUDEFROMCAPTURE`；
- 目标窗口移动或缩放时同步更新叠加层；
- 目标 HWND 消失或换到其他进程时立即停止；
- 默认不写截图、JSON、日志或测试结果文件。

## 明确边界

- 不调用 `SendInput`，不移动、点击或按下真实键鼠；
- 不安装鼠标 Hook，不注册 Raw Input，不隐藏系统光标；
- 不读取或注入目标进程；
- 不判断目标程序是否消费了输入；
- 不进入 Trace Core，不改变任何正式公共契约；
- 不保证独占全屏游戏上一定显示；
- 不保证所有截图、采集卡、远控或驱动级捕获都遵守显示亲和性；
- 退出组合只负责退出本实验叠加层，不承诺目标程序一定看到或一定看不到按键；
- 裸 `Esc` 仅保留为显式的预览对照配置，默认不注册。

本实验没有接入 `Ctrl+Shift+F12` 的低级监听器。因为本实验完全不发送输入，GUI
的停止按钮是第二退出路径；这样也避免为了一个纯视觉实验重新引入可能影响鼠标
流畅度的全局 Hook。未来接入真实执行会话时，再在执行层保留独立紧急停止。

## 使用步骤

1. 点击“刷新窗口”，选择目标窗口；
2. 选择双层鼠标模式；
3. 保持“请求 `WDA_EXCLUDEFROMCAPTURE`”开启；
4. 点击“开始控制态预览”；
5. 点击目标窗口，确认叠加层不抢焦点且不会拦截点击；
6. 在目标客户区移动鼠标，观察外环和智能体指针；
7. 点击“左键定位环”或“右键定位环”确认动画；
8. 按 `Ctrl+Alt+Shift+F10`，确认叠加层立即消失；
9. 分别使用 Codex 截图、向日葵、ToDesk、WGC 桌面捕获、MSS 或 DXCam 观察
   叠加层是否进入捕获画面。

为了验证捕获排除，必须再做一次关闭“请求捕获排除”的控制组。如果关闭时捕获
本来就看不到叠加层，那么该捕获方式很可能只采集目标窗口，不包含其他顶层窗口，
不能据此证明 `WDA_EXCLUDEFROMCAPTURE` 生效。

## 三层结果语义

GUI 将三件不同的事实分开：

1. `native=True`：置顶、不激活和输入穿透等本机窗口门禁已经回读确认；
2. `API_CONFIRMED`：显示亲和性设置成功，且 Windows 回读值与请求值相同；
3. `UNKNOWN / VISIBLE / NOT_VISIBLE`：某个具体捕获后端的实际观察结果。

当前 GUI 只自动给出前两项，第三项默认保持 `UNKNOWN`，需要人工观察。即使接口
回读为 `0x00000011`，也不能自动宣称向日葵、ToDesk、Codex 或任何驱动级后端
一定看不到。

## 双层鼠标语义

- `SYSTEM_PLUS_AGENT`：真实系统光标保持原状，叠加一个白色智能体指针和青色
  脉冲外环；
- `AGENT_INNER_OUTER`：显示中心实点、十字和脉冲外环；
- 第一版的智能体位置只是轮询 `GetCursorPos` 得到的物理系统坐标；
- 第一版没有“计划位置”，也没有把鼠标动作写入录制事件；
- 左/右定位环按钮只在目标中心播放动画，不执行真实点击。

后续与 `input_execution_lab` 连接时，才可以把智能体指针改为计划位置，把定位环
绑定到实际发送事件。连接前仍保持两个实验互不依赖。

## 原生实现边界

叠加层是本进程拥有的独立顶层 HWND，只会修改自己的窗口：

- `WS_EX_LAYERED`：透明分层窗口；
- `WS_EX_TRANSPARENT`：配合 Qt 输入穿透；
- `WS_EX_TOOLWINDOW`：不进入普通任务切换界面；
- `WS_EX_NOACTIVATE`：显示时不抢目标焦点；
- `HWND_TOPMOST + SWP_NOACTIVATE`：置顶但不激活；
- `SetWindowDisplayAffinity(..., WDA_EXCLUDEFROMCAPTURE)`：请求兼容捕获排除；
- `GetWindowDisplayAffinity`：回读请求结果；
- `RegisterHotKey(NULL, ..., MOD_CONTROL | MOD_ALT | MOD_SHIFT |
  MOD_NOREPEAT, VK_F10)`：独立线程注册默认退出组合；
- 监听诊断只驻留内存，区分注册、消息、命中、回调和消息循环退出阶段；当前
  没有消息泵心跳，线程仍存活但内部长期阻塞的情况不声称能够自动识别。

原生层会先证明叠加 HWND 属于本实验进程，并拒绝将目标窗口 HWND 当成叠加窗口
修改。导入 Python 包不会创建 HWND、加载 Qt、注册热键或调用上述原生接口。

## 4K、DPI 与多显示器

Windows 窗口客户区来自物理像素，Qt 顶层窗口使用设备独立像素。本实验按每个
显示器的原点和 DPR 独立映射，支持 4K/200% 和负坐标副屏。

目标客户区跨越两个不同缩放显示器时，第一版会失败关闭，而不是用单一比例产生
错误边框。将目标窗口完整放在一个显示器内后重新开始即可。

## 文件结构

- `contracts.py`：实验状态、目标、视觉参数和捕获诊断契约；
- `session.py`：按 generation 隔离的易失状态机；
- `geometry.py`：物理像素到 Qt DIP 的严格映射；
- `native_overlay.py`：窗口样式、置顶和显示亲和性；
- `hotkeys.py`：可配置的独立 Win32 热键消息线程与易失健康诊断；
- `cursor_probe.py`：只读系统光标位置探测；
- `overlay_window.py`：高亮、状态提示、双层鼠标和定位环绘制；
- `app.py`：目标选择、生命周期、诊断和 GUI；
- `__main__.py`：命令行入口；
- `tests/`：纯契约、原生假后端、DPI、绘制、GUI 和导入边界测试。

## 自动化验收

```powershell
..\.venv\Scripts\python.exe -m unittest discover `
  -s experiments\control_overlay_lab\tests -t . -v
```

自动测试验证：

- 三项门禁齐备后才进入 `ACTIVE`；
- 过期 generation 的绘制和指针更新会被拒绝；
- 4K/200%、负坐标、多屏和半开边界映射；
- 只修改本进程叠加 HWND，不修改目标 HWND；
- 显示亲和性设置、回读、不匹配和恢复；
- 默认组合键注册握手、回调、停止、注销和运行期健康失败；
- 旧 generation 的排队回调不会停止新会话；
- Qt 窗口不激活、输入穿透和真实绘制确认；
- 目标移动跟随和身份变化停止；
- 包导入无 Qt、窗口和热键副作用；
- 离屏启动、激活、停止和关闭不写文件。

自动测试不能证明本机肉眼效果，也不能证明具体远控后端不可见。

## 退出键人工验收顺序

每种情况都应分别记录 `registered`、`alive`、`messages`、`triggers`、
`callbacks` 和 `exit`，不要只凭高亮是否消失判断输入链路：

1. 本地物理键盘 + 普通应用窗口；
2. 本地物理键盘 + 原神窗口化；
3. 本地物理键盘 + 原神无边框全屏；
4. 本地物理键盘 + 原神独占全屏；
5. 仅在失败的显示模式下，分别复测向日葵和 ToDesk；
6. 若目标以高完整性运行，再对比实验普通权限与双方同权限。

按键后若全屏中看不到叠加层变化，应切回实验 GUI 查看终态：

- `messages=0`：当前热键线程没有收到任何窗口消息；
- `messages>0, triggers=0`：收到消息，但没有匹配注册的组合；
- `triggers>0, callbacks=0`：匹配后没有进入回调；
- `callbacks>0` 但会话未停止：Qt 桥接或 generation 门禁需要检查；
- `alive=false` 或存在 `exit`：监听已失效，实验必须自动进入失败终态并清理叠加层。

这些结果只能定位 Windows 输入路径，不能单独证明是反作弊、游戏优先级或远控实现。

### 当前机器桌面捕获 A/B（2026-08-12）

在当前 Windows 11、4K/200% DPI 会话中，使用临时纯色目标窗口和 MSS 桌面区域
捕获进行了不落盘对照：

- 物理客户区：`1040×640 @ (840, 520)`；
- 排除关闭：显示亲和性回读 `0x00000000`，捕获到 114,720 个青色边框像素；
- 排除开启：显示亲和性回读 `0x00000011`，捕获到 0 个青色边框像素；
- 两轮原生接口都确认成功，结束后恢复 `WDA_NONE` 成功。

这只验证当前机器上的 MSS 桌面捕获路径，不能外推到 Codex、向日葵、ToDesk、
采集卡或其他后端。本机物理显示器上的观感仍需用户肉眼验收。
