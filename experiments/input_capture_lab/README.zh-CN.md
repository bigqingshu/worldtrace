# Input Capture Lab（输入捕获实验）

## 当前目标

`experiments.input_capture_lab` 是 Trace Core（轨迹核心）中
`InputRecorder`（输入记录器）正式实现之前的独立验证实验。第一版只回答：

> 在用户明确选择一个普通桌面窗口后，能否只在该窗口持续位于前台时，
> 以统一单调时间记录键盘按下/释放、鼠标按钮按下/释放位置和可选滚轮事件？

它不识别游戏界面，不推断游戏状态，不执行键鼠操作，也不把一次监听事件解释成
“输入已经送达游戏”或“游戏已经产生预期效果”。

本实验保留在 `experiments`；当前契约不是 Trace Core 公共契约，也不写入
`StateSnapshot`、事实存储、关系图或执行器。

## 输入与输出

输入：

- 用户从可见顶层窗口列表中明确选择的目标窗口；
- 目标窗口选择时的 `HWND + PID` 身份、标题和客户区；
- `pynput` 提供的键盘按下/释放回调；
- `pynput` 提供的鼠标按钮按下/释放回调；
- 用户显式启用时的鼠标滚轮回调。

第一版不会注册鼠标移动回调。移动鼠标本身不会生成事件，也不会把连续指针轨迹
放入内存。

被门禁接纳的输出是进程内 `InputCaptureEvent`（输入捕获事件），包含：

- 会话内序号、事件 ID、按下/释放配对组 ID；
- 会话经过时间和单调时间戳；
- 键盘或鼠标设备、事件类型、按键或按钮；
- 目标 `HWND`、PID、窗口标题和监听后端；
- 当前 `focus_epoch`（焦点代次）；
- 鼠标事件的屏幕坐标、客户区坐标和归一化客户区坐标；
- 成对释放事件的按压持续时间；
- 固定为 `UNKNOWN` 的 `delivery_status`（投递状态）。

GUI 使用中文列显示这些信息。默认队列和表格都是有界内存视图；队列溢出会计数，
不会静默伪装成完整时间线。

除事件队列外，会话还提供实验私有
`InputCaptureDiagnosticsSnapshot`（输入捕获诊断快照）。它用于解释“为什么当前
没有事件”以及“监听是否仍然健康”，不是新的游戏状态或投递证明。诊断快照默认
只存在于进程内，不会自动写入 JSON、JSONL、日志或其他文件。

## 前台窗口安全门禁

第一版门禁同时绑定目标 `HWND + PID`，不能只按标题匹配。每个监听回调都在进入
实验事件队列前重新检查：

1. 所选句柄仍然存在；
2. 该句柄当前仍属于选择时的 PID；
3. 目标不是最小化窗口；
4. 当前前台窗口正是所选 `HWND`；
5. 目标重新取得前台后已经连续稳定至少 `200 ms`；
6. 鼠标按下和滚轮位置命中目标客户区及其根窗口。

点击 GUI 中的“开始监听”时，GUI 自身通常位于前台，所以会话先进入
`WAITING_FOREGROUND`（等待目标前台）。切换到目标窗口后先进入
`ARMING`（稳定等待），满 `200 ms` 才进入 `ACTIVE`（激活）。
这段等待用于过滤启动按钮点击、切换窗口点击和 `Alt+Tab` 等焦点获取动作。

目标离开前台后立即暂停接纳事件，并清除尚未闭合的按压组，将其计为不完整组；
不会伪造释放事件。目标再次稳定取得前台会开启新的焦点代次，前后代次的按下和
释放不能配成一组。

若目标被最小化，会话暂停接纳并等待同一窗口恢复；若目标被关闭、句柄失效、
PID／进程实例不匹配，或非最小化窗口的客户区无法可靠读取，会话进入目标丢失／
失败状态并停止监听。第一版不会按标题盲目重连到另一个窗口。

未通过门禁的系统回调只增加分类计数，不进入 `RawInputEvent`、事件队列、表格或
日志，也不保留按键、按钮和坐标详情。

### 鼠标边界

- 鼠标按下和滚轮只有在目标客户区内才会被接纳；
- 已在客户区内接纳的鼠标按下，其匹配释放即使落在客户区外，也可保留为
  `RELEASE_OUTSIDE_CLIENT`，用于结束同一个按压组；
- 客户区外的未配对释放不会单独形成事件；
- 屏幕、客户区和归一化坐标都是事件发生时的观测，不是以后窗口位置的重算结果；
- 第一版不记录鼠标移动轨迹。

## 结构化易失诊断

GUI 会读取结构化诊断快照并显示当前修订号。修订号只在诊断语义发生变化时递增，
避免按 GUI 轮询频率重复刷新同一状态。快照是只读、可转为 JSON-safe
（可安全序列化为 JSON 的基础值）结构的易失观测，包含：

- 会话状态、最后错误和当前前台门禁原因码；
- 目标句柄、预期／当前 PID、进程创建时间、最小化状态和当前客户区；
- 键盘、鼠标两个监听器各自的存活状态、停止状态、回调数量、最后回调时间、
  回调失败数量和错误；一个监听器存活不代表另一个监听器也健康；
- 最近一次鼠标点命中的根 `HWND`、根窗口 PID、是否命中目标／目标进程、
  是否位于客户区及拒绝原因；
- 有界保存的中断按压证据，包括原按下事件 ID、配对组 ID、设备、按键／按钮、
  焦点代次、按下与中断时间及中断原因。

前台关系使用 `ForegroundWindowRelationship`（前台窗口关系）枚举，不能由标题
或模糊进程名替代：

| 值 | 含义 |
| --- | --- |
| `EXACT_TARGET` | 当前前台 `HWND` 正是冻结的目标；只有此关系能够进入激活状态 |
| `SAME_PROCESS_OTHER_WINDOW` | 同一 PID 的另一个顶层窗口在前台，仍按非目标处理 |
| `OTHER_PROCESS` | 其他进程的窗口在前台 |
| `NO_FOREGROUND` | Windows 当前未返回前台窗口 |
| `UNKNOWN` | 前台窗口或其进程关系无法可靠读取，按失败关闭原则不激活 |

若在一个按下组尚未收到释放时发生失焦、焦点代次改变、目标丢失或会话停止，
原始 `KEY_DOWN`／`MOUSE_BUTTON_DOWN` 仍保留，中断原因另存为诊断证据；系统不会
补造 `KEY_UP`／`MOUSE_BUTTON_UP`。因此该时间线仍是不完整观测，后续编译为输入
方案时必须拒绝，不能把诊断证据当作释放事件。

两个实验的失焦语义有意不同：

- 独立 `Input Capture Lab` 是持续被动观测实验：目标失焦后暂停接纳，清理未闭合
  组；目标再次稳定成为精确前台后以新的 `focus_epoch` 恢复；
- `Input Execution Lab`（输入执行实验）内嵌的手动录制是一次性方案采样：一旦
  已经激活过，随后首次失去精确前台就结束该次录制，不在同一次录制中恢复。

这一区别属于宿主策略，不表示后一种目标窗口更不兼容，也不能据此判断反作弊。

## DPI 与坐标解释

项目 GUI 在创建 `QApplication` 前请求 Per-Monitor V2 DPI awareness
（每显示器 V2 DPI 感知）；只有诊断同时确认
`NATIVE_PHYSICAL_PIXELS` 时，窗口客户区和 Win32 坐标才按原生物理像素解释。
若外部宿主提前创建了 GUI/窗口或设置了其他 DPI 策略，被动捕获可以继续，但坐标
证据必须保留实际坐标空间或 `UNKNOWN`，不能强行标成原生物理像素。
在当前 4K、Windows 缩放 `200%`、目标窗口 DPI `192` 的本机只读观测中，同一个
游戏客户区：

- 由 Per-Monitor V2 感知进程读取为 `1920×1080`；
- 由 DPI-unaware（DPI 不感知）进程读取时可能被 Windows 虚拟化为 `960×540`。

这里的 `960×540` 是调用方坐标空间被等比虚拟化后的结果，不等于游戏实际渲染
分辨率，也不能单独解释截图、录制或输入是否成功。GUI 诊断会同时显示目标 DPI、
缩放比例、调用线程 DPI 感知级别、坐标空间和客户区，诊断失败时显示
`UNKNOWN`，但不会为了得到一个数值改变进程 DPI 策略。

## 数据与语义边界

默认运行：

- 只使用进程内有界队列和 GUI 有界表格；
- 不保存截图；
- 不写输入 JSON、JSONL、CSV 或日志文件；
- 不自动写结构化诊断或 DPI 探测结果；
- 不提供导出按钮；
- 不上传、不联网；
- 停止或关闭 GUI 时停止监听并释放后端。

`InputCaptureEvent` 只证明监听后端在门禁通过时观察到一个输入回调。它不能证明：

- Windows 已把事件投递给目标窗口；
- 游戏逻辑已经消费该输入；
- 对应按键绑定、点击控件或人物动作成立；
- 某个画面变化由该输入造成；
- 按键监听完整无丢失。

因此 `delivery_status` 第一版只能为 `UNKNOWN`。未来若要建立输入与画面变化的
关系，必须使用同一时间线上的后续视觉证据和独立验证，不能在本实验内直接晋升为
确认状态或因果关系。

## 权限、隐私与反作弊边界

`pynput` 在 Windows 上安装系统级键鼠监听。应用层的前台窗口门禁限制的是
“哪些回调可以进入 WorldTrace 实验数据”，并不改变系统监听器本身是全局安装的
事实。

第一版约束：

- 不自动申请管理员权限；
- 不注入目标进程，不读游戏内存，不安装驱动，不绕过反作弊；
- 不承诺能够监听高完整性、受保护或独占输入程序；
- 不建议对在线竞技游戏、带严格反作弊的游戏或敏感输入窗口进行测试；
- 不以管理员身份运行来扩大监听范围；
- 只对用户明确选择的测试窗口启动会话；
- 测试过程中不要切换到密码、支付、聊天等敏感窗口后继续输入。

前台过滤是降低误收集风险的第一道门禁，不是安全隔离或反作弊规避措施。若目标
程序的使用条款禁止全局输入钩子，应停止使用本实验。

## 启动

先在项目虚拟环境安装独立实验依赖：

```powershell
cd D:\Games\worldtrace_workspace\worldtrace
..\.venv\Scripts\python.exe -m pip install `
  -r environment_specs\input_capture_lab-requirements.txt
```

启动独立 GUI：

```powershell
..\.venv\Scripts\python.exe -m experiments.input_capture_lab
```

建议使用记事本、画图或自建测试窗口作为首轮目标：

1. 刷新窗口列表并选择目标；
2. 点击“开始监听”；
3. 切换到目标窗口，等待状态从“稳定等待”变为“已激活”；
4. 在目标窗口内执行少量键盘按下/释放和鼠标点击；
5. 切回 GUI 查看中文事件表、门禁状态和过滤计数；
6. 点击“停止监听”，确认监听线程退出。

若 GUI 提供“记录滚轮”开关，首轮默认关闭；只有显式启用后才验收滚轮事件。

## 第一版验收矩阵

| 场景 | 操作 | 期望结果 | 不得出现 |
| --- | --- | --- | --- |
| 未选择窗口 | 点击开始 | 开始按钮不可用或给出明确提示 | 启动全局记录会话 |
| GUI 位于前台 | 选择目标后点击开始 | 状态为等待目标前台 | 启动按钮点击进入事件表 |
| 目标刚取得前台 | 立即按键或点击 | `200 ms` 稳定期内只增加过滤计数 | 焦点获取动作成为事件 |
| 目标稳定位于前台 | 按下并释放普通按键 | 形成同组 `KEY_DOWN / KEY_UP`，释放带持续时间 | 宣布输入已送达 |
| 目标稳定位于前台 | 在客户区内按下并释放鼠标按钮 | 记录屏幕、客户区、归一化坐标并正确配对 | 记录移动轨迹 |
| 拖出客户区释放 | 客户区内按下，客户区外释放 | 同组释放标为 `RELEASE_OUTSIDE_CLIENT` | 释放后留下未闭合按压组 |
| 客户区外点击 | 在目标客户区外独立点击 | 只增加过滤计数，不保留点击详情 | 坐标或按钮进入表格 |
| 切到其他窗口 | 在其他窗口输入 | 暂停接纳，只增加非前台过滤计数 | 其他窗口输入详情进入 DTO、队列或表格 |
| 按住时失焦 | 按下后切离目标再释放 | 原按压组计为不完整；释放不与旧组配对 | 伪造释放或跨焦点代次配对 |
| 再次切回目标 | 等待稳定后输入 | `focus_epoch` 递增并建立新组 | 复用上一焦点代次 |
| 滚轮关闭 | 在客户区滚动 | 只增加“滚轮关闭”过滤计数 | 滚轮事件进入表格 |
| 滚轮开启 | 在客户区滚动 | 记录非零滚轮增量和三套坐标 | 记录鼠标移动 |
| 目标最小化 | 继续操作 | 会话暂停接纳；恢复同一窗口并重新稳定后进入新焦点代次 | 使用最小化前的旧客户区继续接纳 |
| 目标关闭或身份改变 | 继续操作 | 会话进入目标丢失／失败并停止监听 | 按标题自动绑定其他窗口 |
| 队列达到上限 | 人为制造消费者滞后 | 明确增加丢弃计数，时间线标记不完整 | 静默声称事件完整 |
| 停止或关闭 GUI | 结束会话 | 监听器释放，之后不再产生事件 | 后台残留监听继续收集 |

测试窗口上人工完成。

## 第一版以后的方向

完成本实验并不意味着 `InputRecorder` 可以直接定型。进入 Trace Core 前至少还要
分别验证：

- 与截图 `FramePacket` 的同一单调时钟和会话身份对齐；
- Windows Raw Input 等后端的能力、权限与丢失语义；
- 重复按键、组合键、IME、鼠标捕获和独占输入边界；
- 长时间运行的事件完整性、回压和终止清理；
- 明确授权后的易失证据保存与隐私策略；
- 输入观测和后续画面变化之间的独立关联验证。

在这些问题解决前，本模块仍是 `InputRecorder` 的前置实验，不是正式记录器。
