# Minimal Trace GUI（最小闭环实验）

这是一个与 `Frame Inspector` 分离的独立桌面 GUI。它只验证第一条纵向闭环：

```text
选择目标窗口
-> CaptureSession 连续采集
-> FramePacket 有界内存队列
-> 稳定画面判定
-> 严格视觉去重 / OCR 灰区核验（可选）
-> 仅保存稳定且未重复的原始关键帧 PNG + JSON

同一内存帧 -> 固定 HUD 候选旁路（可选）
-> 320x180 相邻帧差 + 稳定锚点差 -> 仅在大变化后打开有界重 CV 窗口
-> 背景运动门禁 -> 屏幕固定点轨迹 -> 双窗口确认
-> 会话内数量/位置/视觉目录 -> 稀疏保存原分辨率裁剪 PNG + 点位 JSON
-> 异步 SAM 掩码预览 -> 人工接受为 PROVISIONAL 模板
-> 后续大变化重新稳定 -> 归一化位置 + 掩码模板匹配
-> PRESENT / ABSENT / UNKNOWN 存在性候选

同一内存帧 -> 屏幕固定 UI 锚点发现旁路（独立实验）
-> 固定 320x180 画布 -> 大范围世界运动门禁
-> 稳定边缘在运动邻域内累计有效支持
-> 跨至少两段运动、两个方向达到默认 50 次支持
-> 有界首次精修 -> 仅保存一次 PROVISIONAL 初始基线
-> 同一次实验运行内持续跟踪当前掩码，按可靠证据动态增加或减少
-> 用户可冻结点击瞬间的当前掩码与同帧源图，做源帧坐标复核或顺序运行 SAM 内存预览
```

它不会启动 Frame Inspector 的线性处理面板、双 OCR 对比或时序模型会话，也没有“手动保存当前帧”入口。只有勾选“RapidOCR 灰区语义去重”后，视觉灰区候选才会调用现有 CPU RapidOCR 节点；不会运行 PaddleOCR 或 LLM。固定 HUD 旁路可对已经成功保存的候选异步调用现有 SAM2 节点，但只有人工接受的掩码才会成为临时模板；UI 锚点页另有显式的“源帧掩码覆盖”和“逐掩码 SAM 预览”按钮，前者只核对画布到源帧的坐标，后者只生成可切换的内存复核结果，二者都不登记模板。两类 SAM 结果都不参与 OCR、关键帧判定或关键帧去重。

## 运行

从 `worldtrace` 仓库目录运行：

```powershell
..\.venv\Scripts\python.exe -m experiments.minimal_trace_gui
```

可指定关键帧输出根目录：

```powershell
..\.venv\Scripts\python.exe -m experiments.minimal_trace_gui `
  --output-dir D:\Games\worldtrace_workspace\runtime_data\minimal_trace_gui
```

默认输出位于外层工作区：

```text
runtime_data/minimal_trace_gui/
├── sessions/<scope_id>/keyframes/
│   └── kf-000001/
│       ├── frame.png
│       └── metadata.json
├── hud_candidates/<scope_id>/
│   ├── hud-candidate-000001/
│   │   ├── crop.png
│   │   └── metadata.json
│   └── hud-candidate-000002/
│       ├── crop.png
│       └── metadata.json
├── hud_templates/<scope_id>/
│   └── hud-template-.../
│       ├── template.png
│       ├── sam_mask.png
│       ├── recognition_mask.png
│       └── metadata.json
└── ui_anchor_candidates/<scope_id>/
    └── ui-anchor-000001/
        ├── reference.png
        ├── stable_mask.png
        └── metadata.json
```

普通采集帧、UI 锚点支持样本、分析缩略图、光流轨迹、差异图和重复稳定帧均不写盘。关闭“仅保存稳定且会话内未重复的关键帧”后，新关键帧仍会在 GUI 中显示但不落盘；固定 HUD 候选有独立开关，默认每次运行最多保存 `20` 份去重后的裁剪证据，也可在详细参数中指定 `1..1000` 或选择“不按条数限制”。UI 锚点也有独立开关，只在候选首次达到晋升条件时保存一次 `PROVISIONAL` 初始基线；后续动态掩码 revision 只驻留内存，不重复落盘。

## 参数入口

主窗口保留最常调整的稳定时间、稳定比较次数、像素差、稳定变化率和历史重复率。点击“详细参数…”可在五个标签页调整：

- 稳定检测：分析/缩略图尺寸、稳定均值差、采样间隔、离开稳定画面的阈值、WGC 静默确认。
- 视觉去重：严格重复与 OCR 灰区的 pHash/MAE 阈值、OCR 参照邻居数、单关键帧别名数、视觉目录容量。
- OCR：最低置信度、文字框容差、worker/候选超时、输入最长边、参照帧缓存数量与内存预算。
- 图标记录：记录数量、近似视觉/同点位去重、固定画布、采样频率、光流运动门禁、固定轨迹、点簇大小、双窗口确认和裁剪边距；还可设置双帧差变化触发窗口、SAM 设备/响应上限，以及模板数量、位置搜索半径、步长和三态分数阈值。该页使用滚动区域，参数仍全部属于下一次启动。
- UI 锚点发现：默认 `50` 次有效支持、采样/证据断档时间、像素稳定与世界变化阈值、光流/网格门禁、一致运动模型内点比例、画布边侧覆盖、运动阶段与方向多样性、稳定核心和候选面积预算。还可独立开关第一轮“半透明固定形状”通道，并调整低对比边缘、长期梯度方向一致度、局部变化衰减和支持率。首次晋升前的有界精修仍可设置启用、最多有效观察、连续无新增转段次数和相对原始种子的最大扩展半径；进入动态跟踪后，默认同一像素连续 `2` 次正命中才加入当前掩码，连续 `8` 次可靠缺失才删除。分析画布固定为 `320x180`。

对话框采用“保存后生效”的事务方式：取消不会修改当前配置，“恢复默认”只重置尚未保存的表单；参数仅保存在本次 GUI 进程内，不写入磁盘，并且运行期间不能修改。OCR 开启时，严格重复保护线仍自动跟随稳定判据，避免高级参数绕过小文字/数字变化核验。

图标高级参数仍受运行预算硬限制：固定画布最多 `640x360` 像素、采样最快 `10 Hz`、角点最多 `1000`、聚类半径最多 `16 px`，单次确认批次最多 `64` 个候选。候选保存还固定保留默认 `10 s` 且不得低于 `1 s` 的批次写入间隔、`4096` 条轻量目录上限、`512 MiB` 本次运行产物预算、`4 MP` 单裁剪像素上限、`16 MiB` 单 PNG 上限和 `2 GiB` 磁盘剩余空间。选择“不限”只取消候选条数额度，不会取消这些资源保护。

## 内存与线程边界

- 复用中立共享层 `experiments.capture_runtime.session.CaptureSession`；旧 Frame Inspector 也通过兼容入口使用同一实现，但本 GUI 不导入 `frame_inspector` 包。
- 后端构造、打开、取帧、停止和关闭仍在同一个采集线程。
- `FramePacket.image_buffer` 是后端已交付的不可变 CPU `bytes`；采集到检测、检测到 GUI 预览都通过有界队列传递，不创建普通帧临时文件。
- 关键帧检测和 PNG/JSON 编码位于独立工作线程，不阻塞采集线程或 Qt GUI 线程。
- OCR 默认关闭；关闭时不构造 OCR session、模型执行器或隔离 worker。
- OCR 开启时，灰区候选在独立 OCR 线程中按单请求执行，当前帧与懒加载参照帧共享默认 `20 s` 截止时间；每次识别返回后都会再次核对截止时间，预处理后也会按剩余时间设置 worker 响应上限。输入先按长边最多 `1600` 等比缩放，再通过 `SharedFramePool` 发布到现有 RapidOCR 隔离 worker；不生成 OCR 输入临时图片、转录 JSON 或 overlay。模型执行器仍可能写入 `runtime_data/model_nodes/logs/` 诊断日志。
- OCR 等待期间，检测线程继续消费帧并更新预览，但不会把新帧再次交给仍有 pending candidate 的检测器；只保留一份 latest deferred frame。
- 图标旁路不直接读取采集队列。关键帧线程消费一次 `FramePacket` 后，使用非阻塞 latest-only 队列把同一不可变帧引用交给独立 CV worker，因此不会与关键帧抢帧；旁路拥塞时只丢旧的待分析帧。
- UI 锚点旁路使用同一 fan-out 边界和自己的 latest-only worker；它在 OCR pending 期间仍收到检测线程已经消费的帧。常驻状态是固定画布上的有界计数/掩码数组、一张前帧，以及每个已晋升候选的当前动态掩码和有限连续证据计数；不保存逐帧证据或历史 revision。
- 图标旁路与 UI 锚点旁路职责隔离：前者自动发现、保存并提交固定 HUD 视觉候选；后者只累计屏幕坐标固定的 UI 结构区域，不自动调用 SAM、模板匹配或 OCR。用户显式点击后的源帧覆盖与逐掩码 SAM 都是独立的人工复核桥，不会反向修改发现累计或候选生命周期。
- 静止阶段只保留前一张与稳定锚点两张 `320x180 GRAY8` 小图，默认按 `5 Hz` 计算相邻差和锚点差；普通变化需连续且覆盖足够网格，强变化可立即唤醒。只有 `ACTIVE_SCAN` 窗口才运行光流候选检测，窗口默认最多 `4.5 s`，命中或超时后冷却。
- 图标 CV 确认窗口只先保留轻量几何匹配和一份源帧，再逐个构造、判重、保存并释放当前 crop；不会在数量额度生效前一次复制整批源分辨率裁剪。常驻状态仅含两张门控小图、前一 CV 采样、最多 `600` 条数值轨迹、latest-only 预览，以及已落盘候选的小型几何/`32x32` 灰度签名，不保存逐帧截图或轨迹 JSONL。启动、分析或普通保存异常进入 `DEGRADED`；触及资源保护则以 `RESOURCE_LIMIT_REACHED` 正常结束 HUD 旁路，两者都不停止采集、OCR 或关键帧线程。
- 自动 HUD SAM 只接收成功持久化且未去重的候选 crop；手动 UI 锚点 SAM 则冻结点击时的 `frame_id/scope_id` 和当时的动态 mask revision，在 `320x180` 上对 progress/refinement/tracking/candidate 掩码做同批空间去重，把直接核心的正点、紧框和阶段容器宽框映射回同一源帧，再加外层 guard 形成源分辨率 crop。两条路径都通过共享内存传给隔离 worker，模型输出使用易失内存；第一遍自动选 mask index，第二遍锁定同一 index 取二值 mask 与 overlay。UI 锚点批次在独立单工作线程中复用一个 provider 逐项执行，单项失败不会覆盖或跳过其余项，也不会阻塞 Qt 线程；若固定 HUD 自动 SAM 正随采集启用，手动批次会等到采集停止后才允许启动，避免同一设备并发加载两份模型。这里冻结的只是一次人工任务的输入一致性，后台检测与主预览仍继续接收后续动态 revision。
- 模板匹配仍在 HUD worker 中执行，但同一次画面变化 epoch 最多运行一轮。默认最多激活 `8` 个模板、位置搜索步长 `4 px`；匹配期间 latest-only HUD 帧可被替换，不阻塞采集或 Qt 线程。
- 预览和分析均为 latest-only；实时预览额外限制为最多约 `10 FPS`，稳定性描述的是检测线程实际消费到的采样，不声称覆盖所有捕获尝试。

## 第一版固定 HUD 候选记录规则

1. 开关默认关闭；开启时强制关闭 WGC 鼠标指针捕获，避免把静止鼠标当成 HUD 候选。
2. 源帧只在内存中等比缩放并 letterbox 到默认 `480x270` 固定画布；点位同时记录画布、源帧和最终 crop 三套坐标映射。
3. 默认每 `200 ms` 采样一次，使用最多 `600` 个 Shi–Tomasi 角点和双向 LK 光流；正反跟踪误差超过 `1 px` 的轨迹直接淘汰。
4. 相邻采样至少有 `80` 条有效轨迹，且至少 `35%` 的轨迹移动 `1.25 px`，并覆盖默认 `4x3` 画布网格中的至少 `7` 格，该转换才算“世界背景在移动”。一个八帧窗口至少五次转换满足此条件才开门，局部粒子或单侧动画不能单独放行。
5. 在合格运动窗口内，相对起点最大半径不超过 `1.5 px`、累计路径不超过 `3 px` 的轨迹才视为屏幕固定点；固定点按空间距离聚类并过滤过小、过大和极端宽高比区域。候选周围默认 `24 px` 邻域还必须存在足够的移动轨迹，避免把另一块静止世界纹理当成 HUD。
6. 两个连续、互不复用转换的运动窗口中，候选框同时满足默认 `IoU >= 0.35`、中心距离 `<= 6 px` 才自动确认；前后窗口使用稳定排序的一对一匹配，同一对窗口可输出多个互不争用的确认候选。
7. 从当前原始彩色帧按映射框直接裁剪，不保存整帧；`metadata.json` 写入两段窗口证据、完整参数、源帧身份、半开区间 bbox、确认点簇，以及位于 crop 内的推荐 SAM 正点。点簇数量受 `max_corners` 硬上限约束，不产生逐帧无限日志。
8. 确认批次先经过本次运行内的目录判定；重复候选不落盘、不消耗数量额度。同一确认批次中的多个候选会逐个处理，后续新确认批次受默认 `10 s` 写入冷却约束。成功原子提交 `crop.png + metadata.json` 后登记轻量目录并继续检测，达到有限额度或资源保护阈值时只结束 HUD 旁路。GUI 始终显示最近一份带红圈正点的已记录裁剪。

这里的产物严格命名为“固定 HUD 候选”，不是已经识别出语义的游戏图标。准星、水印、固定文字、静态角色轮廓等都可能满足同一视觉条件；第一版的目标是验证低频发现、点位积累与稀疏落盘闭环。

## 第一版屏幕固定 UI 锚点发现规则

1. 主界面的本轮验证开关默认开启。只有 `Freshness.NEW` 且达到采样间隔的帧进入固定 `320x180` 分析画布；WGC 鼠标指针捕获会在该旁路开启时强制关闭。
2. 相邻帧必须同时满足全局变化率、均值差、运动网格覆盖和一致的全局光流模型。RANSAC 仿射模型使用全部有效轨迹拟合，而不是只在已移动轨迹中挑一个局部模型；模型中的移动内点默认还要触及画布内容边界的四侧，模型内点比例至少 `45%`。强变化只作为界面切换诊断，不得绕过该全局运动门禁。镜头静止、全屏亮度闪烁，或只在局部大面板内一致平移时不推进发现或动态增删计数。
3. 固定证据分成两个互不相加的通道。原有不透明通道仍只给“两帧都有边缘且像素差不超过稳定阈值”的点投票；实验性的半透明形状通道允许图形像素随背景改变，但要求低对比边缘长期保持相近方向、该点变化明显弱于外围运动环带，并把整个已通过门禁的运动邻域作为支持率分母。两通道各自达到门槛后才合并核心，不能用同一帧的两票提前凑满 `50` 次支持。动态文字或数值可以改变，但不会反向删除发现阶段已经积累的历史支持；进入 tracking 后，只有连续可靠缺失才能减少当前活动掩码。
4. 支持达到最低显示门槛后，“UI 锚点”页会在整张分析帧上显示纯内存调试投影：青色虚线是较宽的临时证据范围，琥珀色半透明区域是不透明稳定核心，紫色半透明区域是形状通道核心，绿色实线只表示本帧首次晋升的 `PROVISIONAL` 基线；进入 tracking 后，主预览会持续用当前活动掩码、本次新增和本次移除覆盖最新采样，并显示候选 ID 与 revision。紫色只说明“由半透明形状规则提供证据”，不代表算法恢复了真实 alpha 或确认了图标语义。`R1/R2/...` 只是当前 scope 的本次证据累计生命周期内用于观察同一区域变化的临时编号；scope 或证据 TTL 重置后会重新编号，也不会进入候选 ID、元数据或任何落盘目录。
5. 每个临时证据区显示支持数、支持率、独立运动阶段、分离方向、核心面积/最短边/最大包围框等几何门槛，以及当前阻塞原因和“证据完成度”。完成度是这些晋升证据门槛完成比例的保守最小值，不是统计学置信度，也不能单独把证据区升级为候选。没有有效世界运动时，预览会明确显示门禁状态和原因；世界暂时静止但已有累计时，区域与当前动态掩码只保持原值、不推进，不解释为 `ABSENT`。
6. 两个通道都默认要求 `support_count >= 50`、来自至少两段独立运动并覆盖至少两个明显分离的运动方向；不透明通道支持率默认 `>= 90%`，半透明形状通道支持率默认 `>= 60%` 且长期梯度方向一致度默认 `>= 85%`。方向内部使用 16 个环形桶，并把相邻桶视为同一方向邻域，避免在桶边界附近用几度抖动伪造“第二方向”。
7. 默认开启有界首次精修。首次达标核心先作为内存种子，之后最多再处理 `20` 次通过世界运动门禁的观察；新像素仍须通过累计支持、支持率、运动阶段、方向多样性和对应通道的一致性门槛，并且只能位于“原始种子膨胀 `4 px`”形成的固定区域内、与种子方向连通。增长范围不会围绕新增像素递归膨胀。连续 `5` 次有效观察没有新增或达到观察上限，只表示首次精修结束并生成一份 `PROVISIONAL` 基线，不再表示检测掩码冻结；关闭精修开关时，首次达标核心会直接作为基线进入动态 tracking。
8. 基线进入 tracking 后仍沿用同一候选 ID 和固定有界容器，但公开的 `active_mask` 可在整次实验运行内持续增加或减少。默认某像素连续 `2` 次得到普通/半透明通道的正命中后才加入；当前活动像素只有在连续 `8` 次满足“本帧可判断、像素发生明显变化、且两个正证据通道都未命中”的可靠缺失后才删除。门禁失败、像素不可判断或其他未知证据既不删除像素，也不把未知解释为 `ABSENT`；正证据恢复会重置该像素的删除累计。内部首次基线只用于位置归属与连通约束，不是不可删除的显示掩码。
9. 主预览是 latest-only 动态视图。tracking 区域持续显示当前活动像素、本 revision 新增/移除像素、候选 ID、revision 和活动像素数；掩码没有实际增减时 revision 不变。它不会为每一版保留历史数组，也不会因为某次导出或 SAM 任务启动而停止接收新观察。
10. 首次达标产物固定为 `PROVISIONAL UiAnchorCandidate`，只原子保存一次 `reference.png`、初始基线 `stable_mask.png` 和 `metadata.json`，目录仍严格只有这三个文件。这里的 `stable_mask.png` 是进入 tracking 时的发现证据基线，不是运行结束时的“最终掩码”；后续动态 revision 不覆盖它、不新建候选目录，也不重复触发候选记录事件。`screen-locked-motion-vote-anchor.v4` 元数据仍明确声明它不是 UI 状态、不是图标身份、也不是可执行控件。
11. 本实验不尝试判断或切分“同一个 UI 状态”的开始与结束；从候选首次晋升到本次实验停止，都视为同一次动态 tracking 生命周期。GUI 的 `n/target` 仍只表示发现阶段的有效运动支持数，不是普通帧数或状态置信度；`target` 可在详细参数中修改，默认是 `50`。
12. “导出当前掩码可视化…”按钮只在当前 scope 已收到预览后启用。它由用户显式选择路径，将点击瞬间的原始 `320x180` 整帧调试投影无损保存为 PNG，而不是保存界面缩放后的 `QLabel` 截图；输出可以包含证据框、首次精修层、当前 tracking 掩码、本次增减和状态文字，但不是候选基线文件。取消对话框不会写文件，scope 重置会立即清除旧快照并禁用按钮；停止采集后仍可导出最后一份有效预览。导出只冻结点击瞬间的图像身份，后台动态 tracking 不会因此暂停。
13. “源帧掩码覆盖”只在当前预览同时持有原始分析画布、同 `frame_id` 源 `FramePacket` 和至少一个有效掩码时启用。点击冻结当前快照，把 `progress` 的不透明/半透明核心、`refinement` 的种子/新增、`tracking` 的当前/本次新增/本次移除以及一次性 `candidate` 基线按与分析输入相同的 FIT/letterbox 关系映射回源分辨率，在独立“源帧覆盖”标签页着色显示。生成覆盖图本身不使用带文字的调试投影、不包含 `volatile_mask`、不调用 SAM、也不自动写盘；新帧到达不会替换已经生成的这次人工复核结果，但主预览和检测仍继续前进。标签页内的“导出覆盖图…”只在已经生成结果后启用，可由用户显式把这一张源分辨率覆盖图保存为无损 PNG；导出点击绑定当时的图、`frame_id/scope_id` 和 mask revision，不会因文件对话框期间到达新 revision 而错配。源帧超过固定像素预算时保守拒绝本次预览，避免在 Qt 点击线程为 8K 画面分配过量内存。
14. “逐掩码 SAM 预览”只在当前预览同时持有原始分析画布、同 `frame_id` 源 `FramePacket` 和至少一个可用直接核心时启用。点击会冻结当时的帧和 mask revision，再按 `tracking > candidate > refinement > progress` 跨阶段去重，同阶段相邻目标仍各自保留；`volatile_mask`、带文字方框的调试投影和推测填充区都不会作为 SAM 正点。单批默认最多保留优先级最高的 `8` 个目标，单 crop 最多 `4194304` 像素、全部 crop 合计最多 `8388608` 像素，超过预算的数量会在界面明确显示。新“锚点 SAM”标签页预先列出所有提示框，随后逐项显示 `SUCCEEDED/FAILED/UNKNOWN`、QA、score 和 overlay；下拉框可来回切换，结果不落盘、不登记模板、不宣布 UI 状态。scope 重置会异步取消旧批次并拒收其迟到结果。一次 SAM 批次冻结输入只用于帧、提示和结果一致，不会冻结后台检测或之后的动态 revision。
15. 随背景一起移动的世界标记不会获得持续的屏幕固定支持。scope 改变会清空不再可映射的发现、首次精修和动态 tracking 内存；超过普通最大采样间隔但不超过证据 TTL 的短断档只重建相邻比较基线。默认连续断档超过 `300000 ms`（5 分钟）会清除尚未晋升的累计并重置动态增删的连续计数，但保留同 scope 当前活动掩码，避免把断档本身误当作可靠缺失。候选序号只在首次发出基线时分配，并在本次运行内始终单调。

## 变化触发、SAM 登记与模板核验

1. 门控固定使用 `320x180` 灰度小图，同时比较相邻采样和最近稳定锚点。默认普通变化为 `6%` 或均值差 `1.5`，还需覆盖 `4x3` 网格中的至少 `6` 格并连续出现两次；`15%` 或均值差 `8.0` 的强变化立即打开扫描。
2. 重 CV 窗口默认最短 `3.2 s`、最长 `4.5 s`。画面连续三次回到 `1% / mean 0.5` 以下、达到最短窗口后结束；检测到候选则提前进入较长冷却。没有变化时不会运行光流候选检测。
3. 候选只有在去重、资源检查和 `crop.png + metadata.json` 原子提交都成功后才提交 SAM。SAM QA 检查正点覆盖、mask 面积、选择框重叠、中心漂移和是否触边；`REJECTED` 不能登记，`READY/NEEDS_REVIEW` 仍必须由用户点击“登记为临时模板”。
4. 人工接受后原子保存 `template.png`、原始 `sam_mask.png`、默认膨胀 `2 px` 的 `recognition_mask.png` 和元数据。状态固定为 `PROVISIONAL`，不赋予语义标签。
5. 每次大变化之后，只有画面重新连续安静时才按模板原归一化位置做一次有限尺度/位置搜索。分数达到默认 `0.88` 输出 `PRESENT`，低于等于 `0.55` 输出 `ABSENT`，中间区间或资源/输入问题输出 `UNKNOWN`。
6. `PRESENT` 只表示“这个像素模板在该约束位置附近存在的候选证据”；`ABSENT` 只表示本次约束搜索低分。二者都不能单独升级为“某个游戏界面已经确认/不存在”。
7. 当前模板 scope 包含 capture session，因此运行时自动匹配只验证本次运行内刚登记的模板。文件会保留供审计，但跨运行复用需要后续另定义不含 session 的目标兼容键，本轮没有暗中放宽。

## 图标候选数量与去重

- 数量额度按一次“开始”到“停止”累计，只统计去重后且成功原子提交的唯一候选；确认失败、冷却跳过、重复跳过和写入失败都不占额度。`None` 表示“不按条数限制”，不是无限队列、无限磁盘或跨重启运行。
- “近似视觉去重”默认开启。它先在同一分析 scope 的默认 `16 px` 半径内查找已记录候选，再从不含 padding 的紧致 selection 生成 `32x32` 灰度签名；只有 `pHash` 距离和 ±2 px 对齐后的归一化 MAE 同时达标才跳过。判断偏保守，不把它描述成语义图标识别。
- “同点位去重”默认关闭。它使用候选框中心距离与 bbox IoU 联合判断，同一槽位即使外观改变也会跳过；若要保留技能亮灭、角色切换或同位置新增图标等变体，应保持关闭。
- 两种去重只与已经成功保存的候选比较。若同时开启，同点位判定优先；同点位未命中后才做近似视觉判断。
- 当前目录按 `scope_id` 分区且仅存在于本次运行内。程序重启、目标代次、分辨率或图标分析策略变化后不读取旧目录做跨运行压制，宁可多保存，也不拿旧布局误删新证据。
- 主界面显示“原始确认 / 冷却批次 / 同点位重复 / 视觉重复 / 保存 x/N”；`LIMIT_REACHED` 与 `RESOURCE_LIMIT_REACHED` 都是 HUD 旁路的正常终态，不影响关键帧、OCR 或采集。

## 第一版稳定与去重规则

1. 原始帧只在内存中缩放为最多 `320x180` 灰度图，并做 `3x3` 模糊。
2. 小于等于默认 `12` 灰度级的像素差先归零，再同时比较相邻采样和当前稳定锚点；默认变化像素不超过 `1%`、阈值后灰度均差不超过 `0.50`。
3. 默认至少完成 `3` 次稳定比较且持续 `600 ms`，才生成稳定候选。
4. WGC 是事件驱动后端；收到 `WAITING/TIMEOUT` 后若 `600 ms` 没有新画面事件，可用 `SOURCE_QUIESCENCE` 作为稳定证据。其他后端的超时不会自动视为稳定。
5. 每个稳定阶段只判定一次。连续出帧时，画面相对该稳定代表帧连续两次明显改变后，检测器才重新寻找稳定状态；WGC 若只交付一个明显变化帧后再次静默，则这段静默可同时证明旧阶段结束和新画面静止。
6. 稳定候选使用灰度缩略图、64 位感知哈希和归一化误差，与本次采集 scope 的内存签名库比较；OCR 关闭时，默认严格重复阈值为 `pHash <= 6`、变化像素 `<= 2%`、归一化 MAE `<= 3%`。
7. OCR 开启时，严格重复的变化面积与均值差异保护线都在原 `320x180` 分析图上收紧到稳定判据（默认 `1%` / `0.5` 灰度级），锁存画面也在同一分析空间、从同一组阈值开始重新确认，避免细文字/数字在缩略图下采样后被平均掉。超过任一保护线但缩略图仍满足 `pHash <= 8`、变化像素 `<= 4%`、归一化 MAE `<= 4%` 的候选进入灰区核验；明显新画面直接保存，不运行 OCR。
8. 灰区首次比较会从近期 canonical 关键帧的有界内存缓存中懒加载参照 OCR，再识别当前候选。NFKC/空白/大小写归一化后的整页文字与布局均相容时，当前视觉签名作为原关键帧的别名加入目录但不落盘；数字变化默认视为有效变化。
9. 空 OCR、低置信度、无效文字框、参照帧已淘汰、超时、异常或停止取消都属于 `UNKNOWN`，一律保守保存，不能据此删除证据。
10. 默认视觉目录保留最近使用的 `512` 个签名（canonical 与视觉别名都计数），且每个 canonical 最多保留 `8` 个别名，避免单个粒子/光效界面冲刷整个目录。已核验的动画变体再次出现时通常不再调用 OCR；超过容量后按 LRU 淘汰。

这些阈值是首轮实验默认值，不是正式游戏事实规则。GUI 会显示实时变化比例和稳定证据，后续应使用真实录制数据标定。

## 当前边界

- 关键帧去重只覆盖当前 `(capture session + target + 尺寸 + policy revision)` scope；程序重启后不会读取旧图库做跨会话去重。
- 保存的是稳定确认时的原始 `FramePacket`，不是 `320x180` 分析图。
- 每个关键帧的 PNG 与 JSON 先在同一临时目录完整生成，再通过一次同卷目录重命名提交；同一 `(scope_id, keyframe_id)` 重试会校验并返回原文件对，不重复落盘。
- 持久化失败时只锁存当前稳定阶段，不把失败候选注册为 canonical；画面离开后再次返回时仍可重试保存，不会让后续重复项指向不存在的文件。
- 会话内视觉签名图库有 `128 MiB` 策略预算上限，默认最多保留 `512` 个低分辨率签名。
- OCR 开启时额外保留最多 `16` 个、合计不超过 `128 MiB` 的近期 canonical 原始 `FramePacket`，只用于灰区首次懒核验；得到可用指纹后立即释放该原始帧，只保留小型 OCR 指纹。缓存缺失时保守保存。OCR 指纹与决策当前只在本次会话内存在，不写入关键帧 sidecar。
- 持久化在关键帧工作线程中同步完成，不阻塞采集线程或 GUI；异常慢磁盘会暂停新的稳定判定，关闭窗口只做有界等待。若以后允许网络盘，应再拆独立写入队列和恢复协议。
- 当前 OCR 语义仍只覆盖文字与文字框布局。固定 HUD 候选、SAM 掩码和模板存在性结果不进入 OCR 或关键帧目录，也不改变关键帧保存率。模板晋升、跨运行兼容、多个图标组合成界面状态及形状模型核验仍属于下一阶段。
- UI 锚点候选同样不进入关键帧、OCR、图标模板或正式状态目录。源帧覆盖只验证点击瞬间的坐标投影，手动逐掩码 SAM 只把该 revision 的当前掩码当作提示来源；二者都只保留易失复核结果且不回写动态 tracking。当前仍只验证“世界在动、区域屏幕固定、首次基线后持续增删”，不识别 UI 状态边界，也不输出 `GAMEPLAY_HUD PRESENT/ABSENT/UNKNOWN` 或 `StateSnapshot`。
- 首次精修和动态增删的观察数都只统计通过世界运动门禁且对应像素具备有效证据的帧，因此 `5` 次无新增、`2` 次加入或 `8` 次可靠缺失在实际墙钟时间上都可能明显更长。录制或采集在首次精修完成前结束时，内存种子不会作为半成品写盘；首次基线已经保存后，停止前最后一版动态掩码也不会被误称为最终产物或自动覆盖基线。固定增长区还可能认领距离很近的小型相邻核心，使其并入现有候选或暂时没有独立轨迹；本轮保持该保守位置归属行为，不把它解释成两个图标已经属于同一语义对象。
- 图标候选按当前 capture session、目标、尺寸、像素格式和图标策略形成独立 scope；任一上下文变化都会清空未完成窗口，不能跨分辨率或窗口代次拼接证据。
- 图标候选 `metadata.json` 使用 `worldtrace.hud_candidate.v2`，记录有限/不限模式、实际目录策略和检测参数；同一 candidate ID 的存储重试仍会逐像素与逐字段校验，不把路径幂等误称为候选去重。
- “不限”模式仍受固定资源预算保护；达到目录、会话字节、单裁剪、单 PNG 或磁盘余量阈值时不会把它当作程序错误。当前写入仍是独立 HUD worker 内的同步原子提交，停止请求可在候选之间中断并释放未物化批次，但无法取消已经进入 PNG 编码或文件系统提交的单次写入。
- 没有人工 ROI 或语义模型时，CV 无法保证自动候选就是期望的那个图标；游戏中若有常驻准星、固定面板或水印，应在真实测试结果上再增加位置约束或人工选择。
- 即使收窄到默认 `4%` 灰区，“相同 HUD 文字 + 真实图标/高亮变化”仍可能被 OCR 误判为别名，因此开关默认关闭并标记为实验；本轮目标是采集命中/回退数据，不把它当成最终无误去重规则。
- 该 GUI 还没有输入记录、动作执行、状态规则或回放；它只完成“连续观察到可审计关键帧”的第一个闭环。
