# Raw Mouse Visualizer（原始鼠标可视化实验）

## 当前状态

第一版实验实现，归属 `experiments`。它用于并排观察 Windows 上不同鼠标输入
路径，并试验采集入口降采样与冻结轨迹简化；不负责判断已经确认的游戏状态，
也不修改 Trace Core 公共契约。

当前上位方向见[鼠标场景模式辅助判定与RAW操作轨迹分层记录构想](../../docs/concepts/interface_discovery/鼠标场景模式辅助判定与RAW操作轨迹分层记录构想.md)。


离屏构造检查：

## 实验目标

当前输入录制实验刻意不记录鼠标移动；指针上下文实验也不注册 Raw Input。
本实验补充一个完全独立、只读、可视化的观测面，回答以下问题：

- 系统绝对光标是否移动；
- `WH_MOUSE_LL` 低级 Hook 是否收到事件；
- Hook 是否带 `LLMHF_INJECTED` 注入标记；
- `WM_INPUT` 是否收到 Raw Input 相对移动、按钮和设备句柄；
- 左、右、中键和 X1/X2 侧键分别在哪条通道出现；
- 本地鼠标、普通远控模式和远控游戏模式的观测签名有何区别。

观测到事件只表示该条 Windows 路径出现了信号，不表示游戏已经消费输入，也不
表示镜头、人物或 UI 已经产生视觉响应。

## 第一版边界

- 被动观测，不调用 `SendInput`，不移动或点击系统鼠标；
- 默认不写 JSON、日志、截图或其他结果文件；
- 所有事件、轨迹和定位环都保存在有界内存中；
- “临时保存预览”只是冻结当前进程中的一段内存数据，不提供文件路径；
- 按所选诊断模式启用的 Raw Input 和/或低级 Hook 位于私有辅助进程；
- GUI 关闭或点击停止时结束辅助进程并释放注册；
- 不读取游戏进程内存，不注入目标进程；
- 不自动把观测编译为输入方案；
- 不根据绝对光标差值伪造 3D 相对移动；
- 暂不通过截图验证游戏画面是否响应。

开始观测后会监听当前 Windows 会话中的全局鼠标事件。测试完成应及时点击
“停止”或关闭窗口。

## 三种采集诊断模式

GUI 顶部的“诊断模式”只控制私有采集进程中的 RAW 与 Hook 通道。`CURSOR`
系统光标轮询不属于这两个通道，三种模式下都会继续运行：

- `RAW_ONLY`：只注册 Raw Input，不安装 `WH_MOUSE_LL`。这是排查低级 Hook
  是否造成系统指针卡顿时应优先使用的模式；
- `HOOK_ONLY`：只安装 `WH_MOUSE_LL`，不注册 Raw Input。全局 RAW 采样和
  临时 RAW 轨迹预览在本轮不参与；
- `RAW_AND_HOOK`：同时注册两条通道，用于跨通道对照，也是兼容原有行为的
  默认模式。

模式在点击“开始观测”时冻结，停止后才能切换。请求的通道必须全部注册成功，
否则本轮报告 `FAILED`，不会静默降级成另一种模式。图层复选框只控制画布是否
显示相应轨迹；关闭图层不会停止采集，也不会降低该通道的采集开销。

这三个模式的用途是形成 A/B 对照：如果只有包含 Hook 的模式出现明显指针卡顿，
低级 Hook 回调路径就是高优先级嫌疑；如果 `RAW_ONLY` 也同样卡顿，则应继续区分
原生采集、GUI 刷新、队列拥塞和游戏自身的指针锁定行为。它们不是游戏场景分类
结果。

## 三条可视化路径

### CURSOR（系统光标轮询）

通过 `GetCursorPos` 获取物理屏幕坐标。青色实线表示真实系统光标位置变化，适合
观察桌面、QQ、浏览器和游戏菜单等定位式 UI。

轮询同时显示：

- 光标是否可见；
- `GetClipCursor` 返回的裁剪区域；
- 当前前台窗口句柄；
- 虚拟桌面边界。

### HOOK（低级鼠标 Hook）

通过 `WH_MOUSE_LL` 观察传统低级鼠标事件。黄色实线表示 Hook 携带的绝对屏幕
位置。诊断栏会在最新 Hook 事件带 `LLMHF_INJECTED` 时显示 `INJECTED`。

`INJECTED=true` 是一条注入证据；`INJECTED=false` 不能反向证明事件一定来自
物理鼠标，因为驱动或虚拟 HID 可能表现为普通设备事件。

### RAW（原始输入）

辅助进程注册鼠标 Raw Input，并读取 `RAWMOUSE.lLastX/lLastY`、按钮标志和
`RAWINPUTHEADER.hDevice`。

绿色虚线不是屏幕坐标。GUI 把最新累计相对位置固定在画布中心，只绘制最近轨迹
相对当前点的变化，以便观察锁定式 3D 指针持续产生的 `dx/dy`。Raw 显示增益只
影响绘图，不修改原始数据。

第一版保留 Raw absolute 标志和值，但不把 0～65535 的绝对 Raw 值擅自映射为
桌面坐标。

## 全局 RAW 采样

GUI 顶部的“全局 RAW 采样”直接作用于私有采集进程中的 Raw Input 移动入口，
发生在进程间队列之前，只对 `RAW_ONLY` 和 `RAW_AND_HOOK` 生效。它有三种选择：

- `完整获取`：每个 RAW 移动样本各自产生一个移动观测；
- `间隔1次`：每 2 个连续兼容移动合成一个观测；
- `间隔N次`：每 `N+1` 个连续兼容移动合成一个观测。

这里的“间隔”不是直接删除位移。相对移动会累加组内全部 `dx/dy`，因此在没有
真正采集丢失的前提下，最终累计位移不变；绝对 RAW 移动保留组内最后位置。
设备或移动模式变化、按钮/滚轮到来以及采集停止时，未满的一组会先被冲刷。
按钮和滚轮本身不参与采样合并，仍逐事件发送。

采样策略在点击“开始观测”时冻结。观测期间控件被禁用；要切换策略，必须停止
后重新开始。这避免同一统计会话中途改变采样语义。

诊断栏把以下两类现象分开显示：

- `主动合并`：按用户选择有意合并掉的移动观测数量；
- `采集端丢弃`：进程间队列满等原因导致的真实丢弃数量。

前者不代表位移丢失；后者才表示当前数据可能不完整。极端队列拥塞时按钮或滚轮
仍可能与任何队列消息一样被队列丢弃，“不参与降采样”不等于“永不受队列溢出
影响”。

## 临时保存预览

“临时保存预览（内存）”标签页用于短时冻结一段 RAW 轨迹，方便检查哪几个点值得
保留。操作顺序为：

1. 开始总观测；
2. 切换到临时预览标签页，点击“开始临时记录”；
3. 完成鼠标动作后点击“停止并生成预览”；
4. 调整阈值并点击“按当前参数重建”；
5. 点击“清空预览”释放该段数据。

临时记录最多 60 秒、最多 50,000 个源 RAW 样本。达到上限会自动停止并生成现有
内存数据的预览。开始新记录会替换上一段临时数据；GUI 关闭后数据自然消失。

简化器使用 NumPy（数值数组计算库）在停止后的冻结批次上计算累计路径，不在
Win32 回调中逐点做数组运算。采集进程只做小组累加。第一版保留以下边界：

- 起点和终点；
- 明显方向变化与回头；
- 停顿后的第一个移动；
- 明显速度变化；
- 最大分段时长；
- 按钮/滚轮和设备变化边界。

“方向分数”使用叉积和点积形成的整数阈值，不宣称是精确角度。灰线是采样输出的
原路径，绿线和圆点是简化后的关键点与分段。简化前后总 `dx/dy` 和最终点必须
一致；它只减少预览与后续分析点数，不改变输入含义。

## 画布与颜色

画布始终保持 Windows 虚拟桌面的宽高比，并使用留黑边方式适应可拖动窗口。
多显示器负坐标会按完整虚拟桌面统一映射。

按钮默认颜色：

- 左键：青色；
- 右键：橙红色；
- 中键：黄色；
- X1：绿色；
- X2：紫色。

按下产生扩散定位环，持续按住显示脉冲环，释放产生收缩环。Hook 点击使用实际
屏幕位置；Raw 点击没有可靠屏幕位置，因此使用相对诊断锚点并以虚线显示。

## 建议对照顺序

第一轮不要寻找唯一“正常路径”，而应形成场景基线：

1. 本地物理鼠标操作普通桌面；
2. 本地物理鼠标操作 QQ 或浏览器；
3. 本地物理鼠标操作原神或无限暖暖的 3D 镜头；
4. ToDesk 普通应用/指针模式；
5. ToDesk 游戏模式；
6. 向日葵普通指针模式；
7. 向日葵“游戏鼠标”模式。

每次分别记录人工观察：

- RAW、HOOK、CURSOR 哪些指示灯闪烁；
- `dx/dy` 是否连续；
- 系统光标是否移动、隐藏或被限制；
- Hook 是否显示 `INJECTED`；
- Raw 设备句柄是否稳定；
- 游戏镜头是否由人眼确认发生响应。

远控在被控机上没有 Raw 设备事件并不等于失败。远控软件可能发送传统注入事件，
也可能通过驱动或虚拟 HID 重建设备输入；本实验只能显示被控机可观测到的签名，
不能仅凭一条信号确认 ToDesk 或向日葵的内部实现。

## 模块

- `contracts.py`：不可变观测、桌面几何和来源状态契约；
- `capture_mode.py`：三种原生采集通道组合及其严格请求语义；
- `raw_sampling.py`：采集入口的全局移动分组与未满组冲刷；
- `win32_source.py`：系统光标探测与私有 Win32 采集进程；
- `session.py`：有界内存轨迹、按钮状态、定位环和频率统计；
- `canvas.py`：虚拟桌面比例变换与分层绘制；
- `trajectory_preview.py`：内存临时记录与 NumPy 冻结轨迹简化；
- `preview_panel.py`：临时预览参数、画面与分段表格；
- `app.py`：GUI 组装、生命周期和诊断显示；
- `__main__.py`：命令行入口；
- `tests/`：契约、会话、坐标变换和离屏 GUI 测试。

## 自动化验收

```powershell
..\.venv\Scripts\python.exe -m unittest discover `
  -s experiments\raw_mouse_visualizer\tests -t . -v
```

自动化测试验证数据边界、轨迹隔离、窗口缩放映射、按钮状态、有界内存、三种
模式的通道请求契约与 GUI 冻结、监听器生命周期、完整/间隔采样、停止时未满组
冲刷、总位移守恒、关键转折保留以及预览无文件写入。真实 Raw Input、低级
Hook、远控软件和游戏视觉响应仍需在目标 Windows 会话中进行人工验收。

第一版人工验收重点：

1. 用同一段鼠标动作依次运行 `RAW_ONLY`、`HOOK_ONLY` 和
   `RAW_AND_HOOK`，确认只启用请求的私有通道；
2. 记录三轮中系统指针是否出现卡顿；不要仅凭 GUI 轨迹刷新判断物理指针卡顿；
3. 用同一段近似直线动作分别测试完整获取、间隔1次和间隔N次；
4. 对比“源RAW移动 / 采样输出 / 主动合并 / 采集端丢弃”；
5. 确认间隔1次的输出点约为完整获取的一半，间隔N次按 `N+1` 分组；
6. 在不足一整组时直接停止，确认最后一小段仍进入累计位移和临时预览；
7. 混合左/右键、滚轮、转弯、回头、停顿与速度变化，确认预览产生对应边界；
8. 确认整个过程中项目目录没有新增轨迹、JSON、截图或模型产物。

## 后续候选

第一版取得对照数据后，再决定是否增加：

- 同步帧差或光流运动量，用于区分“收到输入”与“镜头产生响应”；
- Raw Input 批量缓冲读取和更完整的高回报率统计；
- 每个设备独立的路径和按钮状态；
- 显式导出开关；
- 将已人工确认的鼠标语义绑定回录制事件。

上述候选均不在本轮第一版契约中。
